🔑 3 จุดเด่นหลัก ที่ต้องจำ

  1. Emotional Interaction — หุ่นยนต์ตรวจจับอารมณ์จากใบหน้าผู้ใช้ (ESP-DL) แล้วแสดงอารมณ์ตอบกลับ 9 แบบ ผ่านหน้าจอ TFT + ท่าทาง servo → สร้างแรงจูงใจในการเรียน
  2. AI Tutor (Scaffolding) — ระบบผู้ช่วยสอนผ่าน Gemini 2.5 Pro ใช้ Socratic Method ให้คำใบ้ไม่ให้คำตอบ → ส่งเสริมการคิดแก้ปัญหาด้วยตัวเอง
  3. Modular DIY + Block Coding — หุ่นยนต์ประกอบแบบปิ่นโต 5 ชั้น ถอดเพิ่มลดชั้นได้ + เขียนโค้ดบล็อกผ่านเว็บสั่งควบคุมได้ → เข้าใจทั้ง hardware + software

  • ขาดแคลน 70,000 คน/ปี — ผลิตได้ 30,000 vs ต้องการ 100,000 (depa, 2024)
  • ตลาดหุ่นยนต์การศึกษา: $1.86B (2024) → $18B (2034), CAGR 27.5%

🦾 ระบบแขนแบบมนุษย์ — Humanoid Arm Mechanism

ใช้แขน 2 ข้างหนีบจากด้านข้างตัวเข้าหากัน (เหมือนคนอุ้มของ) แทนที่จะใช้ก้ามปูหนีบจากด้านหน้าแบบหุ่นยนต์ทั่วไป

  • MG996R ×2 — ยกแขนขึ้น-ลง (shoulder pivot)
  • MG90S ×2 — หนีบ-คลายมือ (gripper)
  • S-Curve Path — แขนโค้งหลบหัวและตัวถังไม่ให้ชน
  • Smart Grip — หนีบทีละ 3% พร้อมตรวจจับ stall (ถอยกลับ 3° ถ้าติด)
✨ จุดเด่นสำหรับ IP: ในหุ่นยนต์การศึกษาไม่มีตัวไหนใช้กลไกแขนแบบมนุษย์ 2 ข้างที่หนีบเข้าหากัน — ปกติใช้ก้ามปู (gripper) หรือ claw จากด้านหน้าเท่านั้น

Auto-Analysis

เมื่อผู้ใช้เปลี่ยนบล็อก AI จะวิเคราะห์โค้ดอัตโนมัติ (debounce 5 วินาที) โดยแปลง block tree เป็นข้อความอ่านง่าย แล้วส่งให้ Gemini วิเคราะห์

🤖 โค้ดหุ่นยนต์ — Arduino ESP32 (Robo.ino ~1,113 บรรทัด)

  • WiFi STA Mode — เชื่อมต่อ router, รัน HTTP Server port 80, mDNS: MDTrobot.local
  • Endpoint: GET /run?cmd=... รับ command string → parse → execute ทีละคำสั่ง
  • Emotion State Machine — 9 อารมณ์, hold time 2000ms ป้องกัน jitter, auto-revert 2500ms
  • Servo Lerp — หมุนหัวแบบ smooth ด้วย linear interpolation (speed=0.18), auto-detach 2s ประหยัดไฟ
  • Body-Face Coordination — แต่ละอารมณ์ trigger ท่าทาง servo + ตาพร้อมกัน
  • Smart Gripper — หนีบทีละ 3% + stall detection + VL53L0X verify

📷 ระบบกล้อง — ESP-DL Face Detection + Emotion

XIAO ESP32S3 Sense + OV2640 ประมวลผลบนชิป (Edge AI) ไม่ต้องส่งขึ้น cloud

Pipeline 8 ขั้นตอน

  1. Capture 240×240 RGB565 จาก OV2640
  2. Face Detection — MSR01 (bounding box ~10ms)
  3. Landmark Detection — MNP01 (5 keypoints ~50-60ms)
  4. EMA Smoothing (α=0.5)
  5. Adaptive Baseline Calibration (rate=0.003)
  6. Ratio Calculation (m=mouth/eye, n=nose-mouth/eye)
  7. Hysteresis Filter (2 consecutive frames + 500ms hold)
  8. Emotion Classification → ส่ง Serial ไป ESP32 Main
📊 ประสิทธิภาพ: FPS ~16 (จาก ~3-5 เดิม), Latency ~0.6s (จาก ~6-7s เดิม), Heap stable ไม่ crash
⚠️ จำไว้: กล้องตรวจจับได้เพียง 3 อารมณ์ (Normal, Happy, Sad) เพราะ 5 keypoints ไม่มีคิ้ว → อีก 6 อารมณ์ (Angry, Shocked, Sleepy, Confused, Love, Shy) สั่งผ่าน Blockly เท่านั้น

🔬 Emotion Detection Pipeline (คิดเอง)

ออกแบบ pipeline 8 ขั้นตอนที่ทำงานบน ESP32 (Edge AI) ให้ลื่นไหลและเป็นธรรมชาติ:

ปัญหาที่เจอ → วิธีแก้ที่คิด

ปัญหาวิธีแก้ที่คิดค่าที่ตั้ง
Keypoints กระเด้งไปมาเพราะ noiseEMA Smoothing — ถ่วงน้ำหนักเฉลี่ยเคลื่อนที่α = 0.5
แต่ละคนหน้าไม่เหมือนกัน baseline ต่างกันAdaptive Baseline — ปรับ baseline ช้าๆ ตามใบหน้าจริงrate = 0.003
อารมณ์เปลี่ยนกระตุก สลับไปมาเร็วHysteresis Filter — ต้องตรวจเจอ 2 เฟรมต่อเนื่อง + hold 500ms ก่อนเปลี่ยน2 frames + 500ms + 2000ms
กล้อง 5 keypoints ไม่มีคิ้ว จับ Angry ไม่ได้Ratio Calculation — คำนวณสัดส่วน mouth/eye, nose-mouth/eye แทนm, n, d ratios
เฟรมเรตต่ำ ส่งบ่อยเกินจับ 10 เฟรม ส่งทีละครั้ง + ส่งเมื่อ 2 เฟรมตรงกัน—
💡 สูตรที่ใช้:
EMA: smoothed = α × new + (1-α) × prev
Baseline: baseline = baseline + rate × (current - baseline)
Smile: m = mouth_width / eye_distance
Sad: n = nose_mouth_dist / eye_distance

🤖 Body-Face Coordination (คิดเอง)

ออกแบบให้ทุกอารมณ์ trigger ทั้ง ตา TFT + แขน + มือ + หัว พร้อมกัน แบบสมจริง:

  • Happy → ตาโค้งยิ้ม + โบกมือ + เอียงหัว
  • Sad → ตาน้ำตา + กอดตัวเอง + หัวก้ม
  • Love → หัวใจเต้น + แขนกาง + เอียงหัว (heartbeat animation)
  • Shy → ตาเบือน + แก้มแดง + หัวหันหนี + แขนหุบ

ไม่ใช่แค่เปลี่ยนตา — ร่างกายทั้งตัวแสดงอารมณ์เหมือนมีชีวิต

🎭 Idle Behaviors System (คิดเอง)

ออกแบบพฤติกรรม "เวลาว่าง" ให้หุ่นดูมีชีวิต แม้ไม่มีใครสั่ง:

พฤติกรรมความถี่รายละเอียด
Blink กระพริบตา1.5-3.5 วินาที1-3 ครั้ง (สุ่ม), non-blocking state machine
Glance ชำเลืองมอง4-10 วินาทีม่านตาเลื่อนซ้าย/ขวาแล้วกลับ
Sigh ถอนหายใจ15-30 วินาทีตาครึ่งปิดแล้วเปิด
Head Look หัวหัน4-12 วินาทีServo lerp หันหัวเล็กน้อย
Heartbeat หัวใจเต้นใน Love modelub-dub rhythm animation

ทั้งหมดเป็น non-blocking state machine — ทำงานพร้อมกันโดยไม่ block loop หลัก

🦾 Smart Gripper Algorithm (คิดเอง)

  • smartGrip() — หนีบทีละ 3% ค่อยๆ เพิ่ม 0→100% พร้อม stall detection (ถ้าติดถอย 3°)
  • gripAndVerify() — ลดแขน → smart grip → ยกขึ้น → ตรวจสอบด้วย VL53L0X
  • gripSync() — 2 มือหนีบพร้อมกัน synchronized

🔗 ระบบเชื่อมต่อ Web-Robot (คิดเอง)

  • ออกแบบ Command Protocol ตัวอักษรเดียว + semicolon — เรียบง่ายแต่ครอบคลุมทุกฟังก์ชัน
  • ออกแบบ Logic Unrolling — loop/if ประมวลผลฝั่งเว็บแล้วส่ง flat command string ไปหุ่น
  • ออกแบบ describeWorkspace() — แปลง block tree เป็นข้อความที่ AI อ่านเข้าใจ
  • ออกแบบ Servo Lerp — linear interpolation speed=0.18 ให้หัวหมุน smooth

🏗️ การออกแบบฮาร์ดแวร์ (คิด + ทำเอง 100%)

  • โครงสร้างปิ่นโต 5 ชั้น — ออกแบบใน 3D software แล้ว print
  • S-Curve Arm Path — แขนโค้งหลบหัว/ตัว ไม่ชน (มี arm simulator ทดสอบ)
  • กลไกแขนแบบมนุษย์ — หนีบจากข้าง ไม่ใช่ก้ามปู
  • ล้อตีนตะขาบ — ออกแบบ tank track สำหรับหุ่นเล็ก
  • JST-XH 9 สี — ระบบสายไฟ color-coded ประกอบง่าย
  • จัดวางอุปกรณ์ — low center of gravity (แบตชั้นล่าง), I2C daisy-chain ประหยัด GPIO

Q&A

❓ Q1: ระบบทำงานอย่างไร Step-by-step?

✅ คำตอบ: เปิดเว็บ → ลากบล็อกคำสั่ง (เช่น forward, หน้ายิ้ม, ยกแขน) → กด Run → เว็บแปลงเป็น string คำสั่ง (เช่น "w;h;r;") → ส่ง HTTP GET ผ่าน WiFi ไปยังหุ่น → ESP32 parse แล้วทำทีละคำสั่ง (ขับมอเตอร์, หมุน servo, วาดตา TFT)

เสริม: ระหว่างใช้งาน กล้องบนหัวหุ่น (XIAO ESP32S3) จะตรวจจับใบหน้าผู้ใช้แล้วจำแนกอารมณ์ ส่ง Serial ไปยัง ESP32 หลัก → หุ่นแสดงอารมณ์ตอบกลับทันที

แนะนำ: เปิดหน้าเว็บ share screen ให้ดู + จำลองการลากบล็อกสดๆ

❓ Q2: งานนี้ต่างจากที่มีในตลาดอย่างไร (Research Gap)?

✅ คำตอบ: หุ่นยนต์การศึกษาในตลาด (LEGO, mBot, Edison) เป็นแค่ "เครื่องรับคำสั่ง" — ไม่มีอารมณ์ ไม่มี AI สอน ไม่มีชีวิต นักเรียนแค่สั่ง แต่ไม่มีแรงจูงใจเรียนต่อ

METO ต่างตรงที่:

  1. มี ปฏิสัมพันธ์ทางอารมณ์ — ตรวจจับอารมณ์คน + แสดงอารมณ์ตอบ 9 แบบ (งานวิจัย Belpaeme et al. ยืนยัน เพิ่มแรงจูงใจ d=0.69-0.70)
  2. มี AI Tutor แบบ Scaffolding — ให้คำใบ้ไม่ให้คำตอบ
  3. ประกอบแบบปิ่นโต — ถอดเพิ่มลดชั้นได้ นักเรียนเข้าใจ engineering
  4. ราคาต่ำกว่า 3,000 บาท (ถูกกว่า LEGO 5 เท่า)

❓ Q3: มีการใช้ Open Source หรือ API ของคนอื่นไหม?

✅ คำตอบ: ใช้ครับ — Google Blockly (UI บล็อก), ESP-DL (ตรวจจับใบหน้า), Gemini API (AI สอน), TFT_eSPI (ขับจอ) — ทั้งหมดเป็น open source / API ที่ใช้ได้เสรี

แต่ส่วนที่เป็นของเรา:

  • ฮาร์ดแวร์ทั้งหมด — ออกแบบ 3D + print + ประกอบเอง 100%
  • ตรรกะการทำงาน — Emotion Pipeline, Body-Face Coordination, Idle Behaviors, Smart Gripper
  • สถาปัตยกรรมการเชื่อมต่อ — Web ↔ Robot ↔ Camera ↔ AI ทั้งระบบ
  • โค้ดส่วนใหญ่ใช้ AI ช่วยเขียน (Vibe Coding) — แต่ตรรกะและการออกแบบเป็นของเรา

❓ Q4: ส่วนไหนคือหัวใจหลักของงาน?

✅ คำตอบ: หัวใจคือ "ทั้งระบบ" ที่ผสมผสานกัน — ไม่มีตัวไหนในตลาดที่รวม DIY + Block Coding + Emotion AI + AI Tutor ในตัวเดียว ราคาถูก

แต่ถ้าต้องเลือก เน้นที่:

  1. ฮาร์ดแวร์ — โครงสร้างปิ่นโต + แขนแบบมนุษย์ (จดอนุสิทธิบัตร + สิทธิบัตรออกแบบ)
  2. Emotion Pipeline — EMA + Hysteresis + Adaptive Baseline บน Edge AI (จดอนุสิทธิบัตร)

❓ Q5: สถานะโปรเจกต์ตอนนี้เป็นยังไง?

✅ คำตอบ: เว็บเสร็จแล้ว ต้นแบบที่ 1 เสร็จ กำลังทำต้นแบบที่ 2 จะนำไปทดสอบจริงช่วงเดือน 9-10

สำคัญ: ยังไม่มีการเผยแพร่สาธารณะ → สถานะ "ความใหม่" ยังอยู่ → ต้องยื่นจด IP ก่อนเอาไปทดสอบ

❓ Q6: (ถ้าถาม) โค้ดใครเขียน?

⚠️ ตอบตามจริง: โค้ดส่วนใหญ่ใช้ AI (Gemini/Claude) เป็นผู้ช่วยเขียน — เราเป็นคนคิดลอจิก ออกแบบวิธีแก้ปัญหา ตรวจสอบ และควบคุมทั้งหมด

เปรียบเทียบ: เหมือนสถาปนิกใช้ CAD วาดแบบ — ผลงานการออกแบบยังเป็นของสถาปนิก ไม่ใช่ของโปรแกรม CAD

จุดแข็ง: ฮาร์ดแวร์ 100% ทำเอง → จดสิทธิบัตรได้เต็มที่ ไม่เกี่ยวกับ AI เขียนโค้ด
