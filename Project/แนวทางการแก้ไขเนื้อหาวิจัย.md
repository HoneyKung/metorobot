# การปรับปรุงเนื้อหาในรายงาน บทที่ 1-2 และบทที่ 3 สิ่งที่จะทำ

## บทที่ 1 บทนำ Introduction

### ที่มาและความสำคัญ Pain Point และ Significance

- [ ] ต้องเพิ่มข้อมูลเชิงสถิติ Data Driven Rationale ตัดการพรรณนาแบบนามธรรมออก แทนที่ด้วยข้อมูลจริงเพื่อตอบคำถามว่าทำไมต้องทำงานวิจัยชิ้นนี้

**สิ่งที่ต้องเพิ่ม**

- [ ] กราฟ แผนภูมิ หรือตัวเลขที่แสดงถึงขนาดของปัญหา โดยข้อมูลต้องทันสมัยในช่วงปี 2024 ถึง 2026
- [ ] ช่องว่างงานวิจัย Research Gap
  - [ ] ระบุให้ชัดเจนว่าวิธีเดิมมีปัญหาอะไร และงานของเราจะเข้ามาแก้ปัญหาในจุดไหน

### วัตถุประสงค์และขอบเขตงาน

- [ ] ระบุสิ่งที่ตั้งใจจะทำให้ชัดเจน รวมถึงขอบเขตว่า "จะทำอะไร" และ "จะไม่ทำอะไร"

## บทที่ 2 ทฤษฎีและงานวิจัยที่เกี่ยวข้อง Literature Review รวมถึงสิ่งที่มีมาก่อน

### การวิเคราะห์ด้วยภาพ Visual Literature Review

- [ ] เนื้อหาต้องแสดงถึงความเข้าใจเชิงเทคนิค Technical Depth มากกว่าคำนิยามทั่วไป

### ส่วนทฤษฎี AI และ Model

- [ ] ต้องมีภาพ Diagram แสดง Architecture ของ Model ที่เลือกใช้ เช่น โครงสร้างเลเยอร์ของ CNN หรือ Transformer พร้อมคำอธิบายใต้ภาพที่ละเอียด

### ส่วนงานวิจัยที่เกี่ยวข้อง

- [ ] ทำตารางสรุปงานวิจัย Comparison Table เปรียบเทียบ Paper ระดับ Q1 อย่างน้อย 5 เรื่อง ระบุ Input, Method, Result และ Limitation

### หลักฐานเชิงประจักษ์

- [ ] แคปเจอร์ภาพผลลัพธ์หรือตารางผลการทดลองจาก Paper ที่ศึกษามาวางประกอบ เพื่อวิเคราะห์จุดเด่นและ Gap อย่างเป็นรูปธรรม

### วิวัฒนาการและสิ่งที่มีมาก่อน (Prior Arts & Evolution)

- [ ] อธิบายบริบททางประวัติศาสตร์ สรุปสั้นๆ ว่าก่อนหน้าที่จะใช้เทคโนโลยีหรือโมเดล AI ในปัจจุบัน วงการนี้เคยใช้วิธีการใดแก้ปัญหามาก่อน (Legacy Systems / Traditional Methods) ภาพประกอบเชิงเปรียบเทียบ (Visual Evidence) ต้องแคปเจอร์ภาพหน้าจอ ภาพผลลัพธ์ หรือการทำงานของเครื่องมือ/ระบบ "รุ่นเก่า" มาวางประกอบ พร้อมเขียนคำอธิบายใต้ภาพที่ระบุจุดอ่อนหรือข้อจำกัดอย่างเป็นรูปธรรม พร้อมแหล่งอ้างอิงโดยใช้ endnote เพื่อชี้ให้เห็นว่าทำไมเทคโนโลยีในงานวิจัย Q1 ปัจจุบันจึงต้องเข้ามาแทนที่

## บทที่ 3 วิธีการดำเนินการวิจัย (Methodology)

### ภาพรวมกระบวนการวิจัย (System Pipeline & Workflow)

- [ ] ต้องมีแผนภาพ (Diagram) สร้าง Flowchart หรือ Pipeline Diagram ที่แสดงขั้นตอนทั้งหมดตั้งแต่ต้นน้ำยันปลายน้ำ (Data Input -> Preprocessing -> Model Processing -> Output)
- [ ] คำอธิบายประกอบ อธิบายการเชื่อมโยงข้อมูลระหว่างโมดูลต่างๆ ในภาพให้ชัดเจน

### การจัดการชุดข้อมูล (Dataset & Data Preprocessing)

- [ ] แหล่งที่มาของข้อมูล ระบุให้ชัดเจนว่าใช้ Public Dataset (เช่น จากแพลตฟอร์ม Kaggle, Hugging Face ในช่วงปี 2024-2026) หรือ Custom Dataset ที่เก็บรวบรวมเอง
- [ ] คุณลักษณะข้อมูล ระบุจำนวน (เช่น จำนวนภาพ, ชั่วโมงวิดีโอ, ปริมาณ Text), ประเภทของไฟล์ และความสมดุลของข้อมูล (Data Distribution)
- [ ] การเตรียมข้อมูล (Preprocessing) อธิบายกระบวนการทำ Data Cleaning, Data Augmentation (เช่น การหมุนภาพ, การปรับแสง) หรือการทำ Labeling
- [ ] หลักฐานเชิงประจักษ์ ต้องแทรก ภาพตัวอย่างชุดข้อมูล (Sample Data Images) ทั้งภาพต้นฉบับและภาพที่ผ่านการ Preprocessing แล้ว เพื่อให้เห็นความแตกต่างที่ชัดเจน

### การออกแบบและการตั้งค่าโมเดล (Model Setup & Configuration)

- [ ] เทคนิคและเครื่องมือ อธิบายเครื่องมือที่ใช้ (เช่น PyTorch, TensorFlow) และระบุ Hyperparameters ที่สำคัญต่อการฝึกสอนโมเดล (เช่น Learning Rate, Batch Size, จำนวน Epochs)
- [ ] สภาพแวดล้อมการทำงาน (Environment) ระบุสเปค Hardware ที่ใช้รันงาน (เช่น การ์ดจอที่ใช้ หรือ Cloud Service เช่น Google Colab, AWS)

### การประเมินประสิทธิภาพ (Evaluation Metrics)

- [ ] ระบุตัวชี้วัด (Metrics) ที่จะใช้ทดสอบโมเดลอย่างเจาะจง พร้อมเหตุผลประกอบ เช่น ใช้ Precision/Recall/F1-Score สำหรับงาน Classification หรือใช้ FID/PSNR สำหรับงานจำลองภาพ (Generative AI)

## การปรับปรุงไฟล์นำเสนอ Visual Slide

เพื่อนำเสนอเนื้อหาทั้งบทที่ 1, 2 และ 3 อย่างครบถ้วนด้วยหลักการ Visual Storytelling ให้อยู่ในข้อกำหนด 5 ถึง 7 หน้า ให้คุณปรับโครงสร้างสไลด์เป็น 6 หน้า ดังนี้ครับ (แทนที่โครงสร้าง 5 หน้าเดิม)

- [ ] หน้า 1 หน้าปก (Title & Team): ชื่อโปรเจกต์และสมาชิก
- [ ] หน้า 2 The Problem (Data-Driven Problem): โชว์กราฟสถิติความรุนแรงของปัญหา (จากบทที่ 1)
- [ ] หน้า 3 Evolution & Existing Solutions: โชว์ภาพ "สิ่งที่มีมาก่อน" (วิวัฒนาการ/ระบบเก่า) คู่กับ "งานวิจัยเดิมในปัจจุบัน" และชี้จุดที่เป็นข้อจำกัด (Research Gap) ด้วย Keyword สั้นๆ (ปรับปรุงจากบทที่ 2)
- [ ] หน้า 4 Dataset & Preprocessing: โชว์ภาพตัวอย่างชุดข้อมูล (Dataset) ทั้งต้นฉบับและภาพที่ผ่านการเตรียมข้อมูลแล้ว พร้อมระบุแหล่งที่มาและปริมาณข้อมูล (ดึงเนื้อหาจากบทที่ 3)
- [ ] หน้า 5 Our Approach (System Architecture): แผนภาพรวมระบบจาก Input → โมเดลที่ใช้ → Output (ดึงเนื้อหาจากบทที่ 3)
- [ ] หน้า 6 Expected Outcome & Metrics: ภาพจำลองผลลัพธ์ที่คาดว่าจะได้รับ พร้อมระบุ Keyword ของ "ตัวชี้วัด (Evaluation Metrics)" ที่จะใช้ประเมินความสำเร็จของงาน (รวมเนื้อหาบทที่ 1 และ 3)

> [!NOTE]
> หากหน้า 6 อัดแน่นเกินไป คุณสามารถแยกตัวชี้วัด Metrics ออกไปเป็นหน้า 7 ได้ เพื่อให้หน้าสไลด์ดูคลีนและเน้นภาพเป็นหลักครับ

### โครงสร้างการเล่าเรื่องที่แนะนำ

- [ ] หน้า 1 หน้าปก
- [ ] หน้า 2 The Problem โชว์กราฟสถิติความรุนแรงของปัญหา
- [ ] หน้า 3 Existing Solutions & Prior Arts (ปรับแก้เนื้อหา) โชว์ภาพ "สิ่งที่มีมาก่อน/ระบบเก่า" เทียบกับ "งานวิจัยเดิม" และชี้จุดที่เป็นข้อจำกัด (Research Gap) ด้วย Keyword
- [ ] หน้า 4 Dataset & Preprocessing นี่คือหน้าที่ต้องแทรกเข้ามา โชว์ภาพตัวอย่างชุดข้อมูล (Dataset) ทั้งภาพต้นฉบับและภาพที่ผ่านการคลีนหรือเตรียมข้อมูลแล้ว พร้อมระบุแหล่งที่มาและปริมาณข้อมูลสั้นๆ
- [ ] หน้า 5 Our Approach แผนภาพรวมระบบ System Architecture จาก Input ไปยัง Output
- [ ] หน้า 6 Expected Outcome & Metrics (เลื่อนมาจากหน้า 5 เดิม) ภาพจำลองผลลัพธ์ที่คาดว่าจะได้รับ และให้เพิ่ม Keyword ของ "ตัวชี้วัด (Evaluation Metrics)" ที่จะใช้ประเมินความสำเร็จของโมเดลเข้าไปด้วย
