2.1.1 ESP-DL: โมเดลตรวจจับใบหน้าบน Edge
------------------------------------------------------------

ESP-DL คืออะไร?
    ESP-DL คือไลบรารี (ชุดโปรแกรม) Deep Learning ที่บริษัท Espressif 
    (ผู้ผลิตชิป ESP32) พัฒนาขึ้น เพื่อให้สามารถรันโมเดล AI 
    บนชิปไมโครคอนโทรลเลอร์ขนาดเล็กได้โดยตรง 
    ไม่ต้องส่งข้อมูลไปประมวลผลบน Cloud

ทำไมถึงสำคัญ?
    ปกติการตรวจจับใบหน้าต้องใช้คอมพิวเตอร์สเปกสูง 
    แต่ ESP-DL ทำให้ชิปเล็กๆ ราคาไม่กี่ร้อยบาท 
    สามารถหาหน้าคนในภาพได้เลย → ลด Latency (ไม่ต้องรอส่ง-รับจาก Cloud)
    และรักษาความเป็นส่วนตัว (ภาพไม่ออกจากตัวเครื่อง)

ในโปรเจกต์เราใช้ 2 โมเดลจาก ESP-DL:

    โมเดลที่ 1: MSR01 (Human Face Detect MSR01)
        หน้าที่: สแกนภาพทั้งเฟรม แล้วตอบว่า "มีหน้าคนในภาพไหม? ถ้ามี อยู่ตรงไหน?"
        Input: ภาพ RGB565 ขนาด 240x240 พิกเซล จากกล้อง OV2640
        Output: กรอบสี่เหลี่ยม (Bounding Box) ล้อมรอบใบหน้าที่พบ

    โมเดลที่ 2: MNP01 (Human Face Detect MNP01)
        หน้าที่: เมื่อรู้แล้วว่าหน้าอยู่ตรงไหน → ซูมเข้าไปหา 5 จุดสำคัญบนใบหน้า
        Input: ภาพ + ตำแหน่ง Bounding Box จาก MSR01
        Output: พิกัด 5 Keypoints คือ ตาซ้าย, ตาขวา, จมูก, มุมปากซ้าย, มุมปากขวา

    ทั้ง 2 โมเดลทำงานต่อเนื่องกัน เรียกว่า Two-Stage Pipeline:
        Stage 1 (MSR01): สแกนภาพ → หาหน้า
        Stage 2 (MNP01): ซูมหน้า → หา 5 จุด

อ้างอิง: Espressif Systems. (2023). ESP-DL: Deep Learning Library for ESP32 Series SoCs.
    ลิงก์: https://github.com/espressif/esp-dl


2.1.2 EMA Smoothing (การกรอง Noise ด้วยค่าเฉลี่ยเคลื่อนที่แบบเอ็กซ์โพเนนเชียล)
------------------------------------------------------------

Noise จากกล้องคืออะไร?
    Noise ในที่นี้ไม่ใช่เสียง แต่หมายถึง "ค่าตัวเลขที่กระตุกไปมา" 
    แม้ว่าของจริงไม่ได้เปลี่ยน

    ตัวอย่าง: สมมติคุณนั่งนิ่งๆ ทำหน้าปกติ ไม่ขยับเลย
    ค่า Ratio ความกว้างปากที่กล้องวัดได้ "ควรจะคงที่" แต่จริงๆ แล้ว:
        เฟรม 1:  0.350
        เฟรม 2:  0.358  ← กระตุกขึ้น
        เฟรม 3:  0.342  ← กระตุกลง
        เฟรม 4:  0.355
        เฟรม 5:  0.339  ← กระตุกอีก
    ค่าวิ่งขึ้นลงรอบ 0.35 ตลอดเวลา ทั้งที่หน้าไม่ได้ขยับ! นี่คือ Noise

    สาเหตุของ Noise:
        - แสงเปลี่ยน: ไฟกระพริบเล็กน้อย → ตำแหน่ง keypoint เลื่อนนิด
        - เซนเซอร์กล้อง: OV2640 ราคาถูก มี electronic noise ในตัว
        - AI ไม่เป๊ะ: โมเดลบอกตำแหน่ง keypoint อาจขยับ ±2-3 พิกเซลทุกเฟรม
        - คนหายใจ/กระพริบตา: หัวสั่นเล็กน้อย แต่ไม่ได้หมายความว่าอารมณ์เปลี่ยน

EMA (Exponential Moving Average) คืออะไร?
    EMA คือเทคนิคการกรอง Noise โดยเอาค่าใหม่มา "ผสม" กับค่าเก่า
    ให้น้ำหนักค่าล่าสุดมากกว่าค่าเก่าๆ

    สมการ: smoothed = alpha x new_value + (1 - alpha) x previous_smoothed

    alpha (ค่าความไว) = 0 ถึง 1
        alpha ใกล้ 1 = ตอบสนองเร็ว แต่ยังมี noise
        alpha ใกล้ 0 = เรียบมาก แต่ตอบสนองช้า
        ในงานเราใช้ alpha = 0.5 (กึ่งกลาง)

    ผลลัพธ์:
        ก่อน EMA: 0.350, 0.372, 0.345, 0.368 → กระตุก → อารมณ์สลับไปมา!
        หลัง EMA: 0.350, 0.361, 0.353, 0.361 → นิ่ง → อารมณ์ไม่เปลี่ยนจนกว่าจะยิ้มจริง!


2.1.3 Adaptive Baseline (ปรับค่าอ้างอิงอัตโนมัติ)
------------------------------------------------------------

ปัญหาที่ต้องแก้:
    คนแต่ละคนมีโครงหน้าต่างกัน — คนปากกว้าง vs คนปากเล็ก
    ถ้าใช้ค่าตายตัวว่า "Ratio > 0.37 = ยิ้ม" 
    คนปากกว้างจะถูกตีความว่ายิ้มตลอดเวลา ทั้งที่ไม่ได้ยิ้ม!

    นอกจากนี้ แสงก็เปลี่ยนตลอดเวลา ระยะห่างก็ไม่คงที่
    → ค่า "ปกติ" ของแต่ละคน แต่ละสถานการณ์ ไม่เท่ากัน

วิธีแก้: Adaptive Baseline
    1. เริ่มต้น (Calibration): ให้คนทำหน้าปกติ 10 เฟรม 
       → ระบบเก็บค่าเฉลี่ย → นี่คือ "หน้าปกติ" ของคนนี้ (Baseline)
    2. ระหว่างใช้งาน: ทุกเฟรม ปรับ Baseline ช้ามาก (rate = 0.003 ต่อเฟรม)
       → ถ้าแสงค่อยๆ เปลี่ยน Baseline ก็ค่อยๆ ปรับตาม
       → แต่ช้ามากพอที่การยิ้มจริงจะไม่ถูกดูดเข้าไปใน Baseline

    สมการ: baseline = baseline + 0.003 x (current - baseline)

    จากนั้นจำแนกอารมณ์โดยเทียบ "ค่าปัจจุบัน - Baseline":
        delta > +0.02 = ยิ้มมากกว่าปกติของคนนี้ = Happy
        delta > +0.035 = มุมปากตกมากกว่าปกติ = Sad
        อื่นๆ = Neutral


2.1.4 Hysteresis (การจัดการความหน่วง — ป้องกันอารมณ์กระตุก)
------------------------------------------------------------

Hysteresis คืออะไร? (ทฤษฎีต้นกำเนิด)
    Hysteresis มาจากภาษากรีก แปลว่า "มาช้า" หรือ "ตามหลัง"
    ค้นพบครั้งแรกในปี 1881 โดยนักฟิสิกส์ James Alfred Ewing 
    ตอนทดลองกับแม่เหล็ก

    หลักการ: ระบบ "จำสถานะเดิม" ไว้ 
    และต้องการพลังงาน/แรงมากกว่าปกติในการเปลี่ยนสถานะ
    "จุดเปลี่ยนไป" ไม่เท่ากับ "จุดเปลี่ยนกลับ"

    ตัวอย่างในชีวิตจริง: แอร์บ้าน
        ตั้งอุณหภูมิ 25°C
        ถ้าไม่มี Hysteresis: อุ้ณหภูมิแกว่ง 24.9-25.1 → แอร์เปิดปิดรัวๆ!
        ถ้ามี Hysteresis: ปิดที่ 24°C, เปิดที่ 26°C → แอร์ทำงานนิ่ง

    ตัวอย่าง: พัดลมระบายความร้อน CPU
        ถ้าไม่มี Hysteresis: 70°C เปิด, 69°C ปิด → เปิดปิดรัวๆ!
        ถ้ามี Hysteresis: เปิดที่ 70°C, ปิดที่ 60°C → เปิดปิดนิ่มนวล

Hysteresis ไม่ใช่ delay()
    delay() = หยุดทุกอย่าง หุ่นยนต์ค้างทั้งตัว ไม่กระพริบตา ไม่รับคำสั่ง
    Hysteresis = แค่เช็คเวลา ถ้ายังไม่ครบก็ข้ามไป ทำอย่างอื่นต่อได้

    ในโค้ดจริง:
        if (millis() - emoChangeTime < 2000) return;  // ← ไม่หยุดรอ แค่ข้ามไป!
    ระบบยังกระพริบตา หันหัว รับคำสั่ง Blockly ได้ปกติ

ในหุ่นยนต์ของเราใช้ Hysteresis 2 ชั้น:

    ชั้นที่ 1 — Consecutive Count (ต้องเห็นติดต่อกัน)
        ต้องตรวจจับอารมณ์ใหม่ 2 เฟรมติดต่อกัน ก่อนจะเปลี่ยน
        ถ้าเฟรมที่ 1 เป็น Happy แต่เฟรมที่ 2 เป็น Neutral → นับใหม่ 
        (เฟรมเดียวอาจเป็น noise)

    ชั้นที่ 2 — Minimum Hold Time (ต้องค้างก่อน)
        หลังเปลี่ยนอารมณ์แล้ว ต้องค้างอย่างน้อย:
        - 500ms ที่ฝั่งกล้อง (ESP32-S3)
        - 2000ms ที่ฝั่งตัวหลัก (ESP32)
        ระหว่างนี้ ต่อให้กล้องบอกอารมณ์ใหม่ → ไม่เปลี่ยน!

    ผลลัพธ์:
        ไม่มี: Happy → Neutral → Happy → Neutral (กระตุก!)
        มี:    Happy (ค้าง 2 วิ).......... Neutral (ค้าง 2 วิ) (เป็นธรรมชาติ!)


2.1.5 Emotion State Machine (FSM — เครื่องสถานะจำกัดสำหรับอารมณ์)
------------------------------------------------------------

State Machine คืออะไร?
    State Machine = "ตอนนี้อยู่สถานะอะไร" + "จะเปลี่ยนเมื่อไร" + "ทำอะไรตอนเปลี่ยน"
    มันคือ if-else ที่มีการ "จำ" สถานะปัจจุบันไว้

    ตัวอย่างในชีวิตจริง: ไฟจราจร
        มี 3 สถานะ: เขียว → เหลือง → แดง → เขียว (วนลูป)
        กฎ: ตอนนี้เขียว → ครบ 30 วิ → เปลี่ยนเป็นเหลือง
        ต้องรู้ 2 อย่างเสมอ:
        1. ตอนนี้อยู่สถานะอะไร (เขียว? เหลือง? แดง?)
        2. เงื่อนไขเปลี่ยนคืออะไร (ครบเวลา? มีเหตุการณ์?)

    ตัวอย่าง: ประตูลิฟต์
        สถานะ: ปิด → กำลังเปิด → เปิด → กำลังปิด
        กฎ: กดปุ่ม → เปลี่ยนจาก "ปิด" เป็น "กำลังเปิด"
             มีคนเดินผ่านตอนปิด → เปลี่ยนกลับเป็น "กำลังเปิด"

ในหุ่นยนต์ของเราใช้อย่างไร?
    ตัวแปรสำคัญ: currentEmotion = ตอนนี้อยู่อารมณ์อะไร
    
    สถานะ 8 อารมณ์:
        N = Normal (ปกติ)
        H = Happy (มีความสุข)
        S = Sad (เศร้า)
        A = Angry (โกรธ)
        O = Shocked (ตกใจ)
        Z = Sleepy (ง่วง)
        C = Confused (งง)
        V = Love (รัก)

    กฎการเปลี่ยน:
        1. กล้องส่งอารมณ์ใหม่มา
        2. ถ้าเหมือนเดิม → ไม่ทำอะไร
        3. ถ้าต่างกัน → เช็ค Hysteresis (ครบ Hold Time ไหม?)
        4. ถ้าผ่าน → เปลี่ยน! → วาดตาใหม่ + ขยับร่างกาย

    ถ้าไม่ใช้ State Machine จะเกิดอะไร?
        ไม่รู้ว่าตอนนี้อยู่อารมณ์อะไร → วาดตาซ้ำทุกเฟรม → กระตุก!
    ถ้าใช้ State Machine:
        รู้ว่าตอนนี้อยู่ Happy → กล้องบอก Happy → เหมือนเดิม → ไม่วาดซ้ำ → ไม่กระตุก!


2.1.6 Body-Face Coordination (การประสานท่าทางร่างกายกับใบหน้า)
------------------------------------------------------------

คืออะไร?
    การที่หุ่นยนต์แสดงอารมณ์ไม่ใช่แค่บนหน้าจอ (ตา) 
    แต่ขยับร่างกาย (หัว + แขน) ประกอบด้วย
    ทำให้ดูสมจริงมากขึ้น เหมือนคนจริงที่แสดงอารมณ์ทั้งใบหน้าและท่าทาง

ในหุ่นยนต์ของเรา:
    ทุกครั้งที่เปลี่ยนอารมณ์ ระบบจะทำ 2 อย่างพร้อมกัน:
    1. วาดตาใหม่บนจอ TFT (Face)
    2. ขยับเซอร์โวหัว + แขน (Body)

    อารมณ์แต่ละตัว:
        Happy  → หัวตรง (90°) + ยกแขนขึ้น
        Sad    → ก้มหัว (80°) + แขนตก
        Angry  → หัวตรง (90°) + แขนเกร็ง
        Shocked → เงยหลัง (95°) + ยกแขนสูง + แบมือ
        Normal → หัวตรง (90°) + แขนกลาง

แนวคิดมาจาก: Ribeiro & Paiva (2012) 
    ที่ใช้หลักแอนิเมชันของ Disney กับหุ่นยนต์ ทำให้ดู "มีชีวิต" มากขึ้น


2.1.7 Idle Behaviors (พฤติกรรมขณะว่าง — ทำให้หุ่นดูมีชีวิต)
------------------------------------------------------------

คืออะไร?
    หุ่นยนต์ที่ดูมีชีวิตจะต้องมีการเคลื่อนไหวตลอดเวลา 
    แม้ไม่ได้รับคำสั่งหรือไม่ได้มีคนอยู่ตรงหน้า
    เหมือนคนจริงที่กระพริบตา หายใจ มองไปมา แม้ตอนนั่งเฉยๆ

ในหุ่นยนต์ของเรามี 4 พฤติกรรม:

    1. Blink (กระพริบตา) — ทุกๆ 2.5-5.5 วินาที
       มีรูปแบบ: กระพริบครั้งเดียว / กระพริบ 2 ครั้ง / กระพริบ 3 ครั้ง (สุ่ม)

    2. Glance (เหลือบมอง) — ทุกๆ 8-20 วินาที
       ม่านตาเลื่อนไปซ้ายหรือขวา แล้วกลับที่เดิม

    3. Sigh (ถอนหายใจ) — ทุกๆ 25-45 วินาที
       ตาหรี่ลง (Half-Closed) ค้าง 0.6 วิ แล้วกลับปกติ

    4. Head Look (หันหัว) — ทุกๆ 10-25 วินาที
       หัวค่อยๆ หันไปซ้ายหรือขวา (75°-105° ปลอดภัย) 
       ค้าง 2 วิ แล้วค่อยๆ กลับกลาง (ผ่าน Servo Lerp ราบรื่น)

แนวคิดมาจาก: Ribeiro & Paiva (2012)
    "Illusion of Life" — สิ่งมีชีวิตต้องขยับตลอดเวลา

อธิบาย Section 2.2: งานวิจัย 5 เรื่อง (อธิบายเป็นภาษาไทย)
============================================================

Paper 1: Belpaeme et al. (2018) — "หุ่นยนต์ที่แสดงอารมณ์ ช่วยให้เด็กอยากเรียนมากขึ้น"
------------------------------------------------------------
ลิงก์: https://doi.org/10.1126/scirobotics.aat5954
วารสาร: Science Robotics (Q1)

เขาทำอะไร:
    ทีมวิจัยไปอ่าน paper 101 เรื่องที่เกี่ยวกับหุ่นยนต์สอนเด็ก
    แล้วสรุปว่า "หุ่นยนต์แบบไหนช่วยให้เด็กเรียนรู้ได้ดี"

ค้นพบอะไร:
    หุ่นยนต์ที่แสดงอารมณ์ได้ (เช่น ยิ้ม เศร้า ตกใจ)
    ทำให้เด็กรู้สึกว่าหุ่นยนต์ "เข้าใจ" ตัวเอง
    → เด็กอยากเรียนมากขึ้น เมื่อเทียบกับหุ่นยนต์ที่หน้าตาไม่เปลี่ยนเลย

ข้อจำกัด:
    เป็นงาน review (อ่านแล้วสรุป) — ไม่ได้สร้างหุ่นยนต์จริง
    ไม่ได้บอกว่าต้องเขียนโค้ดยังไง

เกี่ยวกับเรายังไง:
    เป็นหลักฐานว่าสิ่งที่เราทำ (ให้หุ่นแสดงอารมณ์) มันมีประโยชน์จริง
    ไม่ใช่ทำเล่นๆ — มีผลต่อการเรียนรู้ของเด็กจริงๆ


Paper 2: Spezialetti et al. (2020) — "วิธีไหนดีที่สุดในการจับอารมณ์คน?"
------------------------------------------------------------
ลิงก์: https://doi.org/10.3389/frobt.2020.532279
วารสาร: Frontiers in Robotics and AI (Q1)

เขาทำอะไร:
    สำรวจวิธีทั้งหมดที่ใช้จับอารมณ์คนสำหรับหุ่นยนต์ ได้แก่:
    - วัดชีพจร/เหงื่อ (ต้องติดเซนเซอร์ที่ตัวคน — ไม่สะดวก)
    - ดูหน้า (ใช้กล้อง — สะดวก ไม่ต้องแตะตัว)
    - ฟังเสียง (ต้องมีไมค์ + มีปัญหาเรื่อง noise)
    - รวมหลายอย่าง (ดีแต่ซับซ้อนมาก)

ค้นพบอะไร:
    ดูหน้า (facial expression) เป็นวิธีที่ใช้มากที่สุดและได้ผลดีที่สุด
    เพราะไม่ต้องติดเซนเซอร์ที่ตัวคน แค่มีกล้องก็พอ

ข้อจำกัด:
    งานส่วนใหญ่ที่สำรวจ ทำบนคอมพิวเตอร์ตั้งโต๊ะหรือ Cloud
    ยังไม่มีใครลองทำบนบอร์ดเล็กๆ แบบ ESP32

เกี่ยวกับเรายังไง:
    ยืนยันว่าวิธีที่เราเลือก (ใช้กล้องดูหน้า) เป็นวิธีที่ดีที่สุด!
    + ชี้ให้เห็นว่ายังไม่มีใครทำบน Edge → นี่คือช่องว่างที่เราเข้าไปเติม!


Paper 3: Goulart et al. (2019) — "ดูจุดบนใบหน้า แล้วคำนวณว่ายิ้มหรือเศร้า"
------------------------------------------------------------
ลิงก์: https://doi.org/10.3390/s19132844
วารสาร: Sensors — MDPI (Q1)

เขาทำอะไร:
    ใช้กล้องถ่ายหน้าเด็ก 
    → หาจุดสำคัญบนใบหน้า (ตา จมูก ปาก)
    → คำนวณ "สัดส่วน" ระหว่างจุด (Ratio)
    → ถ้าปากกว้าง = ยิ้ม, ถ้ามุมปากตก = เศร้า

เหมือนเราตรงไหน:
    เหมือนกันมาก! เราก็ใช้ 5 Keypoints → คำนวณ Ratio → จำแนก H/S/N
    เหมือนกันเลย

ข้อจำกัดที่เราแก้:
    Goulart (2019)                    เรา
    ประมวลผลบน PC                  → ประมวลผลบน ESP32-S3 (ชิปเล็กๆ)
    จับได้ = เปลี่ยนทันที (กระตุก)  → มี EMA + Hysteresis (ราบรื่น)
    ไม่มี Idle Behaviors            → มี กระพริบตา หันหัว

ทำไมสำคัญ:
    เขาคิดวิธีเหมือนเรา แต่เราเอามาปรับปรุงให้ดีกว่า + รันบนบอร์ดเล็กได้


Paper 4: Ribeiro & Paiva (2012) — "ใช้หลักแอนิเมชัน Disney ทำให้หุ่นยนต์ดูมีชีวิต"
------------------------------------------------------------
ลิงก์: https://doi.org/10.1145/2157689.2157814
วารสาร: ACM/IEEE HRI (CORE A* Conference — ระดับสูงสุดของ conference)

เขาทำอะไร:
    เอาหลักแอนิเมชัน 12 ข้อของ Disney (ที่ใช้ทำการ์ตูน Pixar)
    มาใช้กับหุ่นยนต์จริง เช่น:
    - Easing: เคลื่อนไหวค่อยๆ เร็วขึ้น ค่อยๆ ช้าลง (ไม่ใช่เร็วเท่ากันตลอด)
    - Anticipation: ก่อนทำอะไร ต้องมีท่าเตรียม (เช่น ก่อนกระโดดต้องย่อตัว)
    - Follow-through: หลังทำเสร็จต้องมีท่าตาม (เช่น โยนบอลแล้วมือยังแกว่ง)

ค้นพบอะไร:
    ให้คนดูหุ่นยนต์ 2 ตัว:
    - ตัวที่ 1: เคลื่อนไหวแบบปกติ
    - ตัวที่ 2: เคลื่อนไหวตามหลัก Disney
    ผลลัพธ์: ตัวที่ 2 ถูกประเมินว่า "มีชีวิตมากกว่า" อย่างชัดเจน!

ข้อจำกัด:
    ทดสอบบนหุ่นยนต์ตัวใหญ่ที่มี PC ควบคุม
    ยังไม่มีใครนำไปใช้บนบอร์ดเล็กทรัพยากรต่ำ

เกี่ยวกับเรายังไง:
    เราเอาแนวคิดเดียวกันมาใส่หุ่นของเรา:
    - Idle Behaviors (กระพริบ เหลือบมอง หันหัว) = "ของมีชีวิตต้องขยับตลอด"
    - Body-Face Coordination (ยิ้ม=ยกแขน, เศร้า=ก้มหัว) = Anticipation + Follow-through
    แต่เราย่อลงให้รันบน ESP32 ได้โดยไม่ต้องใช้ PC!

หมายเหตุเรื่องระดับ:
    ACM/IEEE HRI ไม่ใช่ journal เป็น conference จึงไม่มีอันดับ Q1 ตาม SCImago
    แต่ถูกจัดอันดับเป็น CORE A* ซึ่งเป็นอันดับสูงสุดของ conference
    เทียบเท่ากับ Q1 ของ journal


Paper 5: Bennett & Sabanovic (2014) — "แค่ตา 2 ดวงก็พอให้คนบอกอารมณ์ได้"
------------------------------------------------------------
ลิงก์: https://doi.org/10.1007/s12369-014-0237-z
วารสาร: International Journal of Social Robotics — Springer (Q1)

เขาทำอะไร:
    ทดลองว่าหุ่นยนต์ต้องมีส่วนประกอบบนหน้ากี่ชิ้น
    ถึงจะทำให้คนจำอารมณ์ได้:
    - ต้องมีคิ้วไหม?
    - ต้องมีปากไหม?
    - ต้องมีแก้มไหม?

ค้นพบอะไร:
    แค่ "ตา + ปาก" ก็เพียงพอ!
    คนสามารถจดจำอารมณ์ได้จากรูปทรงของตาเพียงอย่างเดียว
    ไม่จำเป็นต้องมีหน้าที่ซับซ้อน

ข้อจำกัด:
    ทดสอบแค่ว่า "คนจำได้ไหม?"
    ไม่ได้ทดสอบการเปลี่ยนอารมณ์แบบ real-time 
    หรือการเปลี่ยนแบบราบรื่น (smooth transition)

เกี่ยวกับเรายังไง:
    ยืนยันว่าหุ่นยนต์ของเราที่มีแค่ตา 2 ดวงบนจอ TFT ก็เพียงพอ!
    ไม่ต้องทำปาก ไม่ต้องทำคิ้ว 
    → ประหยัดทรัพยากร + ง่ายต่อการแสดงผลบน ESP32
