# เนื้อหาบทที่ 3 — วิธีดำเนินการวิจัย (ก๊อปวางได้เลย)

---

บทที่ 3
วิธีดำเนินการวิจัย

3.1 ภาพรวมกระบวนการทำงานของระบบ (System Pipeline & Workflow)
ระบบ RoboMDT ประกอบด้วย 4 โมดูลหลักที่ทำงานร่วมกัน ได้แก่ โมดูลกล้องตรวจจับใบหน้า โมดูลประมวลผลกลาง โมดูลเว็บแอปพลิเคชัน Block Coding และโมดูล AI ผู้ช่วยสอน โดยมีกระบวนการทำงานตั้งแต่ต้นน้ำจนถึงปลายน้ำดังนี้

ขั้นตอนที่ 1 Data Input — โมดูลกล้อง ESP32-CAM จับภาพใบหน้าผู้เรียนแบบเรียลไทม์ด้วยกล้อง OV2640 ความละเอียด 240×240 พิกเซล ในรูปแบบ RGB565 ขณะเดียวกันเว็บแอปพลิเคชัน Blockly รับคำสั่งบล็อกจากผู้เรียนผ่านเว็บเบราว์เซอร์

ขั้นตอนที่ 2 Preprocessing — ภาพจากกล้องถูกปรับขนาดเป็น 240×240 พิกเซลและแปลงเป็นรูปแบบที่ ESP-DL รองรับ จากนั้นนำเข้าสู่โมเดลตรวจจับใบหน้าขั้นที่ 1 (MSR01) เพื่อระบุตำแหน่ง Bounding Box หากพบใบหน้าจะส่งต่อไปยังโมเดลขั้นที่ 2 (MNP01) เพื่อหา 5 Keypoints (ตาซ้าย ตาขวา จมูก ปากซ้าย ปากขวา) ค่า Keypoints ที่ได้จะผ่านการกรองด้วย Exponential Moving Average (EMA, α = 0.5) เพื่อลด Noise และปรับค่าอ้างอิงด้วย Adaptive Baseline Calibration (rate = 0.003) เพื่อชดเชยการเปลี่ยนแปลงของสภาพแวดล้อม

ขั้นตอนที่ 3 Model Processing — ระบบคำนวณ Ratio จาก Keypoints ที่ผ่านการกรองแล้ว (เช่น ความกว้างปาก ระยะจมูก-ปาก มุมหมุนปาก) แล้วเปรียบเทียบกับ Baseline เพื่อจำแนกอารมณ์ โดยใช้ Hysteresis (Consecutive Count = 2 เฟรม, Hold Time = 500 มิลลิวินาที) ป้องกันการสลับอารมณ์ไปมา ผลลัพธ์จะถูกส่งไปยัง Emotion State Machine (FSM) ที่ควบคุมการเปลี่ยนสถานะอารมณ์ 8 แบบ (Normal, Happy, Sad, Angry, Shocked, Sleepy, Confused, Love)
ในส่วนของคำสั่ง Block Coding ระบบจะแปลงบล็อกเป็นสตริงคำสั่ง (เช่น "w;a;w;a;") แล้วส่งไปยัง ESP32-S3 ผ่าน HTTP GET Request

ขั้นตอนที่ 4 Output — ESP32-S3 สั่งการแสดงผลพร้อมกัน 2 ช่องทาง ได้แก่ (1) วาดดวงตาบนจอ TFT ST7789 ขนาด 2.8 นิ้ว ตามอารมณ์ที่จำแนกได้ และ (2) สั่งเซอร์โวมอเตอร์ 5 ตัว (มือ 2 แขน 2 หัว 1) ให้แสดงท่าทางประกอบอารมณ์ (Body-Face Coordination) นอกจากนี้ยังมี Idle Behaviors 4 รูปแบบ (Blink, Glance, Sigh, Head Look) ที่ทำให้หุ่นยนต์ดูมีชีวิตชีวาแม้ไม่ได้รับคำสั่ง

ภาพที่ 13 แผนภาพกระบวนการทำงานของระบบ RoboMDT ตั้งแต่ Data Input จนถึง Output (จัดทำโดยผู้วิจัย)

สิ่งที่ต้องทำ: วาด Flowchart ใน draw.io หรือ Word SmartArt ตามขั้นตอน 4 ขั้นข้างบน

3.2 การจัดการชุดข้อมูลและการเตรียมข้อมูล (Dataset & Data Preprocessing)

3.2.1 แหล่งที่มาของข้อมูล
งานวิจัยนี้ใช้โมเดลสำเร็จรูปจากไลบรารี ESP-DL (Espressif Systems, 2023) ซึ่งเป็นไลบรารีโอเพนซอร์สสำหรับรันโมเดล Deep Learning บนชิป ESP32-S3 โดยไม่ต้องฝึกสอน (Training) โมเดลใหม่ด้วยตนเอง โมเดลที่ใช้มี 2 ตัว ดังนี้

โมเดล	ชื่อเต็ม	หน้าที่	แหล่งที่มา
MSR01	Human Face Detect MSR01	ตรวจจับตำแหน่งใบหน้า (Bounding Box)	ESP-DL Pre-trained Model
MNP01	Human Face Detect MNP01 (Facial Landmarks)	ระบุ 5 Keypoints บนใบหน้า	ESP-DL Pre-trained Model
ตารางที่ 3 โมเดลจาก ESP-DL ที่ใช้ในงานวิจัย

โมเดลทั้งสองถูกฝึกสอนล่วงหน้า (Pre-trained) โดย Espressif Systems ด้วยชุดข้อมูลใบหน้ามนุษย์หลากหลายเชื้อชาติและสภาพแสง โดยออกแบบมาเพื่อทำงานบนไมโครคอนโทรลเลอร์ที่มีทรัพยากรจำกัด ข้อมูลที่ป้อนเข้าระบบคือภาพ RGB565 ขนาด 240×240 พิกเซลจากกล้อง OV2640 ที่ถ่ายภาพแบบเรียลไทม์

3.2.2 คุณลักษณะข้อมูล
ข้อมูลภาพที่ใช้ในระบบมีลักษณะดังนี้
	ความละเอียด: 240 × 240 พิกเซล
	รูปแบบสี: RGB565 (16-bit, 2 bytes ต่อพิกเซล)
	อัตราเฟรม: ประมาณ 5–10 FPS (ขึ้นอยู่กับสภาพแสงและจำนวนใบหน้า)
	ประเภทข้อมูล: ภาพใบหน้าผู้เรียนในสภาพแวดล้อมห้องเรียนจริง
	สภาพแสง: แสงธรรมชาติและแสงไฟในอาคาร (ไม่ได้ควบคุมสภาพแสง)

3.2.3 การเตรียมข้อมูล (Preprocessing Pipeline)
กระบวนการเตรียมข้อมูลก่อนนำเข้าสู่โมเดลมีดังนี้
	ขั้นที่ 1 — Resize: ปรับขนาดภาพจากกล้อง OV2640 เป็น 240×240 พิกเซล
	ขั้นที่ 2 — Color Space: แปลงภาพเป็นรูปแบบ RGB565 ตามที่ ESP-DL กำหนด
	ขั้นที่ 3 — Face Detection (MSR01): สแกนภาพเพื่อหาตำแหน่ง Bounding Box ของใบหน้า
	ขั้นที่ 4 — Landmark Detection (MNP01): ซูมเข้าที่ Bounding Box แล้วหา 5 Keypoints
	ขั้นที่ 5 — EMA Smoothing: กรองค่า Keypoints ด้วย EMA (α = 0.5) เพื่อลด Noise
	ขั้นที่ 6 — Baseline Calibration: ปรับค่าอ้างอิงอย่างช้า (rate = 0.003) เพื่อชดเชยสภาพแวดล้อม
	ขั้นที่ 7 — Ratio Calculation: คำนวณ Ratio จาก Keypoints (ความกว้างปาก ระยะจมูก-ปาก มุมหมุน)
	ขั้นที่ 8 — Emotion Classification: เปรียบเทียบ Ratio กับ Baseline + Threshold เพื่อจำแนกอารมณ์

ภาพที่ 14 ตัวอย่างภาพจากกล้อง OV2640 ก่อนและหลัง Preprocessing แสดง Bounding Box และ 5 Keypoints ที่ตรวจจับได้ (จัดทำโดยผู้วิจัย)

สิ่งที่ต้องทำ: แคปหน้าจอ Serial Monitor ที่แสดง Bounding Box + 5 Keypoints วาดทับภาพจากกล้อง หรือถ่ายจอคอมที่รันโค้ดแสดงผล

3.3.4 เว็บแอปพลิเคชัน Block Coding
ระบบเขียนโค้ดแบบบล็อกพัฒนาบน Google Blockly Framework ทำงานผ่านเว็บเบราว์เซอร์ ไม่ต้องติดตั้งซอฟต์แวร์เพิ่มเติม ผู้เรียนสามารถลากวางบล็อกคำสั่ง 6 หมวด ได้แก่ Motion (เดินหน้า/ถอยหลัง/เลี้ยวซ้าย/เลี้ยวขวา), Arm (ยกแขน/ลดแขน/ตั้งตรง), Hand (กำมือ/แบมือ/ตั้งตรง), Head (หันซ้าย/กลาง/หันขวา), Face (เปลี่ยนอารมณ์ Happy, Sad, Angry ฯลฯ) และ Control (Loop, If-Else, Wait, Stop) เมื่อกดปุ่ม Run ระบบจะแปลงบล็อกเป็นสตริงคำสั่ง (เช่น "w;a;w;a;") แล้วส่งไปยัง ESP32-S3 ผ่าน HTTP GET Request โดยสื่อสารผ่านเครือข่าย Wi-Fi ที่หุ่นยนต์สร้างขึ้นเอง (Access Point Mode: SSID "RobotMDT")

ภาพที่ 17 หน้าจอเว็บแอปพลิเคชัน Block Coding แสดง Toolbox, Workspace และปุ่ม Run
ภาพที่ 18 สถาปัตยกรรมการสื่อสารระหว่างเว็บแอป Blockly กับ ESP32 ผ่าน HTTP

3.3.5 ระบบ AI ผู้ช่วยสอน
ระบบ AI ผู้ช่วยสอนใช้ Gemini API (Google) ผ่าน Cloud Server เป็นตัวกลาง ทำหน้าที่วิเคราะห์โค้ดบล็อกของผู้เรียนและตอบสนองตามหลัก Scaffolding โดยจะไม่เฉลยคำตอบ แต่ใช้คำถามชี้แนะ (Socratic Method) เพื่อให้ผู้เรียนคิดหาคำตอบด้วยตนเอง เหตุผลที่ต้องมี Cloud Server คั่นกลางคือเพื่อซ่อน API Key ไม่ให้ผู้ใช้ปลายทางเห็น และควบคุมปริมาณการใช้งาน (Rate Limiting)

ภาพที่ 19 สถาปัตยกรรม LLM API ของระบบ AI ผู้ช่วยสอน

3.4 การประเมินประสิทธิภาพ (Evaluation Metrics)

งานวิจัยนี้ใช้ตัวชี้วัด 4 ด้านในการประเมินประสิทธิภาพของระบบ RoboMDT ดังนี้

3.4.1 ด้านความพึงพอใจของผู้เรียน (User Satisfaction)
ใช้แบบสอบถามมาตราส่วนประเมินค่า 5 ระดับ (Likert Scale) จำนวน 15–20 ข้อ ครอบคลุม 4 ด้าน ได้แก่ ด้านการเรียนรู้ ด้านความสนุกและแรงจูงใจ ด้านความง่ายในการใช้งาน และด้านการออกแบบหุ่นยนต์ วิเคราะห์ด้วยค่าเฉลี่ย (x̄) และส่วนเบี่ยงเบนมาตรฐาน (S.D.)
เกณฑ์แปลผล: 4.51–5.00 = มากที่สุด, 3.51–4.50 = มาก, 2.51–3.50 = ปานกลาง, 1.51–2.50 = น้อย, 1.00–1.50 = น้อยที่สุด

3.4.2 ด้านอัตราการทำโจทย์สำเร็จ (Task Completion Rate)
วัดร้อยละของผู้เข้าร่วมที่ทำโจทย์ Coding Tasks สำเร็จในแต่ละระดับความยาก (Basic, If-Else, Loop) เพื่อประเมินว่าระบบรองรับการเรียนรู้แบบขั้นบันไดได้ดีเพียงใด

3.4.3 ด้านปฏิสัมพันธ์กับ AI ผู้ช่วยสอน (AI Interaction Metrics)
วัดจำนวนครั้งที่ผู้เรียนขอความช่วยเหลือจาก AI ในแต่ละโจทย์ และวิเคราะห์ว่าการชี้แนะแบบ Scaffolding (ไม่เฉลยคำตอบ) ส่งผลต่อความสามารถในการแก้ปัญหาด้วยตนเองอย่างไร

3.4.4 ด้านต้นทุนและความคุ้มค่า (Cost-Effectiveness)
เปรียบเทียบต้นทุนต่อชุดของ RoboMDT (~2,000–2,500 บาท) กับหุ่นยนต์เพื่อการศึกษาในท้องตลาด ได้แก่ LEGO Mindstorms (12,000–15,000 บาท), Makeblock mBot (3,500 บาท), Edison Robot (4,000 บาท) และ Thymio (~4,500 บาท) เพื่อประเมินความเป็นไปได้ในการนำไปใช้จริงในสถานศึกษาที่มีงบประมาณจำกัด
