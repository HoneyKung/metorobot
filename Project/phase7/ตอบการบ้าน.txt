Project Overwrite (ภาพรวมโครงการที่ปรับปรุงแล้ว) 

Problem Statement (ปัญหาที่ต้องการแก้) : เด็กไทยมีคะแนน PISA ด้านคณิตศาสตร์และวิทยาศาสตร์ต่ำกว่าค่าเฉลี่ย และขาดทักษะดิจิทัลที่จำเป็น 

การเรียนเขียนโปรแกรมแบบเดิมที่เป็นแบบอักษร (Text-based) มีความซับซ้อน น่าเบื่อและเข้าใจยาก ทำให้ผู้เรียนรู้สึกท้อแท้ 

หุ่นยนต์เพื่อการศึกษในตลาดมีราคาสูง ทำให้โรงเรียนที่ขาดแคลนงบประมาณเข้าไม่ถึง 

หุ่นยนต์สำเร็จรูปมักประกอบมาเสร็จแล้ว ทำให้ผู้เรียนไม่ได้เรียนรู้โครงสร้างทางวิศวกรรม และขาดปฏิสัมพันธ์เชิงอารมณ์ที่ช่วยสร้างแรงจูงใจ 

ประเทศไทยกำลังเผชิญปัญหาขาดแคลนบุคลากรดิจิทัล และทักษะด้านวิทยาการคอมพิวเตอร์ของผู้เรียนยังอยู่ในเกณฑ์ต่ำ 

Expected Output (ผลที่คาดหวังจากระบบ AI และโครงงาน) : แพลตฟอร์มหุ่นยนต์เพื่อการศึกษา RoboMDT แบบโมดูลาร์ที่ผู้เรียนสามารถประกอบเองได้ ในราคาประหยัด  

ระบบประมวลผล AI บน Edge (ESP32) ที่สามารถตรวจจับใบหน้าผู้เรียน และแสดงอารมณ์โต้ตอบบนหน้าจอ TFT ได้ 8 รูปแบบ 

แพลตฟอร์มเว็บแอปพลิเคชันที่รองรับการเขียนโปรแกรมแบบบล็อก (Block-based Coding) พร้อมระบบ AI ผู้ช่วยสอนผ่าน Gemini API ที่ใช้หลักการ Scaffolding และ Socratic Method ในการชี้แนะผู้เรียนโดยไม่เฉลยคำตอบตรงๆ  

Dataset Description (ข้อมูลที่จะใช้) 

ระบบที่งานวิจัยเลือกใช้เป็นโมเดลสำเร็จรูป (Pre-trained Model) จากไลบรารี ESP-DL ข้อมูลที่ระบบนำมาประมวลผลเป็น ข้อมูลภาพแบบเรียลไทม์ (Real-time Streaming Data) ที่รับเข้ามาเพื่อทำ Inference บน Edge Device โดยมีรายละเอียดดังนี้ 

แหล่งที่มาของข้อมูล : ภาพถ่ายใบหน้าของผู้เรียนแบบเรียลไทม์ (Real-time) ที่รับเข้ามาผ่านโมดูลกล้อง OV2640 ที่ติดตั้งอยู่บนตัวหุ่นยนต์ 

ประเภทไฟล์ข้อมูล : ข้อมูลภาพถูกดึงมาและแปลงให้อยู่ในรูปแบบ RGB565 (16-bit , 2 bytes ต่อพิกเซล) เพื่อให้รองรับการทำงานกับไลบรารี ESP-DL บนชิปไมโครคอนโทรลเลอร์  

ขนาดและความละเอียดของข้อมูล : ภาพจะถูกปรับขนาด (Resize) ให้มีความละเอียดที่ 240 x 240 พิกเซล 

จำนวนตัวอย่าง : ข้อมูลเข้าสู่ระบบอย่างต่อเนื่องในลักษณะวิดีโอสตรีมมิ่งด้วยความเร็วประมาณ 5-10 เฟรมต่อวินาที (FPS) ในส่วนของความเร็วจะขึ้นอยู่กับปริมาณแสง และจำนวนใบหน้าภายในเฟรม 

สัดส่วนข้อมูลและการจำแนก : ไม่มีการแบ่งสัดส่วน Class ของชุดข้อมูลเพื่อ Train แต่โมเดลจะรับข้อมูลภาพเพื่อนำมาจำแนกตามตรรกะของระบบ (Emotion State Machine) ออกเป็น Output 8 คลาส (8 อารมณ์) ได้แก่ Normal, Happy, Sad, Angry, Shocked, Sleepy, Confused และ Love  

Model Architecture (โมเดลที่เลือก และการนำเสนอด้วยภาพ) 

ประเภทโมเดลที่เลือก : ระบบใช้ Pre-trained Model สำเร็จรูปจากไลบรารี ESP-DL (Deep Learning Library สำหรับชิป ESP32) โดยทำงานร่วมกัน 2 โมเดลในรูปแบบ Two-Stage Pipeline ได้แก่  

MSR01 (Multi-Scale RetinaNet) : ทำหน้าที่ Face Detection เพื่อหาตำแหน่งใบหน้าและสร้าง Bounding Box 

MNP01 (MobileNet Pruned) : ทำหน้าที่ Landmark Detection โดยซูมเข้าที่ Bounding Box เพื่อหาจุด 5 Keypoints (ตาซ้าย, ตาขวา, จมูก, ปากซ้าย, ปากขวา) 

เหตุผลที่เลือกใช้ : เนื่องจากหุ่นยนต์ทำงานบน Edge Device (ESP32-S3) ที่มีทรัพยากรจำกัด การใช้ Pre-trained Model ที่ถูก Optimize มาเพื่อไมโครคอนโทรลเลอร์โดยเฉพาะ (ESP-DL) จะช่วยลดความล่าช้า (Latency) ไม่ต้องส่งภาพไปประมวลผลบน Cloud ซึ่งช่วยให้ระบบตอบสนองได้แบบเรียลไทม์และรักษาความเป็นส่วนตัวของผู้ใช้งาน 

เพิ่มเติมสำหรับระบบ AI ผู้ช่วยสอน : ใช้ Pre-trained Large Language Model (LLM) ผ่าน Gemini API ของ Google  

 

Hyperparameters เบื้องต้น  

ระบบมีการตั้งค่า Inference & Post-processing Hyperparameters เพื่อปรับจูนความแม่นยำและความเสถียรของการจำแนกอารมณ์ ดังนี้  

EMA  α  (Smoothing Factor) : กำหนดค่า 0.5 เพื่อรักษาสมดุลระหว่างความเร็วในการตอบสนองกับการกรอง Noise ของพิกัดใบหน้า 

Adaptive Baseline Rate : กำหนดค่า 0.003 เพื่อปรับค่าอ้างอิงโครงหน้าอย่างช้าๆ ชดเชยการเปลี่ยนแปลงของสภาพแสงหรือมุมกล้อง 

Hysteresis (Consecutive Frame Count & Hold Time) : กำหนดค่า 2 เฟรม ต้องจับอารมณ์ใหม่ได้ติดกัน 2 เฟรมจึงจะเริ่มเปลี่ยนสถานะ ป้องกันการสลับอารมณ์ไปมา ร่วมกับ Main Hold Time 500 ms สำหรับกล้อง และ 2,000 ms สำหรับค้างอารมณ์บนหน้าจอเพื่อให้ดูเป็นธรรมชาติ

Technical Stack & Evaluation Metrics (เครื่องมือและการประเมินผล) 

Flamework & Environment  

AI/ML Framework : ใช้ไลบรารี ESP-DL (Deep Learning Library ของ Espressif) สำหรับการรันโมเดลตรวจจับใบหน้าและจุดสำคัญ (Landmarks) บนไมโครคอนโทรลเลอร์โดยตรง 

LLM API Framework : ใช้ Gemini API จาก Google สำหรับทำงานเป็น AI ผู้ช่วยสอน โดยเชื่อมต่อผ่าน Cloud Server ที่พัฒนาด้วย Node.js + Express 

Web Framework : ใช้ Google Blockly Framework พัฒนาด้วย HTML/CSS/JavaScript สำหรับระบบ Block-based Coding 

Hardware Environment : ทำงานแบบ Edge AI ประมวลผลบนฮาร์ดแวร์แบบ Local โดยใช้ ESP32-S3 DevKit บอร์ดหลัก ร่วมกับโมดูลกล้อง ESP32-CAM ไม่จำเป็นต้องใช้ Google Colab, Kaggle หรือ Local GPU (PC) ในการเทรน เนื่องจากใช้ Pre-trained Model และทำ Inference บนตัวอุปกรณ์ทั้งหมด  

Evaluation Metrics  

เพื่อประเมินประสิทธิภาพทั้งในส่วนของโมเดล AI และภาพรวมของระบบการเรียนรู้ จะแบ่งตัวชี้วัดออกเป็น 2 ส่วน ดังนี้ 

AI & System Performance Metrics (ตัวชี้วัดด้านระบบและโมเดล 

Accuracy & F1-Score (ด้านการจำแนกอารมณ์) : แม้จะใช้ Pre-trained โมเดลจับใบหน้า แต่การตีความ 8 อารมณ์ เกิดจากการคำนวณอัตราส่วน (Ratio) และใช้ FSM ของกลุ่มคุณเอง จึงใช้ Accuracy เพื่อดูความถูกต้องรวม และใช้ F1-Score เพื่อประเมินความแม่นยำในกรณีที่ผู้เรียนอาจแสดงบางอารมณ์ (เช่น ตกใจ, โกรธ) น้อยกว่าอารมณ์ปกติ (Class Imbalance) 

System Latency & FPS (ความหน่วงของระบบ) : วัดความเร็วในการประมวลผล (Inference Time) และเฟรมเรตตั้งแต่กล้องรับภาพจนถึงการวาดอารมณ์บนจอ TFT (เป้าหมายคือการทำงานแบบ Real-time ที่ 5-10 FPS) เพื่อยืนยันว่าฮาร์ดแวร์ทำงานได้ไม่สะดุด 

 

Educational Outcome Metrics (ตัวชี้วัดด้านผลลัพธ์ทางการศึกษา) 

Task Completion Rate (อัตราการทำโจทย์สำเร็จ) : วัดร้อยละของผู้เรียนที่สามารถแก้โจทย์ปัญหา (Coding Tasks) สำเร็จ เพื่อประเมินว่าระบบ Scaffolding และ Socratic Method ของ AI ผู้ช่วยสอนทำงานได้ผลจริง  

User Satisfaction Score : ประเมินความพึงพอใจและแรงจูงใจในการเรียนผ่านแบบสอบถาม (Likert Scale) ครอบคลุมด้านปฏิสัมพันธ์ทางอารมณ์และความง่ายในการใช้งาน

ภาพรวมระบบการทำงานของแพลตฟอร์ม RoboMDT ถูกออกแบบให้ทำงานร่วมกันระหว่างการประมวลผลบนอุปกรณ์ (Edge AI) และการเชื่อมต่อผ่านเครือข่ายไร้สาย (Web/Cloud) โดยแบ่งกระบวนการทำงานตั้งแต่ต้นน้ำถึงปลายน้ำออกเป็น 3 ขั้นตอนหลัก ดังนี้ : 

Input & Preprocessing (การรับข้อมูล และ การเตรียมข้อมูล)  

เนื่องจากระบบเป็นการทำ Inference แบบเรียลไทม์ ขั้นตอนนี้จึงเน้นไปที่การรับสตรีมมิ่งข้อมูลและการกรองสัญญาณรบกวน (Noise Filtering)  

Data Input: กล้อง ESP32-CAM รับภาพใบหน้าผู้เรียนแบบเรียลไทม์ (RGB565 ขนาด 240 x 240) และ Web Application (Blockly) รับคำสั่งจากการลากวางบล็อกของผู้เรียน  

Preprocessing (Real-time) : ภาพจากกล้องจะถูกส่งเข้าโมเดล Face Detection (MSR01) เพื่อสร้าง Bounding Box และส่งต่อให้ Landmark Detection (MNP01) หา 5 Keypoints จากนั้นทำการเตรียมข้อมูลโดยใช้สมการคณิตศาสตร์ EMA Smoothing เพื่อลดการแกว่งของจุด Keypoints และใช้ Adaptive Baseline Calibration เพื่อปรับค่าอ้างอิงโครงหน้าให้เข้ากับสภาพแสงและระยะห่างของผู้เรียนแบบอัตโนมัติ 

 

Processing/Modeling (การประมวลผลข้อมูลเข้าสู่โมเดล) 

Emotion Classification Inference : นำค่า Keypoints ที่ผ่านการกรองแล้วมาคำนวณอัตราส่วน (Ratio) จากนั้นใช้ตัวกรอง Hysteresis (หน่วงเวลา 500ms - 2,000ms และนับเฟรมต่อเนื่อง 2 เฟรม) ส่งเข้าสู่ Emotion State Machine (FSM) เพื่อจำแนกอารมณ์ออกเป็น 8 สถานะ 

Blockly Parsing & AI Tutor Processing : โค้ดบล็อกจะถูกแปลงเป็นสคริปต์คำสั่ง (เช่น "w;a;w;a;") เพื่อส่งไปควบคุมมอเตอร์ ในขณะเดียวกัน หากผู้เรียนขอความช่วยเหลือ โค้ดจะถูกส่งผ่าน Node.js Cloud Server (เพื่อซ่อน API Key) ไปยัง Gemini API (LLM) เพื่อวิเคราะห์และสร้างคำตอบแนะแนวทางแบบ Scaffolding และ Socratic Method  

 

 Output & Evaluation (ผลลัพธ์ที่ได้ออกมา และการวัดผล)  

System Output: * หน้าจอ TFT ขนาด 2.8 นิ้ว วาดใบหน้าและอารมณ์แบบกราฟิก 2 มิติ 

บอร์ด ESP32-S3 สั่งการเซอร์โวมอเตอร์ 5 ตัว ให้ขยับหัวและแขนสอดคล้องกับอารมณ์ (Body-Face Coordination) 

แสดงข้อความแนะนำจาก AI ผู้ช่วยสอนบนหน้าเว็บแอปพลิเคชัน 

Evaluation : ประเมินผลลัพธ์การเรียนรู้และการทำงานของระบบผ่าน 4 ตัวชี้วัด ได้แก่ 1) ความพึงพอใจและแรงจูงใจ (Likert Scale)  
2) อัตราการทำโจทย์สำเร็จ (Task Completion Rate)  
3) ปฏิสัมพันธ์กับ AI ผู้ช่วยสอน  
4) ต้นทุนและความคุ้มค่าเมื่อเทียบกับหุ่นยนต์ในตลาด
