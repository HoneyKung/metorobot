# ข้อเสนอโครงการ NSC 2026 — DRAFT v2

**Narrative หลัก:** ระบบซอฟต์แวร์ Full-Stack (เว็บ + Cloud AI + Embedded AI) ที่ทำให้การเรียนโค้ดจับต้องได้และมี AI ช่วยสอนแบบรายบุคคล

---

## 1. ปกโครงการ (1 หน้ากระดาษ)

- ชื่อไทย: **แพลตฟอร์มหุ่นยนต์นวัตกรรมเพื่อการศึกษาสำหรับการเขียนโค้ดแบบบล็อก**
- ชื่ออังกฤษ: **Innovative Educational Robotics Platform for Block-based Coding**
- หมวด: 12 — โปรแกรมเพื่อส่งเสริมทักษะการเรียนรู้ (ระดับนิสิต นักศึกษา)
- ทีมพัฒนา: [ชื่อหัวหน้า + สมาชิก]
- อาจารย์ที่ปรึกษา: [ชื่อ + ข้อความรับรอง]
- หัวหน้าสถาบัน: [ชื่อ + ตำแหน่ง + ข้อความรับรอง]
- สถาบัน: มหาวิทยาลัยเทคโนโลยีพระจอมเกล้าธนบุรี
- หมายเหตุ: ลายมืออิเล็กทรอนิกส์ได้ ต้องเป็นของจริงและเจ้าตัวยินยอม

## 2. สาระสำคัญและหลักการ

### 2.1 สาระสำคัญและคำสำคัญ (Keywords)

**สาระสำคัญ (ร่าง keyword):**
- ระบบซอฟต์แวร์แบบ Full-Stack 3 ชั้น (Web → Cloud → Embedded)
- ชั้น 1: เว็บ Block Coding IDE ทำงานผ่าน Browser ไม่ต้องติดตั้ง 8 หมวดคำสั่ง
- ชั้น 2: AI Tutor Engine บน Cloud วิเคราะห์โค้ดผู้เรียน real-time ชี้แนะตาม Scaffolding ไม่เฉลยคำตอบ
- ชั้น 3: Embedded AI บนไมโครคอนโทรลเลอร์ ตรวจจับใบหน้า จำแนกอารมณ์ แสดงอารมณ์ตอบสนอง
- ผู้เรียนเขียนโค้ดบนเว็บ → เห็นผลลัพธ์ผ่านอุปกรณ์จริง (Tangible Coding)
- อุปกรณ์มี "ชีวิต" ตอบสนองอารมณ์ผู้เรียน → กระตุ้นแรงจูงใจ

**คำสำคัญ:**
Block-based Coding, AI Tutoring System, Scaffolding, Edge AI, Full-Stack Software, Tangible Coding, Emotion Recognition, Educational Technology

---

### 2.2 หลักการและเหตุผล

**ปัญหาที่ 1 — เด็กเรียนโค้ดแล้วไม่เข้าใจ เพราะมันนามธรรมเกินไป:**
- เครื่องมือสอนโค้ดที่มีอยู่ (Scratch, Code.org) ผู้เรียนลากบล็อกแล้วเห็นแค่ตัวละครขยับบนจอ
- ไม่เข้าใจว่าโค้ดทำอะไรในโลกจริง ไม่เห็นความเชื่อมโยงกับสิ่งรอบตัว
- งานวิจัยยืนยันว่า Tangible Coding (เห็นผลจริง จับต้องได้) ช่วยให้เข้าใจตรรกะเร็วกว่า (Blikstein, 2013)

**ปัญหาที่ 2 — เด็กติดปัญหาแล้วไม่มีคนช่วยแบบ real-time:**
- ครู 1 คนดูเด็ก 40 คน → ไม่สามารถดูแลเด็กรายคนได้
- 74.1% เยาวชนไทยขาดทักษะดิจิทัล (World Bank & EEF, 2024)
- ช่องว่างบุคลากรดิจิทัล 70,000 ตำแหน่ง/ปี (depa, 2024)
- ขาดระบบ AI ที่ช่วยสอนเขียนโค้ดแบบ "ไม่เฉลย แต่ชี้แนะ" อย่างเป็นระบบ

**ปัญหาที่ 3 — เครื่องมือที่เชื่อมโค้ดกับของจริง ซอฟต์แวร์ไม่ฉลาด:**
- LEGO Mindstorms, mBot → มีฮาร์ดแวร์ให้สั่ง แต่ซอฟต์แวร์ไม่มี AI ช่วยสอน ไม่มีปฏิสัมพันธ์เชิงอารมณ์
- อุปกรณ์ทำตามคำสั่งอย่างเดียว ไม่มี "ชีวิต" ไม่กระตุ้นให้อยากเรียนต่อ
- งานวิจัยพบว่าหุ่นยนต์ที่แสดงอารมณ์ช่วยเพิ่มแรงจูงใจของผู้เรียนอย่างมีนัยสำคัญ (Belpaeme et al., 2018)

**ทางออก — ระบบซอฟต์แวร์ Full-Stack:**
- ไม่ใช่แค่เว็บ ไม่ใช่แค่หุ่นยนต์ แต่เป็น **ระบบซอฟต์แวร์ 3 ชั้น** ที่ทำงานร่วมกัน:
  1. **Web Block Coding IDE** → ผู้เรียนลากวางบล็อก ส่งคำสั่งไปอุปกรณ์จริงได้ทันที
  2. **AI Tutor Engine** → วิเคราะห์โค้ดผู้เรียน real-time ชี้แนะตามหลัก Scaffolding โดยไม่เฉลยคำตอบ
  3. **Embedded AI** → อุปกรณ์มี "ชีวิต" ตรวจจับใบหน้าผู้เรียน แสดงอารมณ์ตอบสนอง กระตุ้นแรงจูงใจ

---

### 2.3 วัตถุประสงค์

1. พัฒนา **เว็บแอปพลิเคชัน Block Coding IDE** ที่ทำงานผ่าน Browser ไม่ต้องติดตั้ง รองรับบล็อกคำสั่ง 8 หมวด สั่งงานอุปกรณ์ผ่าน Wi-Fi
2. พัฒนา **ระบบ AI ผู้ช่วยสอน (AI Tutor Engine)** บน Cloud ที่วิเคราะห์โค้ดผู้เรียนแบบ real-time ชี้แนะตามหลัก Scaffolding โดยไม่เฉลยคำตอบ
3. พัฒนา **ซอฟต์แวร์ Embedded AI** สำหรับตรวจจับใบหน้า จำแนกอารมณ์ และแสดงอารมณ์ตอบสนองบนอุปกรณ์ เพื่อกระตุ้นแรงจูงใจผู้เรียน
4. ออกแบบ **โปรโตคอลการสื่อสาร** ระหว่างเว็บ ↔ อุปกรณ์ ผ่าน Wi-Fi (HTTP)
5. ทดสอบระบบกับกลุ่มเป้าหมาย และประเมินผลการเรียนรู้และความพึงพอใจ

### 2.4 ปัญหาหรือประโยชน์

**ปัญหาที่ซอฟต์แวร์แก้:**
- เครื่องมือสอนโค้ดเดิม → นามธรรม ผู้เรียนไม่เห็นผลจริง
- ผู้เรียนติดปัญหา → ไม่มี AI ช่วย real-time ครูดูแลรายคนไม่ไหว
- เครื่องมือที่เชื่อมกับฮาร์ดแวร์ → ซอฟต์แวร์ไม่ฉลาด ไม่มี AI ไม่มีปฏิสัมพันธ์

**ประโยชน์:**
- **ผู้เรียน:** เข้าใจตรรกะโค้ดเร็วขึ้น เพราะเห็นผลเป็นรูปธรรม + มี AI ช่วยสอนรายคน
- **ครูผู้สอน:** AI Tutor ช่วยลดภาระ ดูแลเด็กรายคนได้โดยที่ครูไม่ต้องทำเอง
- **ผู้เรียนขาดแรงจูงใจ:** อุปกรณ์ที่มี "ชีวิต" ตอบสนองอารมณ์ → สร้างความผูกพัน อยากเรียนต่อ
- **Sustainable Learning:**
  - AI Tutor สอนได้ 24/7 ไม่เหนื่อย → ยั่งยืนกว่าพึ่งครูคนเดียว
  - เว็บเปิดได้ทุกอุปกรณ์ ไม่ต้องซื้อซอฟต์แวร์เฉพาะทาง
  - Open-source stack (Blockly, Flask, ESP-DL) → ต่อยอดและขยายผลได้
- **Sustainable Technology:**
  - Edge AI ประมวลผลบนชิป → ไม่ต้องพึ่ง Cloud ตลอด ประหยัดพลังงาน
  - อุปกรณ์โมดูลาร์ → อัปเดตซอฟต์แวร์ได้ ไม่ต้องเปลี่ยนทั้งตัว

## 3. รายละเอียดการพัฒนาและขอบเขต

### 3.1 เป้าหมายและขอบเขต

**เป้าหมาย:** พัฒนาระบบซอฟต์แวร์ต้นแบบ (Prototype) แบบ Full-Stack 3 ชั้น สำหรับการเรียนรู้เขียนโค้ดผ่านอุปกรณ์จับต้องได้ พร้อมทดสอบกับกลุ่มเป้าหมาย ภายใน 3 เดือน

**ขอบเขต:**
- ✅ เว็บ Block Coding IDE (Google Blockly)
- ✅ AI Tutor Engine บน Cloud (Gemini API + Flask)
- ✅ Embedded AI ตรวจจับใบหน้า/อารมณ์ (ESP-DL)
- ✅ เฟิร์มแวร์ควบคุมอุปกรณ์ (ESP32-S3)
- ✅ โปรโตคอลสื่อสาร เว็บ ↔ อุปกรณ์ (HTTP over Wi-Fi)
- ✅ อุปกรณ์ต้นแบบ 1 ชุด เพื่อทดสอบซอฟต์แวร์
- ❌ ไม่รวมแอปมือถือ (ทำงานผ่านเว็บเบราว์เซอร์)
- ❌ ไม่รวมการฝึกโมเดล AI ใหม่ (ใช้โมเดลสำเร็จรูป)

### 3.2 รายละเอียดเชิงลึก

#### เนื้อเรื่องย่อ (Story Board)

**ฉาก 1 — เปิดเว็บ เชื่อมต่ออุปกรณ์**
ผู้เรียนเปิดเว็บ Block Coding ผ่าน Browser ไม่ต้องติดตั้งอะไร เชื่อมต่อ Wi-Fi ของอุปกรณ์ สถานะแสดงบนเว็บแบบ real-time
[ภาพประกอบ: Mockup หน้าเว็บ + สถานะเชื่อมต่อ]

**ฉาก 2 — ลากวางบล็อก เขียนโค้ด**
ลากบล็อกจาก 8 หมวด ต่อเป็นลำดับ เช่น "เดินหน้า → เลี้ยวขวา → ยกแขน → แสดง Happy" จำลองผลบน Simulation Stage ก่อนส่งจริง
[ภาพประกอบ: Mockup การลากวางบล็อก]

**ฉาก 3 — ถาม AI เมื่อติดปัญหา**
กดปุ่ม "ถามพี่โรโบ" → ระบบส่งโค้ดไป Cloud → AI วิเคราะห์แล้วชี้แนะตาม Scaffolding โดยไม่เฉลย เช่น "สี่เหลี่ยมมีกี่มุม? ต้องเลี้ยวกี่ครั้ง? 🤔"
[ภาพประกอบ: Mockup หน้าจอ AI Chat]

**ฉาก 4 — กด Run → อุปกรณ์ทำตาม**
ระบบแปลงบล็อก → สตริงคำสั่ง → ส่ง HTTP ไปอุปกรณ์ → อุปกรณ์ทำตามทันที → ผู้เรียนเห็นผลโค้ดเป็นรูปธรรม (Tangible Coding)
[ภาพประกอบ: อุปกรณ์ทำตามคำสั่ง]

**ฉาก 5 — อุปกรณ์ตอบสนองอารมณ์**
Embedded AI ตรวจจับใบหน้าผู้เรียนบนชิป → จำแนกอารมณ์ → แสดงอารมณ์ตอบสนอง 8 สถานะ พร้อม Idle Behaviors ให้ดู "มีชีวิต" กระตุ้นแรงจูงใจ
[ภาพประกอบ: ดวงตา 8 อารมณ์บนจอ TFT]

#### เทคนิคหรือเทคโนโลยี

| ชั้น | เทคโนโลยี | หน้าที่ |
|---|---|---|
| **Web** | Google Blockly | Visual Programming IDE |
| **Web** | HTML/CSS/JS | Frontend ทำงานบน Browser |
| **Cloud** | Python/Flask + Gemini API | AI Tutor วิเคราะห์โค้ด + Scaffolding |
| **Embedded** | ESP-DL (Edge AI) | ตรวจจับใบหน้า + จำแนกอารมณ์บนชิป |
| **Embedded** | Arduino/ESP32 Firmware | ควบคุมมอเตอร์ + จอ TFT + Wi-Fi Server |
| **Communication** | HTTP over Wi-Fi (AP Mode) | เว็บ ↔ อุปกรณ์ ไม่ต้องพึ่งอินเทอร์เน็ต |

#### เครื่องมือที่ใช้

**ซอฟต์แวร์:** Google Blockly (Apache 2.0), Python/Flask (BSD), Google Gemini API, Arduino IDE (LGPL), ESP-DL (Apache 2.0), TFT_eSPI (FreeBSD), Fusion 360, Render.com

**ฮาร์ดแวร์ (อุปกรณ์ต้นแบบ):** ESP32-S3, ESP32-CAM, จอ TFT ST7789 2.8", เซอร์โว SG90 ×5, DC Motor ×2, L298N, IR Sensor ×2, โครงสร้าง 3D Print/MDF — รวม ~2,080 บาท

### 3.3 รายละเอียดทางเทคนิค (Software Specification)

#### Input/Output

| Input | Output |
|---|---|
| ผู้เรียนลากวางบล็อก → กด Run | อุปกรณ์เคลื่อนไหวตามคำสั่ง |
| ผู้เรียนพิมพ์ถาม AI | AI ตอบชี้แนะ 2-3 ประโยค (ไม่เฉลย) |
| กล้องจับภาพใบหน้าผู้เรียน | อุปกรณ์แสดงอารมณ์ตอบสนอง |

#### Functional Specification (4 โมดูล)

**1. Block Coding IDE (Web)** — ระบบลากวางบล็อก 8 หมวดคำสั่ง แปลงเป็นสตริงคำสั่งส่งไปอุปกรณ์ผ่าน HTTP มี Simulation Stage จำลองผลก่อนส่งจริง

**2. AI Tutor Engine (Cloud)** — รับโค้ดผู้เรียน + คำถาม ส่งไปวิเคราะห์ผ่าน Gemini API พร้อม System Prompt ที่ออกแบบตามหลัก Scaffolding ตรวจจับ Error อัตโนมัติ มี Conversation History ต่อ Session

**3. Communication Layer** — ESP32 สร้าง Wi-Fi เอง (AP Mode) รับคำสั่งจากเว็บผ่าน HTTP ไม่ต้องพึ่งอินเทอร์เน็ตของสถานศึกษา

**4. Embedded AI + Firmware** — ตรวจจับใบหน้าด้วย ESP-DL → จำแนกอารมณ์ → แสดงผลผ่านจอ TFT + ท่าทางเซอร์โว มี Idle Behaviors ให้ดูมีชีวิต

### 3.4 ขอบเขตและข้อจำกัด

1. ทำงานบน Browser เท่านั้น (ไม่รวมแอปมือถือ)
2. ใช้โมเดล AI สำเร็จรูป (ESP-DL, Gemini API) ไม่ฝึกโมเดลใหม่
3. AI Tutor ต้องใช้อินเทอร์เน็ต แต่การสั่งงานอุปกรณ์ไม่ต้องใช้
4. รองรับเฉพาะ Block-based Coding
5. ทดสอบ Pilot Study กลุ่มตัวอย่าง 10 คน
6. ไม่ครอบคลุมการศึกษาผลระยะยาว
