## 3. เพิ่มหัวข้อ Prior Arts / วิวัฒนาการ

### 📍 แทรกตรงไหน?

เพิ่มเป็น **หัวข้อ 2.3 วิวัฒนาการของเครื่องมือสอนเขียนโปรแกรม (Prior Arts & Evolution)** ต่อจาก 2.2 ก่อนเข้าบทที่ 3

### ✅ เนื้อหาที่ต้องเขียน

การเรียนการสอนเขียนโปรแกรมสำหรับผู้เริ่มต้นมีวิวัฒนาการมาอย่างต่อเนื่อง ตั้งแต่ยุคแรกที่ Seymour Papert พัฒนาภาษา Logo และหุ่นยนต์เต่า (Turtle Robot) ในทศวรรษ 1980 ซึ่งให้ผู้เรียนสั่งงานหุ่นยนต์ผ่านคำสั่งข้อความอย่างง่าย เช่น FORWARD, RIGHT (Papert, 1980) ต่อมาในทศวรรษ 2000 MIT Media Lab พัฒนา Scratch ซึ่งเป็นระบบเขียนโค้ดแบบบล็อกบนหน้าจอคอมพิวเตอร์ ช่วยแก้ปัญหาไวยากรณ์ที่ซับซ้อน แต่ยังจำกัดอยู่ในโลกดิจิทัลเท่านั้น ไม่มีวัตถุจับต้องได้ ในช่วงปี 2010 เป็นต้นมา หุ่นยนต์เพื่อการศึกษาสำเร็จรูปเช่น LEGO Mindstorms, mBot และ Edison Robot เริ่มเข้าสู่ตลาดอย่างแพร่หลาย แม้จะรองรับ Block Coding ได้ดี แต่ยังมีข้อจำกัดด้านราคาสูง (3,500–15,000 บาท) ไม่เปิดให้เรียนรู้โครงสร้างภายใน และไม่มีปฏิสัมพันธ์เชิงอารมณ์กับผู้เรียน ดังตารางสรุปวิวัฒนาการต่อไปนี้

### ตารางวิวัฒนาการ

| ยุค | เครื่องมือ | จุดเด่น | ข้อจำกัด |
|---|---|---|---|
| 1980s | Logo + Turtle Robot | เริ่มต้นแนวคิด tangible coding | คำสั่งข้อความ ซับซ้อนเกินเด็ก |
| 2000s | Scratch (MIT) | Block-based ไม่ต้องพิมพ์โค้ด | อยู่แค่บนจอ ไม่มีวัตถุจับต้อง |
| 2010s | LEGO Mindstorms / mBot / Edison | หุ่นยนต์จริง + Block Coding | ราคาสูง ไม่มีอารมณ์ ประกอบสำเร็จ |
| 2020s | Thymio (โอเพนซอร์ส) | ราคาถูกลง (~130 USD) + หลายระดับ | ไม่มีอารมณ์ ไม่มี AI ผู้ช่วยสอน |
| **2025** | **RoboMDT (งานวิจัยนี้)** | **DIY + Block Code + อารมณ์ TFT + AI ผู้ช่วย ราคา ≤2,000฿** | **อยู่ระหว่างพัฒนา** |

> [!IMPORTANT]
> 📊 **แทรกตารางที่ 2 ตรงนี้** ในหัวข้อ 2.3
>
> **คำอธิบายใต้ตาราง:** ตารางที่ 2 วิวัฒนาการของเครื่องมือสอนเขียนโปรแกรมสำหรับผู้เริ่มต้น ตั้งแต่ยุค Logo จนถึง RoboMDT

### ภาพประกอบสำหรับ Prior Arts

| ภาพ | เนื้อหา | วิธีหา |
|---|---|---|
| ภาพที่ 7 | ภาพหน้าจอ Scratch + Logo Turtle Robot | ค้นหา "Logo Turtle Robot" และ "Scratch MIT interface" จาก Google Images แล้วแคปมา |
| ภาพที่ 8 | ภาพหุ่นยนต์ LEGO Mindstorms / mBot / Edison เทียบกัน | แคปจากเว็บขายสินค้าหรือ Paper (Mondada et al., 2017) |

## 4. Diagram ของ ESP-DL Two-Stage Pipeline

### 📍 แทรกตรงไหน?

แทรกใน **หัวข้อ 2.2.1** หลังข้อความ "กระบวนการ 2 ขั้นตอน" (ประมาณบรรทัด 163)

### ✅ สิ่งที่ต้องวาด

Diagram แสดง Architecture ของโมเดล ESP-DL ที่ใช้ในงานนี้:

กล้อง (RGB565 240×240) → [MSR01: Face Detection] → Bounding Box → [MNP01: Landmark Detection] → 5 Keypoints (ตาซ้าย, ตาขวา, จมูก, ปากซ้าย, ปากขวา)

วาดเป็น Flowchart แนวนอน ใส่กล่องสี่เหลี่ยมแต่ละขั้นตอน พร้อมลูกศรชี้ทิศทาง

> [!IMPORTANT]
> 📊 **แทรกภาพที่ 9 ตรงนี้**
>
> **คำอธิบายใต้ภาพ:** ภาพที่ 9 แผนภาพ Two-Stage Pipeline ของ ESP-DL สำหรับการตรวจจับและวิเคราะห์ใบหน้าบนไมโครคอนโทรลเลอร์ ESP32-S3
> ดัดแปลงจาก Espressif Systems (2023)

## 5. Diagram ของ Emotion Processing Pipeline รวม

### 📍 แทรกตรงไหน?

แทรก **ท้ายหัวข้อ 2.2.6 (Body-Face Coordination)** เพราะเป็นจุดที่ปิดเรื่อง Emotion System ทั้งหมด

### ✅ สิ่งที่ต้องวาด

Diagram รวมทั้งระบบอารมณ์ตั้งแต่ต้นจนจบ:

5 Keypoints → [คำนวณ Ratio] → [EMA Smoothing α=0.5] → [เทียบ Adaptive Baseline] → [Hysteresis Check] → [Emotion State Machine] → ได้อารมณ์ใหม่ → [Body-Face Coordination] → วาดตา TFT + ขยับ Servo

> [!IMPORTANT]
> 📊 **แทรกภาพที่ 10 ตรงนี้**
>
> **คำอธิบายใต้ภาพ:** ภาพที่ 10 แผนภาพรวมกระบวนการประมวลผลอารมณ์ของหุ่นยนต์ RoboMDT ตั้งแต่การตรวจจับ Facial Landmarks จนถึงการแสดงออกทางใบหน้าและท่าทาง

> [!NOTE]
> ภาพนี้สำคัญมากเพราะอาจารย์จะเห็นภาพรวมทั้งระบบในที่เดียว แนะนำให้วาดเป็น Pipeline แนวนอนยาว หรือ Flowchart แนวตั้ง

## 7. Diagram ของ LLM API Architecture
