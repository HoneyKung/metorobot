# สรุปการเชื่อมต่อสำหรับอัปเดตวันศุกร์ — RoboMDT

> วันที่อัปเดต: 28 สิงหาคม 2569 — ตรวจผังขาและแก้ครั้งล่าสุด 27 สิงหาคม 2569 ดูบันทึกการแก้ไขท้ายไฟล์
>
> สถานะ: ต้นแบบสำหรับแสดงความคืบหน้า ใช้ XH-M401 แทน UBEC ชั่วคราว และยังไม่ติดฟิวส์ จึงต้องทดสอบภายใต้การดูแลและยังไม่ให้เด็กใช้งานเอง
>
> ⛔ **ก่อนจ่ายไฟครั้งแรกต้องแก้เฟิร์มแวร์ให้ตรง pin map ชุดนี้ก่อน** ดูข้อ 0 ในหัวข้อ 7 โค้ดเดิมใช้ GPIO25/26/27/32/33 เป็นสัญญาณ Servo ซึ่งตอนนี้คือขาสั่ง TB6612 ถ้าเปิดด้วยโค้ดเก่ามอเตอร์จะวิ่งมั่วทันที

## 1. ภาพรวมระบบไฟที่ต่อในวันศุกร์

```text
18650 จำนวน 2 ก้อนแบบอนุกรม 2S
                 │
                 ▼
             BMS 2S 16A
                 │ P+ / P-
                 ▼
          สวิตช์ KCD-105
                 │
                 ▼
          BUS+ / BUS- หลังสวิตช์
             ├── TB6612 VM/GND → มอเตอร์ซ้ายและขวา
             ├── LM2596 5.0V → ESP32 + TFT + XIAO
             └── XH-M401 5.0V → PCA9685 V+ → Servo 6 ตัว

GND ของ BMS, TB6612, LM2596, XH-M401, ESP32 และ PCA9685 ต่อร่วมกัน
```

ข้อกำหนดสำคัญ:

- XH-M401 จ่ายไฟให้ Servo เท่านั้น ไม่จ่ายไฟให้มอเตอร์
- LM2596 จ่ายไฟให้วงจร Logic เท่านั้น ไม่จ่ายไฟให้ Servo หรือมอเตอร์
- TB6612 รับไฟมอเตอร์จาก BUS หลังสวิตช์
- ห้ามต่อขั้วบวกเอาต์พุต XH-M401 และ LM2596 เข้าหากัน
- สายแบต มอเตอร์ และไฟ Servo ใช้สาย 18–20AWG ห้ามใช้ Dupont
- **GND ทุกเส้นรวมกันที่จุดเดียวคือ `BMS P-` แบบ star ground** ห้ามให้กระแสของ Servo หรือมอเตอร์ไหลย้อนผ่านสาย Dupont ของ ESP32
- **สาย Dupont เส้น `ESP32 GND → PCA9685 GND` เป็นสายอ้างอิงลอจิกเท่านั้น** กระแส Servo ต้องกลับทาง 20AWG ของ `XH-M401 OUT-` เสมอ ถ้าลืมเส้น 20AWG แล้วเหลือแต่ Dupont สาย Dupont จะร้อนและ ESP32 จะรีบูต

### เตรียมสายสำรอง UBEC ตั้งแต่ตอนบัดกรี

ตอนบัดกรีจุดกระจายไฟ ให้แยกสายสำรองออกมาสองเส้นแล้วหุ้มปลายเก็บไว้:

| สาย | จาก | หมายเหตุ |
|---|---|---|
| `UBEC+` | `BUS+` | 20AWG แดง หุ้มปลายไม่ให้แตะอะไร |
| `UBEC-` | `BUS-` | 20AWG ดำ หุ้มปลายไม่ให้แตะอะไร |

เมื่อได้ บั๊ก 5A ที่รับอินพุต 6.0–8.4V มาแล้วจะเปลี่ยนได้โดยไม่ต้องรื้อ BMS สวิตช์ หรือสายแบต แค่ย้ายไฟ Servo จาก XH-M401 ไป UBEC ตามขั้นตอนใน `แผนต่อระบบแบตเตอรี่แบบโมดูลาร์_RoboMDT.md`

### คาปาซิเตอร์ที่ต้องใส่ ห้ามข้าม

ถ้าไม่ใส่ ESP32 จะรีบูตทันทีที่เซอร์โวหลายตัวขยับพร้อมกัน เพราะแรงดันตกชั่วขณะ

| ตำแหน่ง | ค่า | ต่อยังไง |
|---|---|---|
| ใกล้ PCA9685 ที่สุด | `1000–2200µF 16V` | บวก → `V+`, ลบ → `GND` |
| ใกล้ TB6612 ที่สุด | `470–1000µF 16V` | บวก → `VM`, ลบ → `GND` |
| ใกล้ ESP32 ที่ราง Logic | `100–470µF 16V` | บวก → `5V`, ลบ → `GND` |
| คร่อมขั้วมอเตอร์แต่ละตัว | `0.1µF` เซรามิก | ไม่มีขั้ว ลดสัญญาณรบกวนที่กวน Encoder และ I2C |

ห้ามต่อคาปาซิเตอร์แบบอิเล็กโทรไลต์กลับขั้ว จะระเบิด

หมายเหตุ: คาปาซิเตอร์หลายตัวอาจทำให้มีกระแสกระชากช่วงสั้นตอนเปิดสวิตช์ แต่ไม่ควรฟันธงว่าต้องเกิดประกายหรือถือว่าประกายไฟเป็นอาการปกติ หากเห็นประกายซ้ำ มีความร้อน กลิ่นไหม้ หรือหน้าสัมผัสผิดปกติ ให้หยุดใช้งานทันที โดยเฉพาะต้นแบบระยะนี้ที่ยังไม่มีฟิวส์

## 3. TB6612 และ GPIO มอเตอร์

| TB6612 | ต่อกับ |
|---|---:|
| `PWMA` | ESP32 GPIO25 |
| `AIN1` | ESP32 GPIO26 |
| `AIN2` | ESP32 GPIO27 |
| `PWMB` | ESP32 GPIO32 |
| `BIN1` | ESP32 GPIO33 |
| `BIN2` | ESP32 GPIO14 |
| `STBY` | ESP32 3.3V |
| `VCC` | ESP32 3.3V |
| `VM` | BUS+ หลังสวิตช์ |
| `GND` | BUS-/GND ร่วม |
| `AO1/AO2` | มอเตอร์ซ้าย |
| `BO1/BO2` | มอเตอร์ขวา |

เริ่มทดสอบ PWM ต่ำและจำกัดไม่เกินประมาณ 180/255 ตอนแบตเต็มจนกว่าจะยืนยันมอเตอร์จริง

### สถานะมอเตอร์ตอนบูต — ปลอดภัยอยู่แล้ว ไม่ต้องเพิ่มอะไร

**`STBY` ผูก 3.3V ตายตัวใช้ได้ ถูกต้องแล้ว ไม่ต้องแกะออก**

TB6612FNG มี **ตัวต้านทาน pull-down ภายในตัวชิป 200kΩ** อยู่แล้วที่ขา `AIN1`, `AIN2`, `BIN1`, `BIN2`, `PWMA`, `PWMB` และ `STBY` ตาม datasheet ของ Toshiba ดังนั้นช่วงที่ ESP32 กำลังบูตและขา GPIO ยังลอยเป็น input อยู่ ขาอินพุตของ TB6612 จะถูกดึงลง LOW เอง

ตาม truth table เมื่อ `IN1 = L` และ `IN2 = L` มอเตอร์จะหยุด และเมื่อ `PWM = L` ก็หยุดเช่นกัน ตอนบูตทั้งสามเงื่อนไขเป็น LOW พร้อมกัน มอเตอร์จึงนิ่ง

แม้ `GPIO14` จะมีสัญญาณกระตุกตอนรีเซ็ตเพราะเป็นขากลุ่ม JTAG/SD ก็ยังไม่ทำให้มอเตอร์หมุน เพราะ `BIN2` กระตุกขึ้นเดี่ยวๆ ขณะที่ `BIN1` และ `PWMB` ยังเป็น LOW = ยังอยู่ในสถานะหยุด

#### ตัวต้านทาน 10kΩ 4 ตัว — เป็นของเสริม ไม่บังคับ

ถ้าจะใส่ `10kΩ` ลง GND ที่ `AIN1/AIN2/BIN1/BIN2` ก็ทำได้ ประโยชน์คือทำให้แรงดึงลงแรงกว่าเดิม 20 เท่า ทนสัญญาณรบกวนจากมอเตอร์ได้ดีขึ้น แต่**ไม่ใช่เงื่อนไขที่ขาดไม่ได้** และถ้า ESP32 ขับขาแบบ push-pull ออกมาจริง ตัวต้านทาน 10kΩ ก็หยุดไม่ได้อยู่ดี

**วิธีเช็คว่าต้องใส่ไหม:** ยกล้อพ้นพื้น เปิดสวิตช์ แล้วดูล้อ

| อาการ | ทำอะไร |
|---|---|
| ล้อนิ่งสนิท | ไม่ต้องใส่ |
| ล้อกระตุกหรือหมุน | ใส่ R 4 ตัว แล้วทดสอบซ้ำ |

## 4. PCA9685 และ Servo

| PCA9685 | ต่อกับ |
|---|---|
| `VCC` | ESP32 3.3V |
| `GND` Logic | ESP32 GND |
| `SDA` | ESP32 GPIO21 |
| `SCL` | ESP32 GPIO22 |
| `V+` | XH-M401 5.0V |
| `GND` Servo | XH-M401 OUT- / GND ร่วม |
| `OE` | **ต่อลง GND ด้วยสาย ห้ามปล่อยลอย** |

`OE` เป็นขา active-low ถ้าปล่อยลอยแล้วมันลอยขึ้นสูง เอาต์พุตทั้ง 16 ช่องจะถูกปิด = เซอร์โวไม่ขยับเลยทั้งตัว แล้วจะไล่หาสาเหตุยากมากตอนหน้างาน ต่อลง GND ไปเลยชัดเจนกว่า

ตอนเปิดเครื่อง PCA9685 ยังอยู่ในโหมด sleep และเอาต์พุตทุกช่องเป็น LOW อยู่แล้ว จึงไม่มีพัลส์ออกไปหาเซอร์โว **ช่วยลดโอกาสที่เซอร์โวจะกระตุก แต่ไม่ได้การันตี** เพราะตัวเซอร์โวเองก็อาจขยับตอนได้รับไฟครั้งแรกจากวงจรภายในของมันเอง ให้ถือว่าเซอร์โวอาจกระตุกตอนเปิดเสมอ และอย่าเอามือหรือกลไกไปขวางไว้

| ช่อง | Servo |
|---:|---|
| CH0 | MG996R แขนซ้ายข้อโคน |
| CH1 | MG90S แขนซ้ายข้อไหล่ |
| CH2 | MG996R แขนขวาข้อโคน |
| CH3 | MG90S แขนขวาข้อไหล่ |
| CH4 | SG90 คอหันซ้าย–ขวา |
| CH5 | SG90 ฐานหัวก้ม–เงย |

> ⚠️ **ช่องชุดนี้ถูกสลับใหม่ทั้ง 6 ช่อง** จากที่เคยเขียนไว้ในไฟล์เก่า ค่ามุมที่คาลิเบรตไว้ใน `รายชื่ออุปกรณ์หุ่นยนต์_RoboMDT.md` ผูกกับเลขช่องชุดเก่า
>
> **ห้ามคัดลอกค่ามุมตามเลขช่อง** ค่ามุมต้องเดินตามตัวเซอร์โว ไม่งั้นจะกลายเป็นเอาลิมิตของ MG90S ไปใส่ MG996R แล้วแขนจะดันจนกลไกเสียหาย ดูตารางแปลงในไฟล์นั้น

ก่อนใส่แขนหรือ Servo horn ให้สั่งทุกช่องไปตำแหน่งกึ่งกลางก่อน

## 5. จอ กล้อง Sensor และ Encoder

### TFT SPI

| TFT | ESP32 |
|---|---:|
| `SCK/CLK` | GPIO18 |
| `MOSI/SDI` | GPIO23 |
| `MISO/SDO` | **ไม่ต่อ** ดูเหตุผลข้างล่าง |
| `CS` | GPIO5 |
| `DC/RS` | GPIO2 |
| `RST` | GPIO4 |
| `LED/BL` | 3.3V ถ้าบอร์ดมีตัวต้านทานจำกัดกระแสมาแล้ว |
| `VCC/VIN` | ตัดสินให้จบก่อนวันศุกร์ ดูตารางข้างล่าง |
| `GND` | GND |

#### ไม่ต้องต่อ SDO/MISO

จอที่ใช้จริงตั้งเป็น **ST7789 240×320** ใน TFT_eSPI และโค้ดใช้ `setRotation(1)` เป็นแนวนอน 320×240 บอร์ดมีขาเรียงว่า `VCC GND CS RESET DC SDI SCK LED SDO | T_CLK T_CS T_DIN T_DO T_IRQ`

ระบบรอบนี้ใช้เฉพาะการแสดงผลแบบเขียนออกและยังไม่ใช้ touch จึงไม่ต้องอ่านข้อมูลกลับทาง `SDO/MISO` ให้ตั้ง `MISO = -1` และไม่ต่อสายนี้ เอกสารไม่อ้างแรงดันหรือพฤติกรรม high-Z ของ SDO จนกว่าจะวัดบอร์ดจริง

ตั้ง `MISO = -1` ใน TFT_eSPI แล้วไม่ต้องเสียบสายเส้นนี้ ได้ GPIO19 คืนเป็นขาสำรองด้วย

#### ขา VCC ของจอ — ต้องดูบอร์ดจริงก่อนจ่ายไฟ

บอร์ดแดงรุ่นนี้ไม่มี level shifter ขาสัญญาณจึงเป็น 3.3V ตรงกับ ESP32 พอดีอยู่แล้ว เหลือแค่ตัดสินขา `VCC`

**วิธีที่ไม่ต้องเดา:**

1. จ่าย **3.3V** ก่อนเสมอ ถ้าภาพขึ้นปกติ จบ ใช้ 3.3V ไปเลย ความเสี่ยงเป็นศูนย์
2. ถ้าไม่ติดหรือภาพซีด ค่อยมองหาเรกูเลเตอร์ตัวเล็ก 3 ขาแบบ SOT-23 ใกล้ขา VCC มักพิมพ์ว่า `662K` ถ้าเจอแปลว่าบอร์ดรับ 5V ได้ ค่อยเปลี่ยนเป็น 5V

ห้ามเริ่มที่ 5V เพราะถ้าบอร์ดไม่มีเรกูเลเตอร์คือพังทันที

#### ขา LED/BL

ถ้าไม่ต่อขานี้ จอจะมืดสนิทจนดูเหมือนจอเสีย ทั้งที่ SPI ทำงานปกติ เป็นอาการที่หลงกันบ่อยมากตอนหน้างาน ถ้าบอร์ดไม่มีตัวต้านทานจำกัดกระแสมาให้ ต้องใส่ `100Ω` อนุกรมก่อนเข้า 3.3V

### XIAO ESP32S3 Sense

| จาก | ไป |
|---|---|
| XIAO `TX` = ขา `D6` / `GPIO43` | ESP32 GPIO16 `RX2` |
| XIAO `5V` | LM2596 5.0V |
| XIAO `GND` | GND ร่วม |
| XIAO `3V3` | **ห้ามต่อ** |

ระบบนี้ส่งข้อมูลจากกล้องทางเดียว ไม่ต้องต่อ ESP32 TX กลับไป XIAO

ฝั่งเฟิร์มแวร์ของ XIAO ต้องพิมพ์ข้อมูลลง `Serial1` ไม่ใช่ `Serial` เพราะ `Serial` ของ XIAO ESP32S3 คือ USB CDC ซึ่งออกทางพอร์ต USB ไม่ได้ออกทางขา D6 ถ้าเขียนผิดตัวนี้ สายต่อถูกทุกเส้นแต่จะไม่มีข้อมูลออกมาเลย

### TCRT5000

| TCRT5000 | ESP32 |
|---|---:|
| DO ซ้าย | GPIO13 |
| DO ขวา | GPIO17 |
| VCC | 3.3V |
| GND | GND |

> ⚠️ **GPIO17 คือขา TX2 ค่าเริ่มต้นของ ESP32** ถ้าเฟิร์มแวร์เรียก `Serial2.begin(9600)` แบบไม่ระบุขา ESP32 จะยึด GPIO16 กับ GPIO17 เป็น RX2/TX2 ทันที แล้ว GPIO17 จะกลายเป็นขา output ของ UART ไปดันกับขา DO ของ LM393 บนบอร์ด TCRT5000 ผลคืออ่านค่าเพี้ยนและมีกระแสไหลย้อนเข้าขา output ทั้งสองฝั่ง
>
> **ต้องเขียนแบบนี้:** `Serial2.begin(9600, SERIAL_8N1, 16, -1);`
>
> **ทำไม `-1` ถึงได้ผล:** ในไลบรารี arduino-esp32 การเติมขาเริ่มต้นจะเกิดขึ้นเฉพาะเมื่อ **ทั้ง rxPin และ txPin ติดลบพร้อมกัน** เท่านั้น (`if (rxPin < 0 && txPin < 0)`) พอเราใส่ `16` ให้ RX เงื่อนไขนี้เป็นเท็จ ไลบรารีจึงไม่เติมค่า TX2 ให้ แล้วส่ง `-1` ต่อไปที่ไดรเวอร์ซึ่งแปลว่า "ไม่ต้องแตะขานี้" ผลคือสัญญาณ TX ของ UART2 ไม่เคยถูกโยงเข้า GPIO17 เลย
>
> ⚠️ **เงื่อนไขเดียวที่ยังพลาดได้:** ห้ามมี `Serial2.begin(...)` แบบไม่ระบุขาอยู่ที่ไหนในสเกตช์เลยแม้แต่บรรทัดเดียว เพราะถ้าเคยเรียกแบบนั้นมาก่อน GPIO17 จะถูกจองไปแล้ว และการเรียกครั้งหลังด้วย `-1` แปลว่า "ไม่ต้องแตะ" ซึ่งก็คือปล่อยให้ GPIO17 ติดค้างอยู่อย่างนั้น ให้ค้นทั้งโปรเจกต์ว่ามี `Serial2.begin` กี่ที่ ต้องระบุขาทุกที่

VCC ของ TCRT5000 ต้องเป็น 3.3V ไม่ใช่ 5V เพราะขา DO จะส่งระดับแรงดันเท่ากับ VCC ถ้าเลี้ยง 5V ขา DO จะเป็น 5V แล้วเกินพิกัดของ GPIO

### Encoder

| Encoder | ESP32 |
|---|---:|
| ซ้าย A | GPIO34 |
| ซ้าย B | GPIO35 |
| ขวา A | GPIO36 |
| ขวา B | GPIO39 |
| VCC | 3.3V |
| GND | GND |

GPIO34–39 ไม่มีตัวต้านทาน pull-up ภายใน ต้องตรวจบอร์ด Encoder จริงก่อนตัดสินใจเพิ่มตัวต้านทาน 4.7–10kΩ

> **อาการที่รู้กันของ ESP32 บน GPIO36 และ GPIO39:** สองขานี้จะมีพัลส์หลอกสั้นๆ ออกมาเวลาชิปใช้งาน ADC หรือ Hall sensor ถ้าใช้ `attachInterrupt` นับ Encoder ฝั่งขวาแล้วเจอค่าเดินเองทั้งที่ไม่ได้หมุนล้อ สาเหตุคือเรื่องนี้ ไม่ใช่สายหลวม ค่อยไปแก้ตอนทำ PID ไม่ต้องแก้วันศุกร์

## 7. ลำดับเปิดทดสอบ

### ⛔ ข้อ 0 — ห้ามจ่ายไฟด้วยเฟิร์มแวร์เก่าเด็ดขาด

สายชุดนี้เป็น pin map ใหม่ ถ้าเสียบสายครบแล้วเปิดเครื่องโดยที่ยังเป็นโค้ดเดิมจาก `Robo/Robo.ino` จะเกิดสามเรื่องนี้พร้อมกัน:

| ขา | โค้ดเก่าใช้เป็น | สายใหม่ต่ออะไร | ผลที่เกิด |
|---|---|---|---|
| GPIO25/26/27/32/33 | สัญญาณ Servo | ขาสั่ง TB6612 | **มอเตอร์วิ่งมั่วทันทีที่เปิด** |
| GPIO13 | `BIN1` เป็น output | ขา DO ของ TCRT5000 | ขา output สองตัวดันกัน |
| GPIO21/22 | `AIN1` และ `PWMA` | I2C ไป PCA9685 | I2C ใช้ไม่ได้ |

**ต้องแก้เฟิร์มแวร์ให้ครบชุดนี้ก่อนเสียบไฟครั้งแรก:**

```
Motor    PWMA=25  AIN1=26  AIN2=27  PWMB=32  BIN1=33  BIN2=14
I2C      Wire.begin(21, 22)              PCA9685 @ 0x40  ใช้ CH0-CH5
TFT      SCLK=18  MOSI=23  MISO=-1  CS=5  DC=2  RST=4
UART     Serial2.begin(9600, SERIAL_8N1, 16, -1)
TCRT     pinMode(13, INPUT);  pinMode(17, INPUT)
Encoder  34 / 35 / 36 / 39 เป็น INPUT   (ไม่มี pull-up ภายใน)
```

### ลำดับปกติ

1. ถอด ESP32, TFT, XIAO, มอเตอร์ และ Servo ออก
2. ตรวจขั้ว BMS และรอยบัดกรีทั้งหมด
3. เปิดสวิตช์ช่วงสั้นและวัด BUS
4. ตั้ง LM2596 เป็น 5.00V
5. ตั้ง XH-M401 เป็น 5.0V — **ถ้าบอร์ดมีสองโวลุ่ม ให้อ่านตัวอักษรบนบอร์ดก่อนว่าตัวไหนคือ CV ตัวไหนคือ CC ห้ามเดาและห้ามหมุนสุด** การหมุน current limit ขึ้นสุดเท่ากับปิดการป้องกันกระแสเกินทิ้ง ถ้ามี CC ให้ตั้งจากค่ากระแสที่วัดได้จริงตอนเซอร์โวทำงาน แล้วเผื่อขึ้นไปพอประมาณ
6. ปิดสวิตช์ แล้วต่อ ESP32 อย่างเดียว
7. ต่อ TFT และ XIAO ทีละตัว
8. ต่อ TB6612 โดยยังไม่ต่อมอเตอร์
9. ยกล้อพ้นพื้น แล้วต่อมอเตอร์ทีละตัว
10. ต่อ PCA9685 โดยยังไม่เสียบ Servo
11. เสียบและทดสอบ Servo ทีละตัวโดยยังไม่ใส่กลไก
12. ติดกลไกหลังยืนยันตำแหน่งกึ่งกลางและทิศทางแล้ว

หยุดทันทีเมื่อสายหรือบอร์ดร้อนผิดปกติ แรงดันตกต่ำกว่า 4.8V, ESP32 รีบูต, Servo สั่นหรือครางค้าง หรือมีกลิ่นไหม้

### ⚠️ เสียบ USB = ปิดสวิตช์หลัก

ตอนสาธิตจะเสียบ USB ดู Serial ไปด้วย แต่ ESP32 DevKit หลายรุ่นต่อไฟ 5V จาก USB เข้าขา `V5` ตรงๆ โดยไม่มีไดโอดกั้น ทำให้ 5V จาก LM2596 กับ 5V จาก USB ดันกัน

กฎง่ายๆ: **เสียบ USB เมื่อไหร่ ปิดสวิตช์แบตเมื่อนั้น** ยกเว้นได้วัดยืนยันแล้วว่าบอร์ดมีไดโอดกั้น

### ⚠️ XH-M401 บนแบต 2S อยู่นอกสเปกของชิป — ถือเป็นของทดลองเท่านั้น

ชิป **XL4016** ที่อยู่ใน XH-M401 ระบุช่วงอินพุตในดาต้าชีตว่า **8V ถึง 40V** แต่แพ็ก 2S ของเราอยู่ที่ 6.0–8.4V แปลว่า**เกือบทั้งช่วงการใช้งานอยู่ต่ำกว่าขั้นต่ำของชิป** มีแค่ตอนชาร์จเต็มใหม่ๆ เท่านั้นที่ถึง 8V

ผลจริงคือมันมักจะทำงานได้ แต่**ไม่มีการรับประกันว่าจะรักษา 5V ไว้ได้** โดยเฉพาะจังหวะที่เซอร์โวกินกระแสกระชาก

| BUS | สถานะ |
|---|---|
| 8.4V ชาร์จเต็ม | อยู่ในสเปก ใช้ได้ |
| 8.0V | ขอบล่างของสเปกพอดี |
| 7.4V | **นอกสเปกแล้ว** มักยังทำงานได้แต่ไม่รับประกัน |
| ต่ำกว่า 7.0V | หยุดใช้งาน ชาร์จทันที |

**เงื่อนไขการใช้งานวันศุกร์:**

- ชาร์จให้เต็มใกล้ 8.4V ก่อนสาธิตทุกครั้ง
- วัดเอาต์พุตของ XH-M401 **ขณะเซอร์โวกำลังเคลื่อนจริง** ไม่ใช่วัดตอนอยู่เฉยๆ
- หลีกเลี่ยงการยกของหนัก (กลุ่ม A ขยับพร้อมกันได้ตามออกแบบ)
- หยุดทันทีถ้ารางต่ำกว่า 4.8V, เซอร์โวสั่น หรือ ESP32 รีบูต

อย่ารอให้ BMS ตัด เพราะ BMS ตัดที่ประมาณ 5.0–5.6V ซึ่งราง 5V พังไปนานแล้ว

**นี่คือเหตุผลที่ บั๊ก 5A ที่รับอินพุต 6.0–8.4V เป็นของที่ต้องหามาเปลี่ยนจริงๆ ไม่ใช่แค่ของอัปเกรด** ดูตัวเลือกและราคาในหัวข้อ "บั๊กที่ใช้เปลี่ยน XH-M401" ท้ายไฟล์ ส่วน XH-M401 เป็นการยืมของที่มีอยู่มาใช้ชั่วคราวเพื่อให้ทันวันศุกร์เท่านั้น

ตอนทดสอบเซอร์โว 6 ตัวพร้อมกัน ให้วัดสองจุดพร้อมกันคือ `BUS` และราง Servo จะเห็นชัดว่าตัวไหนตกก่อน
## ผังขาจริง ESP32 DevKit 38-pin ที่ยืนยันแล้ว

> มองด้านอุปกรณ์ของบอร์ดและวางพอร์ต USB ไว้ด้านบน อ่านแต่ละฝั่งจากบนลงล่าง

```text
ฝั่งซ้าย                                  ฝั่งขวา
CLK     ห้ามใช้ — Flash                  V5      รับ Logic 5V จาก LM2596
SD0     ห้ามใช้ — Flash                  CMD     ห้ามใช้ — Flash
SD1     ห้ามใช้ — Flash                  SD3     ห้ามใช้ — Flash
G15     สำรอง/Strapping                  SD2     ห้ามใช้ — Flash
G2      TFT DC                           G13     TCRT5000 ซ้าย
G0      ห้ามใช้ — BOOT                   GND     GND ร่วม
G4      TFT RST                          G12     สำรอง/Strapping
G16     RX2 รับข้อมูลจาก XIAO TX         G14     TB6612 BIN2
G17     TCRT5000 ขวา                     G27     TB6612 AIN2
G5      TFT CS                           G26     TB6612 AIN1
G18     TFT SCK                          G25     TB6612 PWMA
G19     ว่าง (เดิม TFT MISO)             G33     TB6612 BIN1
GND     GND ร่วม                         G32     TB6612 PWMB
G21     I2C SDA                          G35     Encoder ซ้าย B
RXD     สำรอง Serial0/USB                G34     Encoder ซ้าย A
TXD     สำรอง Serial0/USB                SN/VN   GPIO39 Encoder ขวา B
G22     I2C SCL                          SP/VP   GPIO36 Encoder ขวา A
G23     TFT MOSI                         EN      Reset/Enable ไม่ใช่ GPIO
GND     GND ร่วม                         3V3     Logic 3.3V + TB6612 STBY
```

จุดที่ต้องจำ:

- `SP/VP` คือ GPIO36 และ `SN/VN` คือ GPIO39 ทั้งคู่เป็นขารับสัญญาณอย่างเดียว
- `CLK/SD0/SD1/CMD/SD2/SD3` ต่อกับ Flash ภายใน ห้ามนำไปใช้
- `EN` เป็นขา Enable/Reset ไม่ใช่ GPIO
- `RXD/TXD` คือ Serial0 ที่ใช้กับ USB/ข้อความ Debug จึงยังไม่ใช้กับกล้อง
- XIAO ส่งข้อมูลเข้าขา `G16` ไม่ใช่ขาที่พิมพ์ว่า `RXD`
- ขา `G2/G5/G12/G15` เกี่ยวข้องกับการบูต ห้ามให้โมดูลภายนอกบังคับระดับผิดขณะเปิดเครื่อง
- **ถ้าแฟลชผ่าน USB ไม่เข้า ให้ถอดสาย TFT `DC` ที่ `G2` ก่อนแล้วแฟลชใหม่** เพราะ G2 ต้องเป็น LOW ตอนเข้าโหมดดาวน์โหลด ถ้าบอร์ดจอมี pull-up บนขา DC จะดันให้ G2 สูงจนแฟลชไม่ได้
- ขาที่ยังว่างจริงมีแค่ `G12` กับ `G15` และ `G19` ที่ได้คืนมาจากการไม่ต่อ MISO

### ยังไม่มีขาสำหรับวัดแรงดันแบต

ขา ADC1 ทั้ง 6 ขา (32, 33, 34, 35, 36, 39) ถูกใช้หมดแล้วกับมอเตอร์และ Encoder ส่วน ADC2 ใช้พร้อม WiFi ไม่ได้ แปลว่าเฟิร์มแวร์ไม่มีทางรู้เลยว่าแบตใกล้หมด ซึ่งสำคัญสำหรับหุ่นที่จะให้เด็กใช้

วันศุกร์ยังไม่ต้องทำ ใช้มัลติมิเตอร์วัดเอาตามเส้นหยุดใช้งานในหัวข้อ 7 ไปก่อน แต่ควรตัดสินใจตั้งแต่ตอนนี้เพราะเป็นเรื่อง pin map ที่แก้ยากหลังบัดกรีเสร็จ ทางที่สะอาดที่สุดคือใช้ **ADS1115 บน I2C เส้นเดิม** ซึ่งไม่กิน GPIO เพิ่มเลยแม้แต่ขาเดียว

| 7 | ระบุ `OE` ของ PCA9685 ให้ต่อลง GND | เดิมเขียนว่าเว้นไว้ได้ ถ้าปล่อยลอยแล้วลอยขึ้นสูง เอาต์พุตทั้ง 16 ช่องจะถูกปิด เซอร์โวไม่ขยับเลยทั้งตัวและไล่หาสาเหตุยากมาก |

| 9 | เปลี่ยนราง Servo จาก 5.0-5.2V เป็น 5.0V และเพิ่มเส้นหยุดที่ BUS 7.0V | buck ทั้งสองตัวต้องการ headroom 1.5–2V ที่กระแสสูง แพ็ก 2S จึงมีช่วงใช้งานแคบกว่าที่เขียนไว้ว่า 6.0–8.4V ตั้ง 5.0V ซื้อ headroom เพิ่ม 0.2V และต้องหยุดก่อน BMS ตัดมาก |
| 10 | เพิ่มกฎเสียบ USB ต้องปิดสวิตช์ | DevKit หลายรุ่นต่อ 5V จาก USB เข้าขา V5 ตรงๆ ไม่มีไดโอดกั้น จะดันกับเอาต์พุตของ LM2596 ตอนสาธิตซึ่งต้องเปิด Serial ดูไปด้วย |
| 11 | เพิ่มคำเตือนใต้ตารางช่อง PCA9685 ว่าช่องถูกสลับใหม่ทั้ง 6 ช่อง | ตอนไล่ตรวจเจอว่าในโฟลเดอร์มีผังช่องเซอร์โว **4 ชุดที่ไม่ตรงกัน** ผังในไฟล์นี้ถูกยึดเป็นหลัก และไปแก้ไฟล์อื่นให้ตรงตามแล้ว แต่ `รายชื่ออุปกรณ์หุ่นยนต์` มีค่ามุมคาลิเบรตผูกกับเลขช่องชุดเก่าอยู่ ถ้าเฟิร์มแวร์คัดลอกค่ามุมตามเลขช่องจะเอาลิมิตของ MG90S ไปใส่ MG996R แล้วแขนดันจนกลไกเสียหาย |

### ผังช่องเซอร์โวที่เคยขัดกันในโฟลเดอร์ — ยึดตามไฟล์นี้แล้ว

| เซอร์โว | ช่องชุดเก่า | **ช่องที่ใช้จริง** |
|---|:---:|:---:|
| MG996R แขนซ้าย | CH2 | **CH0** |
| MG90S ซ้าย | CH4 | **CH1** |
| MG996R แขนขวา | CH3 | **CH2** |
| MG90S ขวา | CH5 | **CH3** |
| SG90 หัวหันซ้าย-ขวา | CH0 | **CH4** |
| SG90 คอก้ม-เงย | CH1 | **CH5** |

ไฟล์ที่แก้ให้ตรงแล้ว: `ตารางการเชื่อมต่อและบัดกรี`, `ปัญหาฮาร์ดแวร์`, `แผนต่อระบบแบตเตอรี่แบบโมดูลาร์`, `รายชื่ออุปกรณ์หุ่นยนต์`

ไฟล์ที่ยกเลิกแล้วและไม่ได้แก้: `แผนเสียบสายไฟ_RoboMDT.md` ยกเลิกทั้งไฟล์ตามข้อตกลงข้อ 2 ใน `ปัญหาฮาร์ดแวร์`

เพิ่มเป็นบันทึกไว้ ยังไม่ต้องทำวันศุกร์:

- ยังไม่มีขาเหลือสำหรับวัดแรงดันแบต ADC1 ถูกใช้หมด 6 ขา เสนอ ADS1115 บน I2C เส้นเดิม
- GPIO36/39 มีพัลส์หลอกตามอาการที่รู้กันของ ESP32 จะกวน Encoder ฝั่งขวาตอนทำ PID
- GPIO2 ที่ต่อ TFT `DC` อาจทำให้แฟลชผ่าน USB ไม่เข้า ถ้าเจอให้ถอดสายเส้นนี้ก่อน
- KCD-105 เป็นสวิตช์เรต AC เมื่อสวิตช์ไฟ DC หลายแอมป์บวกกับคาปาซิเตอร์เกิน 3000µF หน้าสัมผัสจะสึกเร็ว

## บันทึกการแก้ไขรอบสอง — 27 สิงหาคม 2569 (หลังตรวจทานซ้ำ)

รอบนี้ตรวจข้อโต้แย้งจากการรีวิวอีกชุดโดยเปิดดาต้าชีตและซอร์สโค้ดจริง ผลคือแก้ 4 จุด และยืนยันไม่แก้ 1 จุด

| # | เรื่อง | ผลตรวจ | แก้เป็นอะไร |
|:-:|---|---|---|
| 1 | **Baud rate ของกล้อง** | ผิดจริง | `FullCam.ino` บรรทัด 127 ใช้ `Serial1.begin(9600, ...)` ไม่ใช่ 115200 แก้เป็น **9600** ทุกไฟล์แล้ว ถ้าตั้งผิดข้างเดียวจะได้ตัวอักษรขยะ |
| 2 | **TB6612 ต้องใส่ R pull-down 4 ตัวไหม** | ผมเขียนเกินจริง | datasheet ของ Toshiba ระบุว่าชิปมี **pull-down ภายใน 200kΩ** ที่ขาอินพุตทุกขารวมถึง STBY อยู่แล้ว สถานะตอนบูตจึงนิ่งเองโดยไม่ต้องเพิ่มอะไร ลดสถานะ R 4 ตัวจาก "ต้องใส่" เป็น **ของเสริม** และยืนยันว่า `STBY → 3.3V` ที่บัดกรีไว้แล้วถูกต้อง ไม่ต้องแกะ |
| 3 | **XH-M401 บนแบต 2S** | ผมประเมินหลวมไป | ดาต้าชีต XLSEMI ระบุ XL4016 รับอินพุต **8V–40V** แต่แพ็ก 2S คือ 6.0–8.4V = อยู่นอกสเปกเกือบทั้งช่วง ไม่ใช่แค่ "คาบเส้นที่ 7.0V" อย่างที่เขียนไว้รอบแรก เปลี่ยนเป็นระบุชัดว่าเป็น**ของทดลอง ไม่รับประกัน** ต้องชาร์จเต็มก่อนสาธิตและวัดใต้โหลดจริง |
| 4 | **current limit ของ XH-M401** | คำแนะนำเดิมอันตราย | ตัดคำว่า "หมุนขึ้นสุด" ออก เพราะเท่ากับปิดการป้องกันกระแสเกินทิ้ง และห้ามเดาว่าปุ่มที่สองคือ CC เปลี่ยนเป็นให้อ่านตัวอักษรบนบอร์ดแล้วตั้งจากค่ากระแสที่วัดได้จริง |
| 5 | **`Serial2.begin(9600, SERIAL_8N1, 16, -1)` ใช้ได้ไหม** | **ยืนยันว่าถูกแล้ว ไม่แก้** | มีข้อโต้แย้งว่า `-1` แปลว่า "คงขาเดิม" จึงยังเสี่ยงยึด GPIO17 ตรวจซอร์สของ arduino-esp32 แล้วพบว่าการเติมขาเริ่มต้นเกิดเฉพาะเมื่อ **rxPin และ txPin ติดลบพร้อมกัน** (`if (rxPin < 0 && txPin < 0)`) พอใส่ `16` ให้ RX เงื่อนไขเป็นเท็จ ไลบรารีไม่เติม TX2 ให้ สัญญาณ TX จึงไม่เคยถูกโยงเข้า GPIO17 — แต่เพิ่มคำเตือนไว้แล้วว่าห้ามมี `Serial2.begin` แบบไม่ระบุขาอยู่ที่ไหนในสเกตช์เลย |

ข้อเสนอที่ **ไม่รับ**: การย้าย UART TX ไป `GPIO19` หรือย้าย `STBY` ไป `GPIO19` เพราะ GPIO19 เป็นขาสำรองที่ได้คืนมาจากการไม่ต่อ SDO และยังเป็นขา `T_DO` ของ XPT2046 ถ้าวันหลังต่อ touch จะกลายเป็น output ชนกัน อีกทั้งสองข้อเสนอนี้แย่ง GPIO19 กันเอง

**เรื่องจอ:** ยืนยันจาก TFT_eSPI ที่คอมไพล์ใช้งานจริงว่าเป็น ST7789 240×320 และโค้ดหมุนเป็น 320×240 ข้อสรุปยังเหมือนเดิมคือไม่ต่อ `SDO/MISO` เพราะระบบแสดงผลอย่างเดียวไม่ต้องอ่านกลับและ touch ยังไม่ใช้งาน ส่วนคำอธิบายเดิมที่อ้าง ILI9341, แรงดัน SDO หรือ high-Z ถูกยกเลิกเพราะไม่ตรงกับ driver ปัจจุบัน

## บั๊กที่ใช้เปลี่ยน XH-M401 — ไม่ต้องเป็น UBEC

ปัญหาของ XH-M401 มีข้อเดียวคือชิป **XL4016 มีพื้นอินพุตขั้นต่ำ 8V** ซึ่งสูงกว่าแบต 2S ของเรา บั๊กราคาถูกเกือบทุกตัวไม่มีปัญหานี้ จึงไม่จำเป็นต้องเป็น UBEC

| โมดูล | ช่วงอินพุต | ครอบคลุม 2S (6.0–8.4V)? |
|---|---|---|
| XL4016 (XH-M401) | **8–40V** | ❌ ตัวปัญหา |
| LM2596 | 4.5–40V | ✅ |
| XL4005 | 5–32V | ✅ |
| MP1584 | 4.5–28V | ✅ |

**สเปกที่ต้องการจริง:** อินพุตครอบคลุม 6.0–8.4V · เอาต์พุตปรับได้ถึง 5.0V · จ่ายได้ **≥3A ต่อเนื่อง**

ที่มาของ 3A คือกลุ่ม A ขยับพร้อมกัน (MG996R ×2 ≈ 1.2–2.0A + MG90S ×2 ≈ 0.3–0.5A + SG90 ×2 ค้างตำแหน่ง ≈ 0.2A = **~1.7–2.7A**)

| ตัวเลือก | กระแส | ราคาโดยประมาณ | ความเห็น |
|---|---:|---:|---|
| **XL4005 5A** | 5A | ~60–90฿ | **แนะนำ** หัวเหลือจริงสำหรับกลุ่ม A + มอเตอร์ |
| LM2596 ตัวที่สอง | ~2A จริง | ~30–45฿ | ถูกสุด แต่ตึงสำหรับกลุ่ม A ระวังความร้อน |
| UBEC 3A | 3A | ~150–250฿ | ทนโหลดกระชากดีกว่า ถ้าอยากได้ความชัวร์ |
| ~~UBEC 10A~~ | 10A | ~1,000฿+ | **ไม่ต้องซื้อ เกินความจำเป็นเท่าตัว** |

ไม่ว่าเลือกตัวไหน คาปาซิเตอร์ `1000–2200µF` ที่ `V+` ของ PCA9685 ยังต้องใส่ เพราะตัวรับกระแสกระชากจริงคือคาปาซิเตอร์ ไม่ใช่บั๊ก

### รูปแบบการสั่งงานจริง

| กลุ่ม | เซอร์โว | สั่งพร้อมกัน |
|---|---|---|
| **A** | MG996R ×2 (CH0, CH2) + MG90S ×2 (CH1, CH3) | ✅ พร้อมกันได้ และวิ่งพร้อมมอเตอร์ล้อได้ |
| **B** | SG90 คอ/หัว (CH4, CH5) | แยกจังหวะจากกลุ่ม A |

ตอนวัดแรงดันใต้โหลด ต้องวัดขณะ **กลุ่ม A ขยับพร้อมล้อหมุน** ไม่ใช่ตอนอยู่เฉยๆ
