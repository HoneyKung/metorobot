## สถานะก่อนเริ่ม — อ่านให้จบก่อนแตะโค้ด

`RoboPCA9685/RoboPCA9685.ino` **ถูกแก้เป็น pin map ชุดใหม่ไปแล้ว** และคอมไพล์ผ่าน
ไม่ใช่ไฟล์โปรโตไทป์เก่าอีกต่อไป สิ่งที่แก้ไปแล้วมีดังนี้ อย่าทำซ้ำ

| แก้ไปแล้ว | รายละเอียด |
|---|---|
| ชั้นมอเตอร์ | ลบโค้ด L298N เดิม (`MOTOR_IN1..IN4` + `analogWrite(200)`) ทิ้งทั้งบล็อก แทนด้วยชั้น TB6612 จาก `MotorTest_TB6612.ino` |
| `driveMotor()` | speed -255..255 บีบใน 60..180 เพดาน 180 เป็น clamp จริงในโค้ด |
| `motorInit()` | ถูกเรียกเป็นบรรทัดแรกของ `setup()` ตั้งขาเป็น LOW ก่อนอย่างอื่น ล้อจึงไม่กระตุกตอนบูต |
| `goForward/Backward/Left/Right` `stopMotors` | คงชื่อเดิม เปลี่ยนไส้ในให้เรียก `driveMotor()` |
| กล้อง | `CAM_RX_PIN = 16`, `CAM_TX_PIN = -1`, `USE_CAMERA` เป็น 1 |
| จอ | `User_Setup.h` ของ TFT_eSPI แก้เป็น MOSI23 CS5 DC2 RST4 แล้ว ปิด `TFT_BL`/`TFT_BACKLIGHT_ON` ทิ้ง |
| สำรอง | `RoboPCA9685.ino.bak-20260906` และ `User_Setup.h.bak-20260906` |

`USE_MOTOR` ยังเป็น **0** โดยตั้งใจ จะเปลี่ยนเป็น 1 ก็ต่อเมื่อรัน `MotorTest_TB6612.ino`
กับมอเตอร์จริงผ่านแล้วเท่านั้น

## Pin map ที่ล็อกแล้ว — ห้ามเปลี่ยน

มาจาก "ข้อ 0" หัวข้อ 16 ของ `ตารางการเชื่อมต่อและบัดกรี_RoboMDT.md` (สเปกวันศุกร์)

```text
Motor    PWMA=26  AIN1=27  AIN2=14   (ซ้าย, สาย M03/M04/M05)
Motor    PWMB=25  BIN1=32  BIN2=33   (ขวา, สาย M06/M07/M08)
         VCC และ STBY จั๊มรวมกันไป 3V3 ไม่กินขา GPIO
I2C      Wire.begin(21, 22)              PCA9685 @ 0x40  ใช้ CH0-CH5
TFT      SCLK=18  MOSI=23  MISO=-1  CS=5  DC=2  RST=4
UART     Serial2.begin(9600, SERIAL_8N1, 16, -1)
TCRT     pinMode(13, INPUT);  pinMode(17, INPUT)
Encoder  ซ้าย A=34 B=35 / ขวา A=36 B=39  INPUT  (ไม่มี pull-up ภายใน)
         บอร์ด Encoder มี pull-up ในตัวแล้ว ไม่ต้องเพิ่มภายนอก เลี้ยงขา 02 ด้วย 3V3 ห้ามใช้ 5V
```

> ⚠️ **`Serial2.begin` ต้องระบุขาทุกครั้ง ทุกจุดในสเกตช์**
> ถ้ามี `Serial2.begin(9600)` แบบไม่ระบุขาอยู่ที่ไหนแม้บรรทัดเดียว ESP32 จะยึด
> GPIO17 เป็น TX2 ไปดันกับขา DO ของ TCRT5000 แล้วเซนเซอร์ตัวขวาใช้ไม่ได้เลย
> การเรียกครั้งหลังด้วย `-1` ไม่ได้ปลดขาที่ถูกยึดไปแล้ว

ขาที่ **ห้ามแตะ**: GPIO6-11 (แฟลชภายใน), GPIO0/12/15 (strapping)
GPIO2 เป็น DC ของจอและเป็นขา strapping — ถ้าแฟลชไม่เข้าให้ถอดสายเส้นนี้ชั่วคราว

## งานที่เหลือให้ทำ

### 1. คำสั่งมอเตอร์ต้องเลิกบล็อก

ตอนนี้จุดเรียกยังเป็นแบบเดิม:

```cpp
case 'w': goForward(); delay(1000); stopMotors(); break;
```

`delay(1000)` ค้าง `loop()` ไว้หนึ่งวินาทีเต็ม ระหว่างนั้น `server.handleClient()`
ไม่ทำงานและตัวอ่าน UART กล้องตกหล่น ให้เปลี่ยนเป็นนาฬิกาหยุดอัตโนมัติแทน:

- `unsigned long motorStopAt` เป็น 0 เมื่อไม่มีคำสั่งค้าง
- `goForward()` และเพื่อน ๆ ตั้ง `motorStopAt = millis() + MOTOR_TIMEOUT_MS`
- ต้นทาง `loop()` เช็ค ถ้าเลยเวลาแล้วให้เรียก `stopMotors()` และเคลียร์เป็น 0
- `#define MOTOR_TIMEOUT_MS 1000` ให้พฤติกรรมเท่าเดิมแต่ไม่บล็อก
- แก้ทั้งสองที่: `executeCommandString()` และ `loop()` (ค้นหา `motorRunFor(1000); stopMotors();` 8 จุด)

> ℹ️ ตอนนี้ `delay(1000)` ถูกเปลี่ยนเป็น `motorRunFor(1000)` ไปแล้ว ซึ่งเรียก
> `encoderTick()` ระหว่างรอเพื่อตรวจล้อติดขัด **แต่ยังบล็อก `server.handleClient()` อยู่**
> งานข้อนี้จึงยังต้องทำ ตอนรื้อเป็นนาฬิกาไม่บล็อก **ต้องคง `encoderTick()` ใน `loop()` ไว้**
> ไม่งั้นการหยุดอัตโนมัติเมื่อล้อไม่หมุนจะหายไป

### 1.5 Encoder — เพิ่มให้แล้ว อย่าทำซ้ำ

| เพิ่มไปแล้ว | รายละเอียด |
|---|---|
| `USE_ENCODER` | สวิตช์ใหม่ ตั้งเป็น 0 ไว้ก่อน เปิดเมื่อต่อสายและใส่ pull-up ครบ |
| ISR quadrature x4 | ทั้งสองข้าง ใช้ `portMUX` กันค่าเพี้ยน |
| `ENC_R_QUADRATURE` | ตั้ง 0 แล้วฝั่งขวานับขอบเดียว ไว้ใช้ตอน GPIO36/39 มีพัลส์หลอก |
| `encoderTick()` | คำนวณ RPM ทุก 200 ms แบบไม่บล็อก + หยุดเองเมื่อสั่งเดินแล้วล้อไม่หมุน 600 ms |
| ปุ่ม E / Z / N | อ่านค่า / ล้างตัวนับ / ตรวจพัลส์หลอก 10 วิ |
| `/state` | เพิ่ม `encL` `encR` `rpmL` `rpmR` ต่อท้ายแล้ว |
| ค้างอยู่ | `ENC_CPR_L`/`ENC_CPR_R` ยังเป็นค่าอ้างอิง 4680 ต้องสอบเทียบด้วย `EncoderMotorTest_TT.ino` ปุ่ม k |

### 2. กล้องหลุดต้องรู้ตัว

ตัวอ่านกล้องใน `loop()` ใช้ได้ตามเดิม เพิ่มแค่:

- จำ `millis()` ครั้งล่าสุดที่รับตัวอักษรได้จาก `Serial2`
- ถ้าเกิน 5 วินาทีแล้วยังไม่มีอะไรเข้า ให้ถือว่ากล้องหลุด
- แสดงสถานะให้เห็น ไม่ใช่เงียบไปเฉย ๆ — จุดเล็ก ๆ มุมจอหรือข้อความบน Serial ก็พอ
- เมื่อรับข้อมูลได้อีกครั้งต้องกลับเป็นปกติเอง

### 3. เพิ่มฟิลด์ใน `/state`

**ห้ามลบหรือเปลี่ยนชื่อฟิลด์เดิม** เพราะ `robot-sim.js` ฝั่งเว็บอ่านชื่อพวกนี้อยู่
เพิ่มต่อท้ายได้สองตัว:

- `cam` — ตัวอักษรล่าสุดที่รับจากกล้อง หรือ `"-"` ถ้ายังไม่เคยได้
- `mot` — 1 เมื่อมีคำสั่งมอเตอร์ค้างอยู่ 0 เมื่อหยุด

(`encL` `encR` `rpmL` `rpmR` เพิ่มให้แล้ว ไม่ต้องทำซ้ำ)

### 4. เปิด `USE_MOTOR` พร้อมค่าที่วัดมาจริง

หลังรัน `MotorTest_TB6612.ino` เสร็จ ให้เติมค่าที่วัดได้ลงไป แล้วค่อยเปลี่ยนเป็น 1

```
PWM ต่ำสุดที่ล้อออกตัวจริง:  ซ้าย ____   ขวา ____
ต้อง invert ไหม:            ซ้าย ____   ขวา ____
PWM_DRIVE ที่จะใช้เดินเดโม:  ____   (ค่าออกตัวที่สูงกว่า + 20 แต่ไม่เกิน 180)
```

ถ้ายังไม่มีตัวเลข ให้คง `USE_MOTOR 0` ไว้ **ห้ามเดาค่าแล้วเปิดเอง**

## ข้อห้าม

1. ห้ามใช้ `delay()` เกิน 50 ms ใน `loop()`
2. ห้ามเปลี่ยน pin map ที่ล็อกไว้ข้างบน
3. ห้ามแก้ `User_Setup.h` ซ้ำ แก้ให้ตรงแล้ว
4. ห้ามเพิ่มเพดาน PWM เกิน 180 ไม่ว่าด้วยเหตุผลใด
5. ห้ามใส่โค้ดเซอร์โวมือ PID หรือการวัดแรงดันแบตในรอบนี้
   **ส่วน Encoder เพิ่มเข้าไปแล้ว (7 ก.ย.) ห้ามลบทิ้ง** — ดูรายการข้างล่าง
6. ห้ามรื้อฟังก์ชัน `drawEyes_*()` `drawEyesForEmotion()` `doBodyGesture()` และระบบอารมณ์
7. ห้ามฝัง SSID/รหัส WiFi ใหม่ ใช้ค่าที่มีอยู่เดิม
8. ห้ามเปิด `USE_MOTOR 1` เองโดยไม่มีผลทดสอบ

## สิ่งที่ยังไม่ยืนยัน — ห้ามเดาแทน

- แรงดันที่ขา VCC ของจอ ST7789 ยังไม่ยืนยันว่ารับ 5V ได้ ให้เริ่มที่ 3.3V
- วงจร LED/BL บนโมดูลจอยังไม่ยืนยันว่ามีตัวจำกัดกระแสในตัวหรือไม่
- **แรงดันเลี้ยง Encoder ที่ขา 02 ของหัว PH2.0-6P ยังไม่ยืนยัน** ค่า 6V ในตารางสเปก
  เป็นแรงดันมอเตอร์ ไม่ใช่ของ Encoder ให้ต่อ 3.3V ตามผังและห้ามเปลี่ยนไป 5V เอง
  เพราะ pull-up บนบอร์ดจะดัน A/B ขึ้นเป็น 5V ซึ่งเข้า GPIO34/35/36/39 ตรง ๆ ไม่ได้
  ยืนยันได้ด้วยการเลี้ยง 3.3V แล้วหมุนล้อ ถ้า A/B สลับ 0/1 ได้แปลว่าใช้ 3.3V ได้จริง
- ค่าฟิวส์สุดท้ายยังไม่กำหนด เพราะยังไม่ทราบสเปกสายจริง

ถ้างานที่สั่งไปแตะข้อใดข้อหนึ่ง ให้เขียนคอมเมนต์ `// ยังไม่ยืนยัน:` กำกับไว้
