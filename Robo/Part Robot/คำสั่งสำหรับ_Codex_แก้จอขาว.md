# คำสั่งสำหรับ Codex — จอขาว หลังแก้เรื่องล้อและเริ่มทำหน้าซิงค์กับเว็บ

ปรับปรุง 7 ก.ย. 2569 · ไฟล์หลัก `RoboPCA9685/RoboPCA9685.ino`

---

## อาการ

จอ ST7789 320×240 **ขาวล้วน ไม่ขึ้นรูปตาเลย** แม้กดสั่งอารมณ์จากเว็บ
เฟิร์มแวร์ส่วนอื่นทำงานครบ มอเตอร์เดินตามคำสั่ง Encoder นับได้ เว็บตอบปกติ

## ไทม์ไลน์ — ข้อสำคัญที่สุดของงานนี้

| ลำดับ | สิ่งที่แก้ | ผลกับจอ |
|---|---|---|
| 1 | ย้ายผังขาจอเป็น SCLK18 MOSI5 CS4 DC17 RST16 + ย้าย CAM RX ไป 23 | **จอยังขึ้นหน้าปกติ** |
| 2 | แก้ล้อไม่เดิน (รีเซ็ตนาฬิกาตรวจล้อติดขัด) + ถอน `server.handleClient()` ออกจาก `motorRunFor()` | เริ่มพัง |
| 3 | ตัดหางที่ล้างจอสองครั้งท้ายคำสั่ง + เพิ่ม `lastDrawnEyes` และฟิลด์ `face` ใน `/state` | ขาวล้วน |

**ผู้ใช้ยืนยันว่าขั้นที่ 1 จอยังขึ้นปกติ** จึงตัดเรื่องสายและ `User_Setup.h` ออกได้
ปัญหาเกิดจากการแก้โค้ดในขั้นที่ 2 หรือ 3 **ห้ามเสียเวลาไปไล่สายหรือสลับ RGB/INVERSION**

## งานแรกที่ต้องทำก่อนอย่างอื่น — หาว่าพังที่ขั้นไหน

มีไฟล์สำรองครบทุกจุด ให้ไล่ทีละตัว อย่าเดา

| ไฟล์สำรอง | คือสถานะไหน | คาดว่าจอ |
|---|---|---|
| `RoboPCA9685.ino.bak-20260907c` | หลังย้ายขาจอ **ก่อน**แก้ล้อและก่อนแตะโค้ดวาดตา | ควรขึ้นปกติ |
| `RoboPCA9685.ino.bak-20260907d` | หลังแก้ล้อ **ก่อน**แตะโค้ดวาดตา | ? |
| `RoboPCA9685.ino.bak-20260907e` | ก่อนแก้จอรอบล่าสุด | ? |
| `RoboPCA9685.ino` | ปัจจุบัน | ขาวล้วน |

แฟลช `c` ก่อน ถ้าจอขึ้น แปลว่าตัวการอยู่ในส่วนต่างระหว่าง `c` กับ `d`
ถ้า `c` ก็ขาว แปลว่าเป็นเรื่องขั้นที่ 1 ซึ่งขัดกับที่ผู้ใช้เห็น ให้รายงานกลับทันที

**diff ระหว่าง c → d มีแค่สามอย่าง**

1. ย้ายประกาศ `encLastMoveMsL/R` จาก `static` ในบล็อกฟังก์ชัน ขึ้นมาเป็นตัวแปรทั่วไปในบล็อก `#if USE_ENCODER`
2. `driveMotor()` รีเซ็ต `encLastMoveMsL/R` เมื่อเริ่มสั่งเดิน
3. ถอด `server.handleClient()` ออกจาก `motorRunFor()`

**diff ระหว่าง d → e (คือของปัจจุบัน) มีสามอย่าง**

1. ท้าย `executeCommandString()` เปลี่ยนจาก `drawEyes_Happy(); delay(1500); drawEyes_Normal();`
   เป็น `drawEyesForEmotion(currentEmotion);`
2. เพิ่มบรรทัด `lastDrawnEyes = 'X';` เป็นบรรทัดแรกของฟังก์ชัน `drawEyes_*` 11 ตัว
   **สังเกต: บรรทัดนี้อยู่นอก `#if USE_TFT` ส่วนโค้ดวาดอยู่ใน `#if USE_TFT`**
3. `/state` เพิ่มฟิลด์ `face`

## หลักฐานที่วัดมาแล้ว อย่าไล่ซ้ำ

ยิง `http://MDTrobot.local/state` 10 ครั้งติดจากเบราว์เซอร์จริง

```json
{"emo":"N","head":90,"blink":0,"busy":0,"up":15240,
 "encL":0,"encR":0,"rpmL":0.0,"rpmR":0.0,"face":"N"}
```

- `up` เดินหน้าตลอด ไม่ย้อนกลับเลย → **ไม่ได้รีบูต ไม่ใช่ไฟตก**
- `blink` สลับ 0/1 → `updateBlink()` ทำงาน → **โค้ดเรียกฟังก์ชันวาดตาอยู่จริง**
- `/run?cmd=h;` ตอบ 200 OK
- `TFT_RGB_ORDER TFT_BGR` และ `TFT_INVERSION_OFF` เหมือนกับไฟล์ตอนจอขึ้นปกติทุกตัวอักษร
- `drawEyesForEmotion()` มี `case 'N': default:` จึงวาด Normal เสมอ ไม่มีทางตกกรณี

## เบาะแสสำคัญ — สีขาวที่เห็นคือ `fillScreen(TFT_WHITE)` ของโค้ดเราเอง

ทุกฟังก์ชัน `drawEyes_*` เริ่มด้วย `tft.fillScreen(TFT_WHITE);` แล้วค่อยวาดวงรีทับ

```cpp
void drawEyes_Normal() {
  lastDrawnEyes = 'N';
#if USE_TFT
  tft.fillScreen(TFT_WHITE);          // ← สีขาวที่เห็นมาจากบรรทัดนี้
  tft.fillEllipse(EYE_L_X, EYE_Y, 55, 60, TFT_BLACK);
  ...
#endif
}
```

**ถ้าเป็นปัญหาสายหรือ SPI ตาย จอจะขึ้นขยะหรือไม่เปลี่ยนเลย ไม่ใช่ขาวสะอาด**
การที่ได้ขาวสะอาดแปลว่า `fillScreen()` ส่งถึงจอสำเร็จ

จึงเหลือสองความเป็นไปได้ **ให้พิสูจน์ว่าอันไหนจริง อย่าเดา**

**ก. `fillEllipse()` ไม่ถึงจอ ทั้งที่ `fillScreen()` ถึง**
สองอันนี้ใช้เส้นทางต่างกัน `fillScreen` เป็นการเขียนบล็อกยาวรวดเดียว
ส่วน `fillEllipse` สลับ DC ไปมาถี่มากเพื่อตั้งหน้าต่างทีละเส้น
ถ้าขา DC (GPIO17) สัมผัสไม่ดีหรือถูกแย่ง จะได้ผลแบบนี้พอดี คือพื้นมาแต่รูปไม่มา

**ข. มีอะไรล้างจอขาวทับทันทีหลังวาดเสร็จ**
`updateBlink()` วาดเต็มจอ 4-6 เฟรมต่อการกะพริบหนึ่งครั้ง ทุก 1.5-5 วินาที
`updateGlance()` อีก 2 เฟรมทุก 4-10 วินาที `updateSigh()` อีก 2 เฟรมทุก 15-30 วินาที
การเติมเต็มจอ 320×240 ที่ 16 บิต บน SPI 27MHz ใช้เวลาราว **45-60 ms ต่อครั้ง**
ซึ่ง **นานกว่าช่วงเวลาระหว่างเฟรมที่ตั้งไว้ (60-120 ms) จนเกือบชนกัน**
ถ้าลูปช้าลงกว่าเดิม (ตอนนี้มี WiFi + เว็บ + ISR ของ Encoder สี่ตัว) ลำดับกะพริบจะยืดออก
จนจอใช้เวลาส่วนใหญ่อยู่ในสภาพ "กำลังเติมขาว"

## สิ่งที่ต้องส่งมอบ

### 1. เครื่องมือวัดก่อน อย่าเพิ่งแก้

เพิ่มปุ่ม `F` บน Serial ในไฟล์ตัวเต็ม (ห้ามสร้างสเกตช์แยก) ที่ทำสามอย่าง

- **หยุดพฤติกรรม idle ทั้งหมดชั่วคราว** (blink glance sigh headLook) แล้ววาด `drawEyes_Normal()`
  ครั้งเดียวแล้วค้างไว้ 10 วินาที ไม่ให้อะไรมาวาดทับ
  ถ้าตาขึ้นชัดและค้างอยู่ → ตอบข้อ **ข** คือโดนวาดทับ
  ถ้ายังขาว → ตอบข้อ **ก** คือ `fillEllipse` ไม่ถึงจอ
- วัดเวลาจริงของ `tft.fillScreen()` และ `drawEyes_Normal()` ด้วย `micros()` แล้วพิมพ์ออก Serial
- พิมพ์ `tft.width()`, `tft.height()`, `ESP.getChipModel()`, `ESP.getPsramSize()`

### 2. นับจำนวนครั้งที่วาดจอ

เพิ่มตัวนับ `eyeDrawCount` บวกหนึ่งทุกครั้งที่ `fillScreen(TFT_WHITE)` ถูกเรียกในกลุ่มวาดตา
แล้วส่งออกทาง `/state` เป็นฟิลด์ใหม่ `draws` ผู้ใช้จะดูได้ทันทีว่าวาดถี่ผิดปกติหรือไม่
ถ้าเลขวิ่งเป็นสิบครั้งต่อวินาทีทั้งที่ไม่ได้สั่งอะไร แปลว่าเจอต้นเหตุแล้ว

### 3. เมื่อรู้คำตอบแล้วจึงแก้

- ถ้าเป็นข้อ **ข** → เลิกใช้ `fillScreen()` ในทุกฟังก์ชันวาดตา
  ให้วาดทับเฉพาะบริเวณตาสองวง หรือใช้ `TFT_eSprite` วาดในหน่วยความจำแล้ว push ทีเดียว
  นี่คือทางแก้ที่ถูกต้องระยะยาว ลดเวลาวาดลงหลายเท่าและกำจัดการกะพริบทั้งหมด
- ถ้าเป็นข้อ **ก** → รายงานกลับพร้อมตัวเลขที่วัดได้ อย่าไปแก้สายเอง

### 4. แก้ข้อความที่ค้างของเก่าและทำให้คนอ่านไม่หลง

- `setup()` พิมพ์ `CAM Serial2 RX=16` แต่โค้ดจริงคือ `CAM_RX_PIN = 23`
- คอมเมนต์บรรทัด 69 ยังเขียนผังเก่า `SCLK18 MOSI23 CS5 DC2 RST4`

## ข้อห้าม

1. **ห้ามไล่สายหรือแก้ `User_Setup.h`** ผู้ใช้ยืนยันแล้วว่าผังนี้จอเคยขึ้นปกติ
2. **ห้ามสลับ `TFT_RGB_ORDER` หรือ `TFT_INVERSION_*`** เทียบกับไฟล์ตอนใช้งานได้แล้ว เหมือนกันเป๊ะ
3. **ห้ามแตะผังขามอเตอร์ Encoder I2C WiFi**
   `PWMA=26 AIN1=27 AIN2=14 | PWMB=25 BIN1=32 BIN2=33 | Encoder 34/35/36/39 | SDA=21 SCL=22`
4. **ห้ามลบระบบหยุดอัตโนมัติเมื่อล้อไม่หมุน** และห้ามลบการรีเซ็ตนาฬิกาใน `driveMotor()`
   เพิ่งแก้บั๊กนี้ไป ถ้าลบล้อจะกลับไปกระตุกแล้วดับ
5. **ห้ามเรียก `server.handleClient()` ซ้อนใน `motorRunFor()`** เคยใส่แล้วถอนเพราะเรียกซ้อนไม่ได้
6. **ห้ามเรียก `Serial2.begin` แบบไม่ระบุขา** ค่าเริ่มต้น TX2 คือ GPIO17 ซึ่งเป็นขา DC ของจอ
7. ห้ามใส่ `delay()` เกิน 50 ms ในเส้นทาง `loop()` ปกติ
8. ห้ามเพิ่มเพดาน PWM เกิน 180 · ห้ามฝัง SSID/รหัส WiFi ใหม่
9. คอมเมนต์เป็นภาษาไทยแบบเดียวกับไฟล์เดิม
