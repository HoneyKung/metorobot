## 1. โครงสร้างแขนที่ถูกต้อง ⚠️ อย่าอนุมานผิด

```
        [ หัว ]
          │
    ┌─────┴─────┐  ← ลำตัว
    │           │
 [MG996R]   [MG996R]   ← อยู่ที่ "ต้นแขน" ในลำตัว (ชั้นก่อนหัวไหล่)
    │           │        ยกทั้งโครงแขน + MG90S + ของ
    ▼           ▼
 [MG90S]    [MG90S]   ← อยู่ที่ "หัวไหล่" เป็นข้อที่ 2
    │           │        หมุนแขนเข้าหากันเพื่อหนีบ
    ╲         ╱
     ╲ ของ  ╱          ← หนีบด้วยผิวแขน 2 ข้างบีบเข้าหากัน
      ╲___╱
```

| ข้อ | เซอร์โว | ตำแหน่ง | หน้าที่ | ต้องยกอะไร |
|:--:|---------|---------|---------|-----------|
| 1 | **MG996R** ×2 | ต้นแขน (ในลำตัว ชั้นก่อนหัวไหล่) | ยกแขนขึ้น-ลง | **โครงแขนทั้งชุด + MG90S + ของ** |
| 2 | **MG90S** ×2 | หัวไหล่ | หมุนเข้าหากันเพื่อหนีบ | แรงบีบ |

**สิ่งที่ต้องรู้:**
- แขน **ยื่นออกนอกลำตัว** อยู่แล้ว → ของที่จับอยู่ห่างตัวเสมอ **ไม่มีเคส "ยกแนบตัว"**
- MG90S **ไม่ได้อยู่ปลายแขน** อยู่ที่หัวไหล่

## 3. ปัญหาการต่อ เรียงตามความรุนแรง

### 3.1 ❌ สายไฟหาย 2 เส้น — ต่อครบตามแผนแล้วอุปกรณ์ยังไม่ติด

| อุปกรณ์ | สายในแผน | ขาดอะไร |
|---------|---------|---------|
| **จอ TFT** | 7 เส้น: CS / RST / DC / MOSI / SCLK / BL / GND | ❌ **ไม่มี VCC** → จอไม่ติด |
| **XIAO ESP32S3** | 3 เส้น: Signal / ว่าง / GND | ❌ **ไม่มีไฟ 5V** → กล้องไม่ทำงาน |

ชั้น 5 มีอุปกรณ์ 3 ตัว แต่มีไฟเลี้ยงแค่ตัวเดียว (MPR121 ที่ได้จากสาย I2C)

> ถ้าใช้บอร์ดขยาย (หัวข้อ 4) ปัญหานี้หายไปเอง เพราะทุกหัวเสียบมี V/G มาให้อยู่แล้ว

### 3.2 ❌ Encoder อ่านไม่ได้ถ้าไม่ใส่ตัวต้านทาน

D34 / D35 / D36 / **D39** เป็น input-only **ไม่มี internal pull-up** ส่วน Hall encoder หลายรุ่นเป็น open-collector

→ **ต้องใส่ 10kΩ pull-up ไป 3.3V** ที่ขาสัญญาณ encoder ฝั่ง ESP32 ไม่งั้นอ่านได้ 0 ตลอด

⚠️ **ยังต้องเช็ค:** ถ้าชิปบนแผ่น encoder เป็น **A3144 / AH3144E** จะต้องการไฟขั้นต่ำ **4.5V** → ใช้ 3.3V ไม่ทำงาน ต้องเลี้ยง 5V แล้วต่อตัวแบ่งแรงดันลงมา 3.3V ก่อนเข้า ESP32

### 3.3 ❌ LM2596 จ่ายไฟไม่พอ

ราง 5V ต้องเลี้ยง **เซอร์โว 6 ตัว + ESP32 + จอ + XIAO** พร้อมกัน

| สถานการณ์ | กระแส | LM2596 (3A) |
|-----------|------:|-------------|
| อยู่เฉย ๆ | ~0.5 A | ✅ |
| เซอร์โวขยับ 1–2 ตัว | ~1.5 A | ✅ |
| เซอร์โวขยับพร้อมกัน 6 ตัว | ~2.5–3.5 A | ⚠️ คาบเส้น |
| **MG996R ยกแขนพร้อมของหนัก** | **~5–7 A** | ❌ ตกแน่นอน |

**ผล:** ราง 5V ตก → ESP32 brown-out reset → หุ่นรีบูตกลางทาง

#### ✅ ทางแก้ที่แนะนำ — แยก 2 ราง

```
                      ┌─► [XH-M401 5.0V ชั่วคราว] ──► PCA9685 V+ ──► เซอร์โว 6 ตัว
BMS ──► สวิตช์ ──► BUS ───┤  (ฟิวส์เพิ่มหลังวันศุกร์)
                      ├─► [LM2596 3A ตัวเดิม] ──► ESP32 + จอ + XIAO   (~0.5A สบาย)
                      │
                      └─► 7.4V ตรง ──► TB6612 VM ──► มอเตอร์
```

**สถานะวันศุกร์:** ใช้ LM2596 ตัวเดิมเลี้ยง Logic และใช้ XH-M401 ที่มีอยู่เลี้ยง Servo ชั่วคราว หลังวันศุกร์จึงเปลี่ยน XH-M401 เป็น บั๊ก 5A ที่รับอินพุต 6.0–8.4V

| รุ่น | หน้าที่ | สถานะ |
|------|---------|--------|
| **XH-M401** | Servo rail 5.0V | ⚠️ ชิป XL4016 สเปกอินพุต 8–40V แต่แพ็ก 2S คือ 6.0–8.4V = **อยู่นอกสเปกเกือบทั้งช่วง** ใช้ชั่วคราวได้แต่ไม่รับประกัน ต้องชาร์จเต็มก่อนสาธิตและทดสอบโหลดเบา |
| **บั๊ก 5A ที่รับอินพุต 6.0–8.4V** | Servo rail 5–6V | ทางถาวรหลังหาซื้อได้ |
| LM2596 | Logic rail 5V | ใช้ต่อสำหรับ ESP32/TFT/XIAO |
| LM2596 สองตัวขนาน | ไม่ใช้ | ห้ามขนานเอาต์พุตโดยไม่มีวงจร current sharing |

**สำคัญ:** GND ของทั้ง 2 ราง **ต้องต่อร่วมกันที่จุดเดียว** (star ground ที่ BMS P−)

**ข้อดีที่แท้จริงของการแยกราง:** ต่อให้เซอร์โวดึงไฟจนราง servo ตก **ESP32 ก็ไม่รีบูต** เพราะคนละ converter

### 3.4 ⚠️ สาย Dupont รับกระแสไม่พอ 3 เส้น

สาย Dupont 26AWG รับได้ ~1–2A

| สาย | กระแส | ใช้ Dupont ได้ไหม |
|-----|------:|-------------------|
| 5V → PCA9685 (ไฟเซอร์โว) | 3–5 A | ❌ **ห้าม** |
| 7.4V → TB6612 VM | 1.5 A | ❌ คาบเส้น |
| TB6612 → มอเตอร์ | 1.5 A | ❌ คาบเส้น |
| สายสัญญาณทุกเส้น | < 20 mA | ✅ ได้หมด |

→ **3 เส้นนี้ใช้ขั้วต่อแบบขันน็อต (Screw Terminal / Terminal Block)** ใช้ไขควงขัน **ไม่ต้องบัดกรี** เด็กทำได้

### 3.5 ⚠️ Dupont หลุด + เสียบกลับด้านได้

หุ่นตีนตะขาบสั่นแรงกว่าหุ่นล้อมาก และ Dupont ไม่มีตัวล็อก

| ปัญหา | วิธีแก้ (ไม่ต้องบัดกรี) |
|-------|------------------------|
| **หลุดจากแรงสั่น** | หยอด**กาวร้อน**ที่หัวปลั๊กหลังเสียบ (แกะออกด้วยแอลกอฮอล์ได้) + รัด**เคเบิลไทร์**ห่างหัวปลั๊ก ~2cm + ทำจุดยึดสายบนตัวถัง 3D print |
| **เสียบกลับด้าน = ไหม้** | ใช้ **สาย Dupont สำเร็จรูปแบบ housing หลายขา** (2/3/4/6/8 ขา ซื้อสำเร็จ ไม่ต้องย้ำเอง) + **เว้นขาว่าง 1 ขา** เป็น key + ให้แต่ละกลุ่มมีจำนวนขาไม่ซ้ำกัน |
| **เสียบผิดตำแหน่ง** | พิมพ์ตัวถัง 3D ให้มีป้ายชื่อจุดเสียบ + ทำสีขา 1 |

### 3.6 ✅ สวิตช์ KCD-105 — ใช้ได้ ไม่ต้องเปลี่ยน

KCD-105 พิกัด ~6A/125VAC ที่ **7.4V DC อาร์กแทบไม่เกิด** (อาร์ก DC จะเป็นปัญหาจริงที่ >12V)

→ **ใช้ได้เลย** แค่ให้ **ปิดสวิตช์ตอนหุ่นนิ่ง** ไม่ใช่ตอนเซอร์โวกำลังขยับ จะยืดอายุหน้าสัมผัสมาก

### 3.7 ✅ MPR121 — เก็บไว้ ถูกแล้ว

**ผมประเมินผิดรอบก่อนว่า "ทับซ้อนกับ touch ในตัว ESP32"** — ไม่จริง

**ทับซ้อนยังไง:** ทั้งคู่ใช้หลักการเดียวกัน (capacitive sensing — วัดความจุที่เปลี่ยนเมื่อนิ้วเข้าใกล้) ESP32 มีวงจรนี้ในตัว 10 ช่อง

**แต่ในโปรเจกต์นี้ ช่อง touch ของ ESP32 ถูกใช้ไปกับงานอื่นเกือบหมด:**

> ตารางนี้อัปเดตเป็น pin map ชุดวันศุกร์แล้ว ของเดิมอิงผัง v3 เก่า

| ช่อง | GPIO | สถานะใน pin map ชุดวันศุกร์ |
|:----:|:----:|-------|
| T0 | D4 | ใช้แล้ว — TFT_RST |
| T2 | D2 | ใช้แล้ว — TFT_DC |
| T3 | D15 | **ว่าง** (ถ้าใช้ touch XPT2046 จะโดนจองเป็น T_CS) |
| T4 | D13 | ใช้แล้ว — TCRT5000 ซ้าย |
| T5 | D12 | **ว่าง** |
| T6 | D14 | ใช้แล้ว — TB6612 BIN2 |
| T7 | D27 | ใช้แล้ว — TB6612 AIN2 |
| T8 | D33 | ใช้แล้ว — TB6612 BIN1 |
| T9 | D32 | ใช้แล้ว — TB6612 PWMB |

→ **เหลือ 2 ช่อง (D15, D12)** และทั้งคู่เป็นขา strapping ที่ห้ามให้แผ่นสัมผัสไปดันระดับตอนบูต

**ทำ "ลูบ" ได้ไหม:** "ลูบ" = ไล่นิ้วผ่านหลายจุดตามลำดับ → ต้องมี **แผ่นอย่างน้อย 3 แผ่นเรียงกัน** แล้วดูว่าแตะ A→B→C (ลูบไป) หรือ C→B→A (ลูบกลับ)

- **ESP32 touch เหลือ 2 ช่อง → ยังไม่ถึง 3 ทำได้แค่ "แตะ" ทำ "ลูบ" ไม่ได้**
- **MPR121 มี 12 ช่อง → ทำ "ลูบ" ได้จริง**

**เทียบเรื่องการต่อ (ตาม scope นี้):**

| | ESP32 touch | MPR121 |
|---|---|---|
| ช่องที่ใช้ได้จริง | **2** | **12** |
| ทำ "ลูบ" ได้ | ❌ | ✅ |
| กิน GPIO เพิ่ม | 1 ขา ต่อ 1 แผ่น | **0 ขา** (ใช้ I2C ที่มีอยู่) |
| การเดินสาย | สายเดี่ยวจาก D15/D12 (ชั้น 3) ขึ้นหัว (ชั้น 5) ~20cm **ไม่มี shield → รับ noise ค่าแกว่ง** | จิ้ม I2C 4 เส้นต่อจากตัวก่อนหน้า |
| auto-calibration ตามความชื้น/อุณหภูมิ | ❌ ต้องเขียนเอง | ✅ มีในชิป |
| กัน noise ตอนมอเตอร์ทำงาน | ⚠️ ค่าแกว่ง | ✅ มี filter ในชิป |

**สรุป: MPR121 ต่อง่ายกว่าด้วย** เพราะไม่กิน GPIO เพิ่มเลย แค่ต่อ I2C พ่วงจากตัวก่อนหน้า → **ซื้อมาแล้ว ใช้ต่อได้เลย ถูกต้องแล้ว**

### สถาปัตยกรรมที่เสนอ

| ระดับ | ใคร | ทำอะไร |
|-------|-----|--------|
| **ชุดแบต** | 👨‍🏫 ครูบัดกรีล่วงหน้า | รางถ่าน → BMS → สวิตช์ → buck; เพิ่มฟิวส์หลังวันศุกร์ ทำเป็น **โมดูลปิดผนึก** เด็กไม่แตะ |
| **Capacitor** | 👨‍🏫 ครูบัดกรีล่วงหน้า | ติดบนบอร์ดที่เกี่ยวข้องไปเลย |
| **ไฟกำลัง 3 เส้น** | 🧒 เด็กขันน็อต | Screw Terminal ใช้ไขควง ไม่ต้องบัดกรี |
| **สายสัญญาณทั้งหมด** | 🧒 เด็กจิ้ม | Dupont สำเร็จรูป |

### ⭐ ตัวช่วยหลัก: บอร์ดขยาย ESP32 38-pin (Expansion / IO Shield)

แทน Perfboard ด้วย **บอร์ดขยาย ESP32 แบบสำเร็จรูป** (~60–120 ฿) — ESP32 **เสียบลงไปเฉย ๆ ไม่ต้องบัดกรี**

```
         สาย Dupont 3-pin จิ้มตรง
              ↓  ↓  ↓
    ┌─────────────────────────────┐
    │  S V G   S V G   S V G  ...  │ ← ทุก GPIO มี 3 ขา: Signal / VCC / GND
    │  ┌───────────────────────┐  │
    │  │      ESP32 38-pin     │  │ ← เสียบลง ถอดได้
    │  └───────────────────────┘  │
    │  [Screw Terminal ไฟเข้า]     │
    └─────────────────────────────┘
```

**แก้ได้หลายปัญหาพร้อมกัน:**

| ปัญหาเดิม | แก้ยังไง |
|-----------|---------|
| Perfboard ต้องบัดกรี | ไม่ต้องบัดกรีเลย |
| จอ TFT ไม่มี VCC | ทุกหัวเสียบมี V/G มาให้อยู่แล้ว |
| XIAO ไม่มีไฟเลี้ยง | เหมือนกัน |
| เซนเซอร์ต้องแยกหาไฟ | ได้จากหัวเสียบของตัวเอง |
| สายรกไม่รู้เส้นไหนคือเส้นไหน | 1 อุปกรณ์ = 1 หัวเสียบ (เหมือนเสียบเซอร์โว) |

**⚠️ ข้อควรระวัง**
1. บอร์ดขยายส่วนใหญ่มี **jumper เลือก 3.3V / 5V** บนขา V → **ตั้งเป็น 3.3V** ก่อนเสียบเซนเซอร์ ไม่งั้นเผา
2. **ห้ามเอาไฟเซอร์โว 5A ผ่านบอร์ดขยาย** — ลายทองแดงรับไม่ไหว เซอร์โวรับไฟจาก XL4015 → PCA9685 โดยตรง
3. ต้องเลือกรุ่นที่รองรับ **38 pin** (บางรุ่นเป็น 30 pin)

### อุปกรณ์หลายขา (TFT 8 เส้น / TB6612 9 เส้น)

ใช้ **สาย Dupont สำเร็จรูปแบบ housing หลายขา** (6/8 ขา) ซื้อสำเร็จ **ไม่ต้องย้ำเอง** — จิ้มทีเดียวทั้งชุด ไม่หลุดทีละเส้น และกลับด้านยากกว่า

## 5. ผังขา ESP32 38-pin — ผังเก่า เก็บเป็นประวัติ

> **ห้ามใช้ผังในหัวข้อนี้ต่อระบบฉบับวันศุกร์** ผังเป้าหมายล่าสุดอยู่ใน `ตารางการเชื่อมต่อและบัดกรี_RoboMDT.md` และ `สรุปการเชื่อมต่อสำหรับอัปเดตวันศุกร์_RoboMDT.md`

> ⚠️ ผัง ASCII ใน `แผนเสียบสายไฟ_RoboMDT.md` วาดเป็นบอร์ด 30-pin → **ซ้าย/ขวาสลับกับของจริง** ใช้ผังนี้แทน
> 📸 **รอรูปบอร์ดจริงมายืนยันอีกครั้ง** — clone บางยี่ห้ออาจต่างเล็กน้อย

```
                 ┌───────────────────────────────────────┐
           3V3 ──┤ 1                                  38 ├── GND
            EN ──┤ 2                                  37 ├── D23   ← ว่าง → STBY
  ENC_B_R  D36 ──┤ 3 🔒 (เสนอเพิ่ม + 10k)            36 ├── D22   ← I2C_SCL
  ENC_A_R  D39 ──┤ 4 🔒 (+ 10k pull-up)              35 ├── TX0
  IR ขวา   D34 ──┤ 5 🔒                               34 ├── RX0
  CAM_RX   D35 ──┤ 6 🔒                               33 ├── D21   ← I2C_SDA
  MOT_PWMB D32 ──┤ 7                                  32 ├── GND
  MOT_PWMA D33 ──┤ 8                                  31 ├── D19   ← TFT_BL
  ENC_A_L  D25 ──┤ 9                                  30 ├── D18   ← TFT_SCLK
  ENC_B_L  D26 ──┤10                                  29 ├── D5    ← TFT_MOSI
  MOT_IN4  D27 ──┤11                                  28 ├── D17   ← TFT_DC
  MOT_IN3  D14 ──┤12                                  27 ├── D16   ← TFT_RST
  MOT_IN2  D12 ──┤13 ⚠️ strapping                     26 ├── D4    ← TFT_CS
           GND ──┤14                                  25 ├── D0    ⛔ ปุ่ม BOOT
  MOT_IN1  D13 ──┤15                                  24 ├── D2    ← ว่าง
           SD2 ──┤16 ⛔ ต่อ flash ภายใน               23 ├── D15   ← IR ซ้าย
           SD3 ──┤17 ⛔                               22 ├── SD1   ⛔
           CMD ──┤18 ⛔                               21 ├── SD0   ⛔
            5V ──┤19                                  20 ├── CLK   ⛔
                 └──────────────[ USB ]───────────────┘
                    ◄─ ฝั่งซ้าย ─►      ◄─ ฝั่งขวา ─►
                    MOTOR + ENCODER      I2C + TFT
```

### ✅ การจัดกลุ่มของ v3 ยังใช้ได้ แค่สลับด้าน

| | v3 เขียนว่า | ของจริงบน 38-pin |
|---|---|---|
| Motor + Encoder | ฝั่งขวา | **ฝั่งซ้าย** |
| I2C + TFT | ฝั่งซ้าย | **ฝั่งขวา** |

→ **แก้แค่คำว่า "ซ้าย/ขวา" ไม่ต้องเปลี่ยนเลข GPIO เลย**

### ⚠️ สิ่งที่ต้องรู้

| # | เรื่อง |
|:-:|-------|
| 1 | **ฝั่งซ้ายเต็ม 100%** — GPIO ใช้ได้ 12 ขา v3 ใช้ครบทั้ง 12 (Motor 6 + Encoder 4 + IR ขวา + CAM_RX) ไม่เหลือสำรอง |
| 2 | **ฝั่งขวาเหลือ 2 ขา** — D23 และ D2 (D0 เป็นปุ่ม BOOT ห้ามใช้) |
| 3 | **STBY ข้ามฝั่ง** — D23 อยู่ฝั่งขวา TB6612 อยู่ฝั่งซ้าย มี 1 เส้นข้ามฝั่ง ยอมรับได้ |
| 4 | ⛔ **SD0/SD1/SD2/SD3/CMD/CLK (GPIO 6–11) ใช้ไม่ได้** ต่อกับ flash ภายในชิป — 38-pin มีขามากกว่า 30-pin ก็จริง แต่ขาที่เพิ่มมาใช้ไม่ได้ทั้งหมด |
| 5 | ⚠️ **D12 strapping** — ถ้า TB6612 breakout มี pull-up บนบอร์ด ESP32 จะบูตไม่ขึ้น ถ้าเจออาการนี้สลับ MOT_IN2 ไป D23 แล้วเอา STBY ไป D2 |

## 6. การจัดชั้น

### 6.1 ผังปัจจุบัน

```
ชั้น 5   TFT + XIAO + MPR121 + แผ่นทองแดง
ชั้น 4   MG996R×2 (ต้นแขน) + MG90S×2 (หัวไหล่) + SG90×2 (คอ/ก้มเงย)
ชั้น 3   ESP32 + PCA9685
ชั้น 2   BMS + TB6612 + CM620
ชั้น 1   TT Motor×2 + รางถ่าน 18650 + LM2596 + IR×2 + VL53L0X
```

### 6.2 ✅ ที่ถูกแล้ว ไม่ต้องแก้

| จุด | เหตุผล |
|-----|--------|
| **แบต + มอเตอร์ อยู่ชั้น 1** | ของหนักอยู่ล่างสุด จุดศูนย์ถ่วงต่ำ ✅ |
| **LM2596 อยู่ชั้นเดียวกับแบต** | สมเหตุสมผล — ของกลุ่มพลังงานอยู่ด้วยกัน ✅ |
| **ESP32 อยู่ชั้นกลาง (3)** | เป็นศูนย์กลางของทั้งบน (จอ/กล้อง) และล่าง (มอเตอร์) ✅ |
| **SG90 คอที่ชั้น 4 / ก้มเงยที่ฐานหัว** | ความสูงชั้น 5 กำหนดโดยจออยู่แล้ว ไม่ได้ทำให้สูงขึ้น ✅ |
| **XIAO + MPR121 อยู่ชั้น 5** | กล้องต้องอยู่ระดับหน้า / touch pad ต้องอยู่บนหัว ✅ |

### 6.3 ⚠️ จุดเดียวที่ควรปรับ — BMS แยกจากกลุ่มพลังงาน

ตอนนี้ไฟวิ่งขึ้นลงไปกลับ:

```
แบต(ชั้น1) → BMS(ชั้น2) ↑ → สวิตช์ → buck(ชั้น1) ↓ → ESP32/PCA9685(ชั้น3) ↑↑
```

**ไม่ใช่เรื่องผิด** — แค่สายไฟ 3–5A เดินยาวกว่าที่จำเป็น

**ทางแก้ที่ตรงกับที่ออกแบบไว้อยู่แล้ว: ย้าย BMS ลงชั้น 1**

```
ชั้น 1   TT Motor×2 + รางถ่าน + BMS + LM2596 + XH-M401 ชั่วคราว + สวิตช์ + TCRT5000×2
         └── ชั้นพลังงานครบวงจร ไฟออกขึ้นชั้นบนทางเดียว
ชั้น 2   TB6612 + CM620   ← เหลือของน้อย มีที่ว่างเยอะ
```

BMS หนาแค่ 3mm ใส่ชั้น 1 ได้สบาย และ **ตรงกับที่คุณคิดไว้** ว่าของพลังงานควรอยู่กับแบต

> ถ้าไม่อยากขยับอะไรเลยก็ได้ — เรื่องนี้เป็นการ optimize ไม่ใช่ปัญหาที่ทำให้ต่อไม่ได้

### 6.4 ⚠️ VL53L0X — ต้องย้ายขึ้นชั้น 4

หน้าที่คือเช็คของในมือ แต่มืออยู่**ชั้น 4** ส่วนเซนเซอร์อยู่**ชั้น 1** → มองไม่เห็นมือ

→ **ย้ายขึ้นชั้น 4 ติดลำตัวหันไปข้างหน้า ระดับที่แขนยื่นออกมา**

**ผลพลอยได้:** I2C ทุกตัวจะอยู่เหนือ ESP32 หมด (PCA9685+VL53L0X ชั้น 4 / MPR121 ชั้น 5)
→ bus เดินขึ้นทางเดียว **~60cm → ~25cm** และ **ชั้น 1 ไม่มีสาย I2C ลงไปเลย**

**ข้อจำกัดที่ต้องออกแบบเผื่อ:** VL53L0X อ่านระยะต่ำกว่า ~40mm ไม่แม่น → ต้องวางให้ของที่จับอยู่ห่างเซนเซอร์ **≥50mm** ตอนอยู่ในท่า carry (แขนยื่นออกมาอยู่แล้ว น่าจะผ่านสบาย แต่ควรวัดจากโมเดล 3D ก่อน)

### 6.5 ⚠️ รู USB สองรู

CM620 (ชาร์จ) กับ ESP32 (โปรแกรม) เจาะใกล้กัน → เด็กเสียบผิดรู
→ ให้อยู่**คนละด้านของตัวถัง** หรือพิมพ์สัญลักษณ์ลงบนตัวถังเลย

### 📌 หมายเหตุสายพาน (TPU)

| เรื่อง | รายละเอียด |
|-------|-----------|
| **วัสดุ** | สายพาน = **TPU** / ตัวถัง+เฟือง = PETG หรือ PLA |
| **พิมพ์ TPU** | ควรใช้ extruder แบบ direct drive ถ้าเป็น bowden ต้องพิมพ์ช้ามาก (~15–25 mm/s) และ retraction น้อย |
| **TPU ยืดตามเวลา** | ยังต้องมี **idler wheel ปรับตำแหน่งได้** เพื่อตั้งความตึงใหม่ |
| **ข้อดี** | TPU เกาะพื้นเรียบดีกว่าข้อแข็ง และดูดซับแรงกระแทกแทนเฟืองมอเตอร์ |
| **ต้องออกแบบเผื่อ** | ให้สายพานหลุดได้เมื่อเจอแรงเกิน = mechanical fuse กันเฟืองพลาสติกใน TT Motor รูด |

## 8. ลำดับทดสอบก่อนประกอบเข้าตัวถัง

> **อย่าพิมพ์ตัวถัง 3D จนกว่าข้อ 1 จะผ่าน** เพราะถ้าไม่ผ่านต้องเพิ่ม buck ซึ่งกินพื้นที่

> ⛔ **ข้อ 0 ก่อนทุกข้อ: ต้องแฟลชเฟิร์มแวร์ที่ตรง pin map ชุดใหม่ก่อน** โค้ดเดิมใช้ GPIO25/26/27/32/33 เป็นสัญญาณ Servo ซึ่งชุดใหม่คือขาสั่ง TB6612 ถ้าเปิดด้วยโค้ดเก่ามอเตอร์จะวิ่งมั่วทันที ดูชุดค่าที่ต้องแก้ในข้อ 0 ของ `ตารางการเชื่อมต่อและบัดกรี_RoboMDT.md` หัวข้อ 16

| # | ทดสอบ | ผ่านคือ |
|:-:|-------|---------|
| **1** | ต่อ buck → PCA9685 → เซอร์โว 6 ตัว + ESP32 → สั่งขยับ 6 ตัวพร้อมกัน **พร้อมของถ่วงที่แขน** | จอ buck ไม่ตกต่ำกว่า 4.7V **และ ESP32 ไม่รีบูต** (Serial ไม่ขึ้น boot log ใหม่) — วัด `BUS` กับราง Servo พร้อมกันสองจุดจะเห็นว่าตัวไหนตกก่อน |
| **2** | `Wire.begin(21,22)` รัน I2C Scanner | เจอ **0x40 / 0x29 / 0x5A** ครบ |
| **3** | หมุนล้อซ้ายด้วยมือ 1 รอบ | ได้ ~**4,680** (quadrature ×4) |
| **4** | หมุนล้อขวาด้วยมือ 1 รอบ | ได้ ~**1,170** — ถ้าค่าเดินเองทั้งที่ไม่หมุนล้อ คืออาการพัลส์หลอกของ GPIO36/39 ไม่ใช่สายหลวม |
| **5** | ต่อจอ TFT (อย่าลืม VCC + BL, **ไม่ต่อ MISO**) | ภาพขึ้นถูกสี ถ้าจอมืดสนิทแต่ SPI ปกติ ให้ดูขา BL ก่อน |
| **6** | ต่อ XIAO (อย่าลืม 5V) ส่ง L/C/R | ESP32 อ่านตัวอักษรได้ — ฝั่ง XIAO ต้องพิมพ์ลง `Serial1` ไม่ใช่ `Serial` |
| **7** | ต่อมอเตอร์ สั่งเดินหน้า/ถอย/เลี้ยว | 2 ล้อหมุนถูกทิศ และ **ตอนเปิดสวิตช์ล้อต้องนิ่งสนิท** ปกติ pull-down 200kΩ ในชิปจัดการให้แล้ว ถ้ายังกระตุกค่อยเสริม R 10kΩ 4 ตัว |
| **8** | **ทดสอบยกจริง** — MG996R ยกแขน+MG90S+ขวดน้ำ | ยกขึ้นได้ ไม่ตกกลับ ไม่ร้อนผิดปกติ |

### 10.1 คำนวณ torque ใหม่ตามโครงสร้างจริง

**MG996R (ต้นแขน) — ต้องยกอะไรบ้าง**

```
โครงแขน PETG           ~35 g
MG90S ที่หัวไหล่        ~14 g
ของ (ขวดน้ำ 500ml แบ่ง 2 แขน)  ~250 g
                       ───────
รวมต่อแขน               ~300 g

ระยะจากแกน MG996R ถึงจุดศูนย์ถ่วง ~9 cm
torque = 0.3 kg × 9 cm = 2.7 kg·cm
เผื่อ safety factor 2–3× = 5.4–8.1 kg·cm

MG996R = 11 kg·cm   ✅ พอดี เหมาะสมแล้ว
MG90S  = 2.2 kg·cm  ❌ ไม่พอ
```

→ **MG996R ถูกต้องแล้ว ใช้ต่อ** และปัญหาไฟต้องแก้ที่ระบบไฟ (หัวข้อ 3.3) ไม่ใช่เปลี่ยนเซอร์โว

### 10.2 MG90S หนีบขวดน้ำได้ไหม?

แรงหนีบขึ้นกับ **ความฝืดของผิวสัมผัส มากกว่าแรงเซอร์โว**

```
ต้องการ: 2 × μ × N ≥ m × g     (สัมผัส 2 ข้าง)

ขวด 500g, ผิว PETG เปล่า (μ ≈ 0.25):
   N ≥ 0.5 × 9.8 / (2 × 0.25) = 9.8 N ≈ 1.0 kgf
   ถ้าจุดหนีบห่างแกน MG90S 5cm → torque = 5 kg·cm  ❌ MG90S ไม่พอ

ขวด 500g, ติดยาง/ซิลิโคน (μ ≈ 0.8):
   N ≥ 0.5 × 9.8 / (2 × 0.8) = 3.1 N ≈ 0.31 kgf
   ถ้าจุดหนีบห่างแกน MG90S 5cm → torque = 1.55 kg·cm  ✅ MG90S พอ (2.2 kg·cm)
```

**สรุป:**
- **ผิวพลาสติกเปล่า → หนีบขวดน้ำเต็มไม่อยู่** ไม่ว่าจะใช้เซอร์โวอะไร มันจะลื่นไหลลง
- **ติดแผ่นยาง/ซิลิโคนที่ผิวหนีบ → MG90S พอ** ← ตัวแปรสำคัญที่สุด
- ลดน้ำหนักของที่ให้ยก (ขวดน้ำเปล่า ~20g) จะง่ายขึ้นมาก

**⚠️ ปัญหาที่ทั้ง MG90S และ MG996R มีเหมือนกัน:** เซอร์โวที่หนีบค้างไว้ = stall ตลอดเวลา = **กินกระแสสูงสุดตลอดที่ถือของ + ร้อน** ต้องเผื่อไว้ในงบไฟ และไม่ควรถือของค้างนานเกิน ~30 วินาที
