อธิบายการสื่อสารระหว่าง Web Interface และหุ่นยนต์ RoboMDT
=========================================================

1. คำถาม: สื่อสารผ่าน Serial หรือไม่?
------------------------------------
คำตอบ: "ไม่ใช่" ครับ สำหรับการกดสั่งจากหน้าเว็บนี้
การสั่งงานจากหน้าเว็บ Code Block ใช้การส่งข้อมูลผ่าน **Wi-Fi** ด้วยระบบ **HTTP Request** ครับ

(แต่ในโค้ดฝั่งหุ่นยนต์ Robo.ino มีการเขียนเผื่อให้รับคำสั่งผ่าน Serial Monitor ได้ด้วย หากต่อสาย USB กับคอมพิวเตอร์โดยตรง)

2. กระบวนการทำงาน (Flow) จากเว็บไปหาหุ่นยนต์
------------------------------------

[1] ผู้ใช้กดปุ่ม Run หรือกด Block บนหน้าเว็บ
    - Javascript ในไฟล์ `script.js` จะทำการแปล Block ทั้งหมดเป็น "รหัสคำสั่ง"
    - ตัวอย่างรหัส: "w;a;s;" (เดินหน้า; เลี้ยวซ้าย; ถอยหลัง;)

[2] ส่งข้อมูลผ่าน Wi-Fi (HTTP GET)
    - ฟังก์ชัน `sendToRobot(cmd)` ใน Javascript จะใช้คำสั่ง `fetch`
    - ส่งไปยังที่อยู่ IP: `192.168.4.1` (ซึ่งเป็น IP ของหุ่นยนต์ตอนปล่อย Hotspot)
    - รูปแบบ URL ที่ส่งไปคือ: `http://192.168.4.1/run?cmd=w;a;s;`

[3] หุ่นยนต์รับข้อมูล (ESP32 WebServer)
    - ในไฟล์ `Robo.ino` ส่วน `void setup()` มีการสร้าง Server รอรับที่ Path `/run`
    - เมื่อได้รับสัญญาณ หุ่นยนต์จะแกะค่าจากตัวแปร `cmd` (คือ "w;a;s;")

[4] การประมวลผล (Parsing & Execution)
    - ฟังก์ชัน `executeCommandString()` จะทำการตัดคำด้วยเครื่องหมาย `;`
    - ตัวแรก "w" -> เรียกฟังก์ชัน `goForward()` (เดินหน้า)
    - ตัวที่สอง "a" -> เรียกฟังก์ชัน `goLeft()` (เลี้ยวซ้าย)
    - ทำงานจนครบทุกคำสั่ง

สรุป
----
- หน้าเว็บ -> หุ่นยนต์ : ใช้ **Wi-Fi (HTTP)**
- ต่อสาย USB -> หุ่นยนต์ : ใช้ **Serial** (Option เสริมที่เขียนไว้ในโค้ด)

3. ความหมายของ !important ใน CSS
=========================================================
ในระหว่างการแก้ไขไฟล์ style.css เรามีการใช้ `!important` หลายจุด เช่น:
`color: #4C97FF !important;`

ความหมายคือ:
- **!important** เป็นคำสั่งที่บอกให้ Browser "บังคับใช้" สไตล์นี้เป็นอันดับแรกสุด
- ไม่สนใจลำดับความสำคัญ (Specificity) เดิมของ CSS
- ใช้เพื่อแก้ปัญหาเวลาที่เราต้องการเปลี่ยนสีหรือขนาดของ Library (เช่น Blockly) ที่มีการกำหนดค่ามาอย่างแน่นหนา หรือมีการเขียนทับกันหลายชั้น
- ถ้าไม่ใส่ `!important` ค่าที่เราเขียนใหม่อาจจะไม่แสดงผล เพราะโดนค่าเดิมของ Library ทับอยู่ครับ

=========================================================
4. ทำไมต้องใช้เครื่องหมาย ; คั่นคำสั่ง (แทนที่จะใช้เว้นวรรค)
=========================================================
ในโค้ดการส่งคำสั่ง "w;a;s;" เราใช้เครื่องหมายเซมิโคเพื่อให้แยกคำสั่งชัดเจน (Delimiter) เพราะ:

1. **ลดความผิดพลาดจาก Space:** การใช้เว้นวรรค (Space) อาจสับสนได้ง่ายถ้ามีช่องว่างเกินมา (เช่น "w  a") หรือกรณีที่คำสั่งในอนาคตอาจต้องมีวรรค
2. **ง่ายต่อการเขียนโค้ดตัดคำ (Parsing):** ในภาษา C++ (Arduino) การใช้ `indexOf(';')` เพื่อหาตำแหน่งจบคำสั่งนั้นเป็นมาตรฐานแลเขียน logic ได้ง่ายและแน่นอนกว่า

5. ทำไมลากของไปทิ้งในถังขยะไม่ได้ (หรือยากกว่าปกติ)
=========================================================
ปัญหาเกิดจาก: **"ถังขยะนี้เป็นปุ่ม HTML ภายนอก ไม่ใช่ถังขยะของ Blockly โดยตรง"**

1. **คนละระบบกัน:** ตัว Blockly (พื้นที่วางบล็อก) เป็นระบบวาดภาพ SVG ส่วนปุ่มถังขยะที่เราทำใหม่เป็น HTML Button แยกออกมา
2. **Blockly ไม่รู้จักปุ่มนี้:** ปกติ Blockly จะมีระบบแม่เหล็กดูดเข้าถังขยะ (Bump) เฉพาะกับถังขยะของตัวเองเท่านั้น มันจะไม่รู้ว่ามีปุ่มแดงๆ นี้อยู่บนโลก
3. **เราต้องเขียนดักจับเอง (Manual Detection):** ในสคริปต์ `handleTrashDrop()` เราใช้วิธีจับตำแหน่งเมาส์ตอนปล่อย (Mouse Up) ว่าตรงกับปุ่มไหม
   - ซึ่งถ้าปล่อยเมาส์ผิดตำแหน่งนิดเดียว หรือจังหวะ Browser ไม่ส่งค่าตำแหน่งมา ก็จะลบไม่ได้
   - ไม่มี Effect "ฝาถังเปิด" หรือ "แสงเรือง" เพื่อบอกว่า "ปล่อยตรงนี้ลบนะ" เหมือนของแท้ ทำให้กะระยะยากครับ

6. สิ่งที่หน้าเว็บนี้ยังขาด (Missing Features)
=========================================================
นอกเหนือจากระบบ Login แล้ว ฟีเจอร์ที่ควรมีเพื่อให้เว็บมีความสมบูรณ์แบบสำหรับงาน Education / Controller:

1. **ระบบบันทึกและโหลด (Save & Load Blocks):**
   - ตอนนี้ถ้ากด Refresh หน้าเว็บ สิ่งที่ต่อไว้จะหายหมด
   - ควรมีปุ่ม "Save Project" เพื่อดาวน์โหลดเป็นไฟล์ .xml หรือ .json เก็บไว้ในคอม และปุ่ม "Load" เพื่อนำกลับมาแก้ไข

2. **สถานะการเชื่อมต่อ (Connection Status):**
   - ตอนนี้เรากด Run ไปโดยไม่รู้ว่าหุ่นยนต์เปิดอยู่หรือเชื่อมต่ออยู่ไหม
   - ควรมีไฟสถานะ (Online/Offline) ที่มุมจอ โดยให้หน้าเว็บยิง Ping ไปหาหุ่นยนต์ทุกๆ 2-3 วินาที

3. **คอนโซลรับค่ากลับ (Sensor Monitor / Console):**
   - ตอนนี้เรา "ส่งคำสั่งไป" อย่างเดียว (One-way)
   - หากหุ่นยนต์เดินไปเจอสิ่งกีดขวาง หรืออ่านค่าเซนเซอร์ได้ ควรส่งค่ากลับมาแสดงบนหน้าเว็บได้ด้วย (เช่น "Distance: 15cm")

4. **การดูโค้ดจริง (Code Preview):**
   - เพื่อการเรียนรู้ ควรมีปุ่ม "Show Code" เพื่อดูว่าบล็อกที่เราต่อ พอร์ตออกมาเป็นภาษา C++ หรือ Python หน้าตาเป็นอย่างไร

   - การจัดการพื้นที่ถ้าบล็อกยาวจนล้นจอ หรือใช้บนมือถือ/แท็บเล็ต อาจต้องมีการปรับ Layout ให้ซ่อน Toolbox ได้ หรือย่อขยายพื้นที่ทำงานได้ดีกว่านี้

7. ปัญหาและวิธีแก้ของบล็อก Repeat / If
=========================================================
**ปัญหา:** ตอนแรกบอร์ดไม่ทำงานเมื่อใส่ Loop หรือ Condition
**สาเหตุ:** ตัว Generator เดิมแปลงโค้ดเป็นภาษา JavaScript (เช่น `for (i=0; i<3; i++) { ... }`) ซึ่งเมื่อส่งข้อความนี้ไป "ทั้งดุ้น" ให้หุ่นยนต์ หุ่นยนต์อ่านไม่รู้เรื่อง (เพราะหุ่นยนต์รอแค่ `w;a;s;`)

**วิธีแก้ (Logic Unrolling):**
ผมได้แก้โค้ดให้ "คำนวณล่วงหน้า" บนหน้าเว็บเลยครับ
1. **Repeat (วนลูป):** แทนที่จะส่งคำสั่ง Loop -> คัดลอกคำสั่งข้างในต่อกันตามจำนวนรอบ
   - *ตัวอย่าง:* Repeat 3 Times [เดินหน้า] => "w;w;w;"
2. **If (เงื่อนไข):** เช็คเงื่อนไข (เช่น 1 = 1) บนหน้าเว็บทันที
   - *ตัวอย่าง:* ถ้า 1=1 [เลี้ยวซ้าย] => โปรแกรมเห็นว่าเป็นจริง => ส่ง "a;"
   - *ตัวอย่าง:* ถ้า 1=2 [เลี้ยวซ้าย] => โปรแกรมเห็นว่าเป็นเท็จ => ไม่ส่งอะไรเลย ("")

**ข้อจำกัด:** วิธีนี้ใช้ได้กับเงื่อนไขที่เรารู้ค่าอยู่แล้ว (เช่น ตัวเลข) แต่ยังใช้ไม่ได้กับค่าเซนเซอร์แบบ Real-time (เช่น "เดินจนกว่าจะเจอผนัง") เพราะเว็บส่งคำสั่งไปทีเดียวจบครับ

8. ทำไมตัวหนังสือตอนเลือก (Selected) ถึงเป็นสีขาวอ่านยาก?
=========================================================
**อาการ:** เมื่อคลิกเลือกหมวดหมู่ (เช่น Motion) ชื่อหมวดกลายเป็นสีขาว กลืนไปกับพื้นหลัง
**สาเหตุ:** เป็น CSS เริ่มต้นของ Blockly Library ครับ
- ปกติ Blockly จะทำแถบสีน้ำเงินเข้ม (Background Blue) เวลาเลือกหัวข้อ
- ดังนั้นมันจึงตั้งค่าตัวอักษรให้เป็น **สีขาว (White)** อัตโนมัติเพื่อให้ตัดกับพื้นน้ำเงิน
- แต่พอเราทำธีมใหม่เป็น "Minimal" สีพื้นหลังเราขาว หรือเทาอ่อน ทำให้สีขาวของตัวอักษรจมหายไปครับ

**วิธีแก้:** เราต้องเขียน CSS ทับ (Override) โดยบังคับให้:
1. พื้นหลังตอนเลือก (Selected Background) เป็นสีจางๆ หรือโปร่งใส
2. ตัวอักษร (Label) กลับมาเป็นสีเข้ม (หรือสีตามหมวดหมู่) และใส่ `!important` เพื่อเอาชนะค่าเดิมของ Library ครับ

9. ทำไมแก้ CSS แล้วยังเป็นสีขาวอยู่? (Persistent White Text)
=========================================================
ถ้าแก้โค้ดข้อ 8 แล้วยังหายไม่หมด เป็นไปได้ว่า:
1. **Specific Selector:** Blockly มีการใช้ Selector ที่ระบุเจาะจงกว่า (เช่น ระบุ ID หรือระบุลำดับชั้นลึกๆ)
2. **Inline Style:** ตัว JavaScript ของ Blockly อาจจะกำลัง "ยัดเยียด" ค่าสี `style="color: #fff"` ใส่เข้าไปใน HTML โดยตรงตอนที่เราคลิก ซึ่งจะชนะ CSS Class ปกติ

**วิธีแก้ทางเลือก (Alternative Solutions):**
1. **The "Nuclear" Option (ใช้ค้อนทุบ):** ใช้เครื่องหมายดอกจัน `*` เพื่อสั่งให้ "ทุกสิ่งที่อยู่ในกล่องที่ถูกเลือก ต้องเป็นสีดำ"
   - Code: `.blocklyTreeSelected * { color: #333 !important; }`
2. **แก้ที่ Theme Setting (JS):** ในไฟล์ `script.js` ตรงการตั้งค่าธีม อาจจะต้องลองหา Property ที่ชื่อว่า `treeSelectedColour` หรือใกล้เคียงเพื่อเปลี่ยนค่า Default จากต้นทางครับ
